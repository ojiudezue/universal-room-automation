## What still stands, and why

- **One DB writer** (one queue, one connection, WAL reads). It ended "database is locked". Every new write channel gets a write-volume review, because the Optimization Coordinator took the house down with O(N)-per-cycle writes. → [001](entries/001_db_single_writer_architecture.json), [021](entries/021_optimization_coordinator_v5_shipped_writeflood_incident_remediation.json)
- **Battery control is cloud-first, permanently; telemetry is local-first.** Enphase fw 8.3.x accepts local writes and ignores them; control ran dead ≥7 days unnoticed. Every write is verified against the cloud. → [028](entries/028_marathon_ev_deadband_cloud_first_writes_wave_dashboards.json)
- **Energy trust:** SmartHub > Emporia/SPAN > Envoy for totals; SOC is Envoy, never SPAN; Emporia is the solar-follow grid primary by operator ruling. → [003](entries/003_energy_measurement_trust_hierarchy.json), [147](entries/147_envoy_stream_trust_and_emporia_primary.json)
- **A missing number beats a wrong one.** The Envoy lifetime production counter flaps (32 drops since 09-20), which made daily solar 0.0 on 5 of 40 days and NULL on 31, understating the consumption the forecast trains on. v5.103.82 uses the monotonic production CT counter, and rejected days now write NULL and train nothing instead of falling back to a net-import-only figure. → [231](entries/231_solar_counter_flap_corrupts_daily_energy.json), [232](entries/232_v5_103_82_daily_solar_uses_the_production_ct_cou.json)
- **Bills come from meter counters, not integrated power** (power integration lost every Envoy dropout, 24–34% low). Measure a source's cadence before switching it live. → [191](entries/191_ec_billing_meter_counters_option_b.json)
- **The battery reserve has one governor.** About 25 decision branches each applied their own floors, so reviews kept finding leaks. The reserve is governed at the `_result` chokepoint first, and the inclement fixes are rebuilt on top. Storm doctrine: alert → is it local to our point → local forecast over the alert window → energy decision; an offline Envoy blocks commands, never decisions. → [213](entries/213_reserve_governor_first_inclement_doctrine.json)
- **Untrusted SOC refuses every path except off-peak ensure-on and should-start-by.** SOC was untrusted ~21% of 14 days, mostly overnight; refusing everything would starve EV charging, while a cloud-SOC start costs only a few minutes of battery draw. → [183](entries/183_ec_p1_tier3_reviews_and_untrusted_soc_option1.json)
- **HVAC:** read `HVAC_ARCHITECTURE_STATE_OF_PLAY.md` first, because ~15 wrong claims came from stale memos. The Zone 1 strands were real Carrier manual holds created after URA's own return. S1's old "don't fight manual" rule was replaced by four gates, because it was secretly the only thing protecting live borrows. URA's energy actions win over person protection ("URA has more information"), and the protection that does apply survives restarts. → [145](entries/145_hvac_arc_four_workstreams_state_of_play_read_first.json), [148](entries/148_zone1_strands_real_manual_holds_not_status_lag.json), [152](entries/152_s1_manual_guard_superseded_four_gates.json), [154](entries/154_borrow_starts_win_person_protection_persists.json)
- **URA is going to more homes.** Carrier quirks stay out of shared paths; thermostat brands are code profiles, auto-detected per zone, with a Generic safety net. → [166](entries/166_multi_home_rollout_generalize_thermostat.json), [169](entries/169_thermostat_profiles_in_code_autodetected_generic_net.json)
- **Census: fix the inputs first.** The hybrid estimator was approved, then held, because the door ledger logs a group of 8 as one cancelled round-trip; an estimator built on it would ship noise. → [184](entries/184_census_hybrid_inputs_first.json)
- **Process.** Regression-prone work gets three framing-disjoint reviews, and Tier 3 adds an adversarial-completeness pass. Measure before building, verify before working, and fix the implementation rather than overturn an operator decision. → [029](entries/029_measure_before_build_failover_rescope.json), [146](entries/146_hvac_live_room_gate_restores_operator_rule_opus55.json)

## 2026-10-20/21: the arc in flight

**Housekeeping that compounds.** v5.103.78 stopped diagnostic sensors rewriting unchanged values every tick (countdowns, "minutes ago"): URA's recorder rows dropped from ~20.1k to ~8.8k per hour, and recorder excludes on HA cut ~18k more. v5.103.79 predicts the bill from SmartHub's cost to date plus same-weekday pricing for the rest of the cycle (15% error at day 7/14 vs 32–43% for a straight line) and tracks its own accuracy → [228](entries/228_v5_103_79_bill_prediction_uses_smarthub_cost_and.json). v5.103.81 saves energy state at shutdown and stops EC timers first, because HA never unloads integrations on stop, so saves were skipped and timers could actuate after the DB writer closed → [229](entries/229_v5_103_81_energy_state_is_saved_at_shutdown_and_.json).

**Predictions must earn trust (critical).** An audit found no URA prediction that was both useful and correct. Next-room did no better than guessing the usual room, the room forecasts had AUC 0.605, the "94%" accuracy was the empty-room base rate, and the energy forecasts lost to yesterday-persistence. Root cause: the Bayesian model counts arrivals rather than dwell, ignores the current room, and is never scored against a trivial baseline. Rule: **nothing may consume a prediction for actuation until its producer beats a trivial baseline.** The operator chose to rebuild the anomaly sensor rather than retire it, sensor-only. v5.103.83 runs it on a per-room, hour-of-week dwell model from `environmental_data`. It was built first and replayed after ("we forget these cards"): median 0 fires/day, 47/47 rooms learned. → [230](entries/230_predictions_not_trustworthy_dwell_model.json), [233](entries/233_v5_103_83_occupancy_anomaly_sensor_on_a_room_dwe.json)

**Halo wall panels.** Panel presentation is a separate opt-in integration (`halo`, repo halo-panels) with a typed `halo.indicate`/`release` service API. It replaced a fire-and-forget bus event, which the operator found fragile. S1a is live on all 7 panels with a lease arbiter, sleep floor, snapshot/restore and kill switch. Bridge 1.7.0 now publishes colour mode, colour and effect after each command and on reconnect, because HA had been dropping the colour. Next: URA's Notification Manager delivers to Halo as a channel.

**OC goes agent-first (critical).** Static detectors produced ~90% noise (72 real problems in 5,305 findings over 14 days). In one session, a manual context → reason → fix → verify loop found real faults: the solar counter flap, missing exit rows, and a Foyer BLE pull. So the OC becomes a URA-specialized nightly agent with tiered tools that acts alone only within risk tiers. R0 observes. R1 makes silent, reversible fixes (reloads, rechecks), verified and auto-demoted. R2 makes occupant-visible fixes, only for promoted fix types and never while the house sleeps. R3 never acts alone (restarts, battery/EV, locks, deletes, money). The only static trust machinery is an action log. R2 uses each coordinator's existing paths, because a unified request API would cost ~6 Tier-3 cycles against ~2. → [234](entries/234_oc_agent_first_risk_tiered.json)
