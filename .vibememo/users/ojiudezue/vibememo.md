## What still stands, and why

- **One DB writer.** Every write goes through one asyncio queue and one connection; reads use transient WAL connections. It ended the "database is locked" era. A write-VOLUME review per channel is standing, because the Optimization Coordinator took the house down with O(N)-per-cycle writes the bug-class checklist never asked about. → [001](entries/001_db_single_writer_architecture.json), [021](entries/021_optimization_coordinator_v5_shipped_writeflood_incident_remediation.json)
- **Battery control is cloud-first, permanently; telemetry is local-first.** Enphase firmware 8.3.x accepts local battery writes and silently ignores them, so control ran dead for at least 7 days before we caught it. Every battery write is verified against the cloud oracle. No failover may ever demote control writes back to local. → [028](entries/028_marathon_ev_deadband_cloud_first_writes_wave_dashboards.json)
- **Energy trust:** SmartHub > Emporia/SPAN > Envoy for cumulative totals; battery SOC is Envoy, never SPAN. **Emporia is the permanent solar-follow grid primary** (operator: "I trust emporia more period") and the local Envoy MQTT stream is fallback only. The ~0.5 kW gap is mostly Emporia's 1-min average lagging, but the operator ruled on trust, not speed. → [003](entries/003_energy_measurement_trust_hierarchy.json), [147](entries/147_envoy_stream_trust_and_emporia_primary.json)
- **Framing-disjoint review for anything regression-prone** (Tier 2-DB = 3 framings; Tier 3 adds an adversarial-completeness pass and an operator checkpoint). Mutation drills are executed, not claimed. Wire-in anchors are mandatory because a tested helper does not prove a tested call site. Tonight a fix-up round was sent back twice: once for missing call-site tests, once because its test helper swallowed exceptions and hid a crash that fires whenever Zone Intelligence is off. → [018](entries/018_v4728_v4729_ships_tier2db_policy_day_boundary_bug_class.json), [146](entries/146_hvac_live_room_gate_restores_operator_rule_opus55.json)
- **Measure before you build; verify before you work.** One read-only probe over existing history comes before any empirically-scoped design. Every card, memo and README is a claim to verify against code or live data before acting. The Sept 25 night is the proof: roughly 15 wrong HVAC claims came from stale memos, READMEs and single-file greps. → [029](entries/029_measure_before_build_failover_rescope.json), [145](entries/145_hvac_arc_four_workstreams_state_of_play_read_first.json)
- **Model tiering:** planner, builder and reviewer run on opus-5.5. Opus-5 "often built the wrong thing and would not follow instructions" — its live-room plan let a reloading room satisfy zone establishment, the exact hazard the rule existed to prevent. Any opus-5 output is hand-checked. → [146](entries/146_hvac_live_room_gate_restores_operator_rule_opus55.json)
- **Never overturn an operator decision by adjudication.** Fix the implementation. In round 5 I reverted the operator's "count only running rooms" rule instead of fixing round 4's any() bug; the live-room cycle undoes that. → [146](entries/146_hvac_live_room_gate_restores_operator_rule_opus55.json)

## The HVAC arc as it stands (2026-09-26)

**Read first:** `docs/Coordinator/HVAC_ARCHITECTURE_STATE_OF_PLAY.md`, mandatory for every agent (CLAUDE.md 5b). Its §10 ledger lists the claims that were wrong; do not re-assert them.

**What was true all along.** HVAC got its own room/zone occupancy in v5.103.7: hallways are excluded, per-room tail-holds apply, and night protection is reset-only, so an established empty zone retreats even when someone is home elsewhere. That fixed Zone 3's 56–62 flips/day (now 9–33). But HVAC only *samples* occupancy on a 5-minute tick. The occupancy fast path was designed and never built, so a person entering a hot room still waits.

**The Zone 1 story, corrected twice [144](entries/144_hvac_zone1_strands_are_status_lag_selflockout_not_bryant.json).** It was not the Bryant schedule: removing it cut manual time from 44% to 26% but the strands continued. URA was wrongly cleared because `ura_activity_log` never records temperature writes; the evidence sat in `ac_ramp_events`. The nudge/borrow works and returns in 2–5 minutes. The damage — about 25 hours over 5 days, holds of 1.5 to 11 hours — is URA trusting a status-lagged `manual` from ha_carrier after a successful return. `preset_mode` comes from the slow status poll; `hold_activity` comes from the prompt config feed. URA books the lag as a human override, the arrester sees zero delta, S1 locks itself out, and `infinite_holds` keeps the hold. Nudges stay on.

**Consolidated plan [145](entries/145_hvac_arc_four_workstreams_state_of_play_read_first.json)** (operator: "consolidate or we will never get done"; problems before cards):
- **W1 — thermostat definition, one per BRAND, not per zone.** How to hold a preset, borrow and return, and *read* the true hold state, discovered and written down in detail behind a small generic interface. Carrier is first, with a plain default for other thermostats and Nest when there is one to test. Stage A (behaviour-neutral) routes all three write verbs through funnels with a durable row per write. Stage B (Tier 3) makes returns presets-only for every borrow kind and counts `manual` as a person only when the config feed agrees. The borrow's return is bookkeeping only (each call site writes its own), which is exactly why one definition beats N patches. The upstream `set_activity_setpoint` (ha_carrier #427, no hold) is available to W1 — but it edits the named profile, so W1 must own restoring it.
- **W2 — occupancy truth.** First the live-room gate (v5.103.15, in review: failed rooms act as if not defined in URA; loading rooms block; the hold covers only the occupancy un-retreat). Then the fast path, scoped to shaving the 5-minute tick only. Then a night still-sleeper hold (Jaya was lost by radar twice after her fan stopped, with her phone stationary in the suite). Room override switches stay as they are, documented.
- **W3 — energy-aware HVAC. W4 — closure** (dispose shipped cards, README write-backs, keep the doc current).
