## Cleared, with evidence

- **`_demote`** (4460): `Severity` is an IntEnum and LOW=1 is the minimum (base.py:47). `max(LOW, min(s, LOW))` = LOW for every input. It can never raise severity. Floor holds.
- **D3 normalisation:** `zone_slug` lowercases and collapses non-alnum runs to `_`, applied to both sides. `entered_zones` (not `current_zones`) is used, so non-list input gives `entered_zones_missing`, which fails open. The age is `abs`, so ±20 s. MAX_AGE 0 means `disabled`.
- **D1 zone map:** live ids are `<camera>_property_person_occupancy` (verified in the live registry: 7 ids). Rung (a) longest-prefix is deterministic: two different same-length stems cannot both prefix one string, and a cross-camera tie gives no match and a WARN. `frigate_name` is the matched camera stem. The overlay is keyed on the zone stem and consulted before the alias table.
- **D1 exclusion, 5 sites:** base union (589), resolver legs (597), `_2` safety net (608), legacy fallback (650), `_rescan_siblings` (2809). The F7 linker "missing" check (2205) and the two `_2`-missing WARNs (`not _zoned`) are also covered. The predicate is NVR family OR the `_person_occupancy[_2]` suffix, so it catches a leg whose tag is `legacy`.
- **NVR-family tagging of zone legs** (627-641): the tag is inherited from a dropped `frigate2` leg, so live bare zones become `frigate2`. Without a dropped leg it falls back to the `_2` rule. `nvr_family` folds both into `frigate`, so the burst sibling check (2584) cannot pair a zone leg with a leftover camera leg.
- **`_person_occupancy_2` fix:** now `frigate2` / `protect2`. Before, D5/D10.5 liveness could never see Frigate on live cameras. There is no live `_person_detected_2` (registry checked), so the D1.8 family fold is byte-identical for today's legs.
- **D5 eligibility:** the exemption is checked first. Then `both` families live, then samples ≥ max(1, MIN_SAMPLES) and rate ≥ 0.6 (None means not eligible), then prior = 0 dispatched alerts in 1800 s, counted by D5 itself (`_record_burst_alert` appends only after dispatch, at 2641), then lookback. A sample is opened only when both families are live and the leg's family is frigate or protect. The forward scan is `0 ≤ dt ≤ 60`. A corrupt store gives an empty tracker, so nothing is eligible. Unknown engine: `family=""` makes `_other_family_fire_since` True, so the result is corroborated and nothing is demoted (fail-open).
- **Hold / in-flight:** the key is added before the await. Every `_async_hold` exit releases it on False or exception. The caller releases it on `not _proceed` and on BaseException out of finish. The only early `return` in `_async_finish_perimeter_dispatch` (1703) is patched with `if held`.
- **D6 parse:** strict first non-empty line. `PERSON: NO.`, `**Person:** no` and `PERSON: No person` give NO. `PERSON: NOT SURE` and any other word give UNSURE. If there is no PERSON line, the result is UNSURE and the text is untouched. Any exception gives (None, UNSURE). Enforce needs NO, a tier in `("frigate_event",)` and no exemption. D8 measured 0 `frigate_event` files, so enforce is inert today (card owed, per the README).
- **D10.5 table** matches plan §D10.5: known → LOW, waived → unchanged, corroborated → unchanged, uncorroborated → LOW. Doctrine floor `max(0.9, knob)`. Frigate legs (conf None) are unknown unless the non-face path matches. A latched name is rejected by `lc < edge-15 s`, and a leg with no timestamp is skipped (H4). Naive/aware mismatches are caught per item. The PersonCoordinator key normalisation matches the census slug (person_coordinator.py:979).
- **D10.1 egress:** egress sensors map to their camera through `_append_sensor` (shared `_sensor_to_camera`), so a dual-role stamp is keyed to the dual camera and excluded. Perimeter-only cameras still read the global stamp.
- **D7, all six `_send_whatsapp` callers:** :2050 per-person immediate (counted only if True; `fired_for_person` feeds the audit row). :3174 critical fan-out, :4547 menu reply and :5870 channel test ignore the return, which is correct because none of them records delivery. :5516 multi-channel digest and :5544 first-wins chain now fall through on failure. Dry-run returns True before the bridge check, matching the pre-cycle `channels_fired` and `delivered=1` rows. The bridge check returns False only when entries exist and none is LOADED, or when every status is known-bad. Unknown statuses send as before.
- **INV-FP-DEMOTE-ONLY at defaults (no config change):** with zones empty, D3 returns early with no record. D5 is shadow only (no hold). D6 is off, which is exactly the pre-cycle `enrich_dispatched_alert` call. With no dual-role cameras, D10.1, D10.3 and D10.5 are inert and no egress-identity listener is registered. The zone overlay is empty. Remaining default deltas: the D4 flip (carve-out), D7 (carve-out), and display-only diag keys (A-L4). The README's deploy-time config (zones + dual-role cameras) is an intentional behaviour change that the operator applies.
