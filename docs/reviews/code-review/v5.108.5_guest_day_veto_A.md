## Findings

**MEDIUM-1 (Bug class: interaction between policies, undocumented ripple), `presence.py:6325-6332` with grace `:6296-6303`.** The veto pushes `ended_on` later, which moves the 7-day re-entry grace window later. Grace bypasses `GUEST_STAY_ENTRY_NIGHTS`, so a veto-extended stay lets a single night re-enter where it could not before. This is the 09-16 change in `test_replay_fixture_day_list_entry_nights_2` (`test_guest_stay_producer.py:263-268`): with the veto, the 08-26 stay is held to 09-12, its end night falls within 7 days of night 09-15, and 09-16 comes back by grace although K = 2. The "no phantom chain" bound in the State of Play (§2 step 3: "never extends past 7 days from the last normally-entered stay's end") still holds, but that end is now pushed by any number of vetoed days. The effective reach is (daytime hold length) + 7 days. The test pins the behaviour, but the README and State of Play do not name it. Fix: one sentence in the README Residual section and in State of Play §2 step 3. No code change needed if the operator accepts it.

**LOW-1 (doc accuracy), README "Residual" and State of Play §2.** These call the D4 28-day page "the backstop". `_check_guest_stay_long` (`presence.py:6476-6510`) only pages and releases nothing. What actually bounds a veto-only hold (no qualifying night) is the replay window: the walk starts False `GUEST_STAY_REPLAY_NIGHTS` (35) nights back (`:6169-6170`, `:6241`), so the stay drops once its entry night falls out of the span, about 33 nights after entry. A daytime phantom (GB1/GB2: MS600 radar-derived motion only, no fan-immune witness; GB2 has no BLE, so a resident's daytime use is not subtracted either) only needs 0.10 x 12 h = 72 min of a guest-room day to hold GUEST. It can do so for up to about 5 weeks, with a page at 28 days. Fix: state both bounds in the README.

**LOW-2 (deliberate asymmetry, document it), `presence.py:6281-6284`.** Entry needs the same room for night and day (`:6225-6234`), but the veto takes any guest room. So daytime use of a guest room that is not the stay's room (e.g. GB1 as a daytime room) holds a GB2 stay. The README says "any guest room", so this is intentional; the replay shows 0 clean-period days (clean max day 0.051). No fix needed beyond keeping it named.
