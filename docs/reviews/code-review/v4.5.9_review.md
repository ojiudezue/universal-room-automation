### Per-deliverable critique

**D1 dispatch tilt-awareness** — Three-tier resolution is the right shape. Auto-detect requires BOTH `supported_features` tilt bits AND `current_tilt_position` attribute exposure, avoiding integrations that advertise tilt but don't actually report it. No issues.

**D2 closed-set lifecycle** — Set populated in close phase, drained in open phase, rebuilt on `discover_covers`. Manual-override drops covers from set during close window (design decision: HVAC's "I closed this, I'll reopen it" claim becomes invalid the moment user touches the cover). Cover-removed-from-discovery handled defensively (`if cover is None: discard`). No issues.

**D3 intent predicate** — `is_cover_currently_intended_open` lives on `RoomAutomation`. Five mode mappings explicit. `none` and `on_entry` return False (HVAC stays out). The three time-bearing modes return `in_open_window AND not past_close`. Defensive try/except wraps the time checks (sunrise calc can fail if location unconfigured per `_is_after_sunrise`'s known v3.20.0 fix). Unknown mode defaults to False. Tight.

**D4 opt-out** — `CONF_COVER_HVAC_MANAGED` defaults True (preserves prior behavior). Form field added to both setup and reconfig cover_behavior steps. Reading happens at `discover_covers` time; user changing the toggle takes effect on next reload (acceptable per the same model as every other room CONF). The 11th field on the cover step is a soft-limit bump from 10; documented.

**D5 occupancy-aware skip** — `OCCUPIED_CLOSE_TEMP_DELTA = 2.0°F` is the same threshold the v3.8.4 fan controller uses for "fan activation delta." Symmetric with the existing comfort tolerance. The gate is "occupied AND not meaningfully warmer → skip" — vacant rooms always allow close, missing data defers to other gates rather than blocking.

**D6 diagnostic surfacing** — `hvac_closed_set` is a sorted list of entity IDs (deterministic); `hvac_closed_count` is the integer count. `covers_closed` retained as a bool form for back-compat with any dashboard tile reading the v3.8.4-era key. Three new attrs total: `managed_tilt_covers`, `managed_shade_covers`, `hvac_closed_set/count`.

## Review 2 (Core B) — Race conditions, restart resilience, lifecycle

### Restart in middle of solar window

- `_hvac_closed` is in-memory; HA restart inside the close window resets the set to empty.
- On next coordinator tick, the controller re-evaluates `should_close` (still True if outdoor still ≥ 85°F and hour in window). Per-cover `_should_hvac_close` re-runs all gates; intent predicate, occupancy, manual-override all re-checked. Re-issues close on each cover that passes gates.
- For tilt covers already at tilt=0: `_is_cover_already_in_target_state` returns True → skip, no service call. For shade covers already closed: same skip.
- Worst case: a cover that's in manual-override (`manual_override_until` in entry data persisted? No — also in-memory on `ManagedCover`). On restart, manual override stamps are lost. Re-issued close on a cover the user manually opened during HVAC's first close window. **Edge case worth noting in the README.** Mitigation: covers that the user manually re-opened pre-restart will be re-closed by HVAC post-restart. User can manually re-open again; HVAC's 120s `last_command_time` window catches that as a manual override and stamps a fresh 2hr backoff.
- **Live signal**: if user observes "HVAC closed my cover after I opened it post-restart," that's the documented edge case. Acceptable for single-user; could be fixed by persisting manual override stamps in a future hardening cycle.

### Restart after solar window end (covers stale-closed)

- Open phase only fires if `_hvac_closed` has entries. After restart it's empty → open phase no-op.
- Covers that HVAC closed pre-restart stay closed until next per-room `check_timed_cover_close`/`check_timed_cover_open` cycle.
- For tilt covers: slats stay closed (tilt=0). Per-room timed_open at sunrise will reopen via tilt-aware dispatch (v4.5.6 fix).
- For shade covers: blind stays at position=0. Same per-room timed_open path.
- **Acceptable**: the per-room schedule is the source of truth post-window. HVAC just supplements during peak afternoon.

### Race conditions

- **Per-room close at 13:00 + HVAC close at 13:00 same tick**: both fire `cover.close_cover` (or `_tilt`). Idempotent. ✓
- **HVAC tries to close while per-room timed-open is mid-flight**: per-room runner has `_cover_op_in_flight` flag; HVAC has its own `last_command_time` window (120s). Each issues its own service call independently. The integration's underlying cover handles serialization. Possible "open then close in 30s" sequence is annoying but converges. Edge case; not a code bug. The user's `_should_hvac_close` intent gate already filters out rooms where the timed-open just happened (intent says open, room is in open window, so HVAC respects that).
- **`_get_room_coordinator` returns None mid-cycle (entry reload)**: `_should_hvac_close` checks `if room_coord is None` (implicit — `automation = getattr(room_coord, "automation", None)` handles it via the next `if automation is not None` check). Falls through to "intent gate doesn't apply for CM-level covers," meaning HVAC may close a room cover whose owning room is mid-reload. Race window is ~1 second per reload; low impact.

### Cross-coordinator interaction

- **Energy coordinator changes `constraint.mode` to "shed" during HVAC's solar window**: `update()` doesn't read `constraint.mode` — only `outdoor_temp` (and falls back to `forecast_high_temp` if needed). Mode doesn't affect HVAC cover logic. ✓
- **Zone preset changes to "away" mid-window**: zone preset is independent of CoverController — the `_hvac_closed` set keeps tracking. Open phase will still reopen at 18:00.
- **`_zone_manager.zones` mutated mid-cycle (rare; zone reconfigure)**: the `_should_close_for_occupied_room` loop iterates `self._zone_manager.zones.values()` once per cover. If mutation lands mid-iteration, Python may raise `RuntimeError: dictionary changed size during iteration`. Low probability (zones are reconfigured rarely; HVAC cover update runs every 5 min). Defensive snapshot via `list(...)` would harden, but adds noise. Marking as acceptable.

### Lifecycle

- **Cover entity removed from HA mid-day**: `_command_close_one` raises Exception inside try/except → logged, no crash. `_hvac_closed` keeps the stale entity_id; open phase drops it (`if cover is None: discard`).
- **Room entry deleted mid-day**: discovery hasn't re-run → `self._covers` still has the entry. Operations may fail when `_get_room_coordinator` returns None for the now-deleted room. Same gracious-degradation as above. Discovery re-runs on integration reload, dropping the entry.
- **Manual override during close window then user is gone**: `manual_override_until` is `last + 2hr`. If the open phase fires after the override expires, cover gets reopened normally. ✓

## Live validation plan (Review 3, post-deploy)

After HACS download + HA restart:

1. **Immediate (first 5 minutes after restart):**
   - Watch HA log: no new SyntaxError / ImportError / NameError on URA modules.
   - Confirm HVAC coord still loads — check `sensor.ura_hvac_coordinator_*` mode sensor populates.
   - Confirm `sensor.ura_hvac_coordinator_*` `extra_state_attributes` includes `hvac_closed_set` (sorted list, likely empty post-restart) and `managed_tilt_covers`/`managed_shade_covers` counts.

2. **Next solar window (~13:00 CDT next clear day, outdoor ≥ 85°F):**
   - HVAC log shows: `HVAC Covers: closed N cover(s) for solar gain (now tracking N total HVAC-closed)` where N is non-zero on a hot day.
   - For each tilt cover affected: HA logbook shows `cover.close_cover_tilt` was called (NOT `cover.close_cover`). Tilt position drops to ≤5; blind position stays at the room's intended position (not forced to 0).
   - For each shade cover affected: HA logbook shows `cover.close_cover`. Position drops to 0.
   - Covers in rooms with `cover_open_mode = none` or `cover_hvac_managed = False`: NOT touched. Confirm via logbook + state history.
   - Occupied room with temp at-setpoint: skipped if `cover_open_mode` would otherwise allow.

3. **Solar window end (~18:00 CDT):**
   - HVAC log: `HVAC Covers: reopened N cover(s) post-solar window` where N matches the count closed at 13:00.
   - For each tilt cover: `cover.open_cover_tilt` called; tilt position rises to ≥95.
   - Covers HVAC didn't close stay untouched.
   - `hvac_closed_set` clears to empty.

4. **Manual-override smoke test (optional, can do mid-day):**
   - Manually open a cover that HVAC closed (lift the blind via app).
   - Wait for next coordinator tick (~5 min).
   - HVAC should NOT re-close it; manual_override_until stamp prevents.
   - At 18:00 end-of-window: HVAC drops the cover from `_hvac_closed` (logged as "user manually overrode during closed window") and does NOT reopen it. The user's manual position is preserved.

If any step deviates, capture HA debug logs around the deviation and surface as a follow-up bug.
