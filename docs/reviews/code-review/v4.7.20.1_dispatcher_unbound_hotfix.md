# v4.7.20.1 — UnboundLocalError on async_dispatcher_send (Tier 1 hotfix review)

**Branch:** `feature/v4.7.20.1-dispatcher-unbound-hotfix` @ `8e8d95d` (+ post-review LOWs)
**Tier:** 1 (single adversarial review — 1 production file, surgical import removal). Bug Class #34 recurrence.

## What broke

v4.7.20's fan-noise B-H2 fix-up hoisted `async_dispatcher_send` to a module-top
import in `presence.py:68` but left bare **function-local** imports of the same
name in `_run_inference` (line 4443) and `_handle_face_arrival` (3223). A
function-local import re-scopes the name as a method-local for the **entire**
function; the `_run_inference` import sits in the **conditional** house-state-change
branch, so on every tick without a state change the later uses
(`SIGNAL_PRESENCE_ENTITIES_UPDATE` at ~4760 + the new fan-gate dispatch at ~4613)
were unbound → `UnboundLocalError`. Live: ~174 occurrences in the first hour
(every tick), confirmed via HA `error_log` traceback. This is a recurrence of
Bug Class #34, evading the original v4.5.11 AST guard's "used-before-import-line"
heuristic because the import is conditional (line order ≠ execution order).

**Functional impact:** presence sensors lost their proactive attr re-render push
(still update on HA's natural re-query); the Layer-2 fan-gate signal never
dispatched. No safety/HVAC impact — truth-preserving invariant (H2) held clean.

## Fix (`8e8d95d`)

Removed both redundant bare function-local imports; the module-top binding
(`presence.py:68`) is now the sole binding. Added
`quality/tests/test_v4_7_20_1_dispatcher_unbound_regression.py` — an AST guard
forbidding any bare function-local re-import of `async_dispatcher_send`, plus a
module-top-presence assertion. Proven non-hollow (flags both pre-fix offenders).
