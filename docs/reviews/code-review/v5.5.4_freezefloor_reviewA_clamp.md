## Findings

### A-HIGH-1 — Freeze clamp bypasses the MIN_DEADBAND invariant → can emit inverted range ⚠️
**Severity: HIGH** · `hvac.py:1517` (clamp), `preset_overrides.py:186-196` (invariant), `_MIN_DEADBAND=2.0` at `preset_overrides.py:36`.

`OverrideEngine.resolve_range` enforces a post-resolution invariant `cool_low ≤ cool_high − 2.0`, clamping `cool_low` DOWN if violated (`preset_overrides.py:189-196`). The freeze floor runs AFTER that, in the coordinator (`hvac.py:1517` `emit_low = self._apply_freeze_floor(resolved.cool_low)`), raising `cool_low` to 50 with **no re-check of the deadband**. If a zone's resolved `cool_high < 52`, the emitted pair becomes `(50, cool_high)` with `cool_low > cool_high − 2` — and if `cool_high < 50`, the pair is **inverted** (e.g. resolved `(45, 49)` → emitted `target_temp_low=50, target_temp_high=49`).

This is not a theoretical corner. The feature's own rationale (spec line 12, 20) is that normal presets already hold ≥58°F, so the floor "only catches a custom/edge preset set dangerously low." A custom preset with a low cool_high is precisely that edge case — so the one scenario where the clamp actually fires is the scenario most likely to violate the deadband. Most thermostats reject or silently coerce `target_temp_low > target_temp_high`; behavior is device-dependent and unsafe to leave to the integration layer. cool_high is "untouched" per spec, but untouched-and-inverted is worse than a coordinated nudge.

**Recommended fix:** clamp `emit_high` up alongside `emit_low` to preserve the deadband — `emit_high = max(resolved.cool_high, emit_low + _MIN_DEADBAND)` when the floor fires — or route the floored low back through the same invariant. Add a test: resolved `(45,49)` + freeze active → emitted pair satisfies `emit_low ≤ emit_high − 2`. (Reviewer C owns test authority; flagging the gap.)

### A1 — `_apply_freeze_floor` clamp math ✅
`hvac.py:1424-1431`. `return max(cool_low, float(FREEZE_FLOOR))` only when `self._freeze_active and cool_low < FREEZE_FLOOR`, else bare `cool_low`. Monotone-raising, never lowers (`max`), explicit `float()` cast avoids int/float comparison surprises. The `cool_low < FREEZE_FLOOR` guard makes the `max` redundant-but-harmless. Correct in isolation. ✅ (see A-HIGH-1 for the cross-field interaction).

### A2 — `_update_freeze_active` hysteresis boundary logic ✅
`hvac.py:1395-1422`. Arms when `temp <= FREEZE_TRIGGER_TEMP` (≤35 — correct, ≤ not <). Once armed, clears only when `temp > FREEZE_TRIGGER_TEMP + FREEZE_TRIGGER_HYSTERESIS` (`> 38` — strict, correct). In the 35–38 band an already-armed latch stays armed (neither branch flips it). At exactly 38 it stays armed (`38 > 38` is False) — matches spec "clear at 38" intent (clears strictly above 38). `FREEZE_TRIGGER_HYSTERESIS=3` → ceiling 38. No flap. ✅

### A3 — `_get_best_outdoor_temp` fail-open + crash safety ✅
`hvac.py:1377-1393`. `_predictor` is constructed unconditionally in `__init__` (`hvac.py:159`), so `getattr(self, "_predictor", None)` is belt-and-suspenders but never None in practice. Delegates to `HVACPredictor._get_outdoor_temp` (`hvac_predict.py:1096-1106`), which returns None for missing entity, `unavailable`/`unknown`, and `ValueError/TypeError` (non-numeric). Outer `try/except Exception` → `_LOGGER.debug` + None. None → `_update_freeze_active` sets `_freeze_active=False` (`hvac.py:1404-1406`) → fail-open, no fabricated freeze. No crash on unavailable/unknown/non-numeric. ✅

### A4 — Injection point + idempotent throttle ✅
`resolved.cool_low` IS `target_temp_low`: the `set_temperature` write (`hvac.py:1536-1537`) maps `emit_low`→`target_temp_low`, `emit_high`→`target_temp_high`, and `emit_low` derives from `resolved.cool_low` (`hvac.py:1517`). `ResolvedRange.cool_low` is documented as the low cooling bound (`preset_overrides.py:78`). The throttle pair `resolved_pair = (emit_low, emit_high)` (`hvac.py:1522`) uses the POST-clamp values and is what gets cached to `_last_emitted_range` (`hvac.py:1541`), so a clamp cannot be suppressed by a stale pre-clamp comparison — the first armed cycle differs from the cached normal pair and fires; the cleared cycle differs again and restores. `emit_high = resolved.cool_high` unmodified — cool_high never altered by the clamp itself. ✅

### A5 — No-op byte-identity ✅
Freeze inactive: `_apply_freeze_floor` returns bare `cool_low` (`hvac.py:1431`), `emit_high = resolved.cool_high`, so `resolved_pair` equals the pre-fix `(resolved.cool_low, resolved.cool_high)` — byte-identical, no spurious write. heat_low ≥ 50 with freeze active: guard `cool_low < FREEZE_FLOOR` is False → bare `cool_low` → identical. The pre-fix throttle compared `(resolved.cool_low, resolved.cool_high)`; the new code compares the same tuple in both no-op paths. ✅

### A6 — `_freeze_active` RAM init / no Bug Class #52 ✅
`hvac.py:236` `self._freeze_active: bool = False` in `__init__`. No RestoreEntity, no `.storage` read, no coercion of an `unavailable` restored value (Bug Class #52 is structurally impossible here). On restart it re-derives from live temp on the first `_async_apply_preset_overrides` cycle via `_update_freeze_active` (`hvac.py:1472`). Worst case after a cold-restart during a freeze: one decision cycle of un-floored range before re-arming — acceptable and consistent with the "re-derive every cycle" design. ✅

### A7 — `_update_freeze_active` called once per apply, before zone loop ✅
`hvac.py:1471-1472` — invoked once at the top of `_async_apply_preset_overrides`, before resolving any zone, so all zones in a cycle see a consistent latch. ✅
