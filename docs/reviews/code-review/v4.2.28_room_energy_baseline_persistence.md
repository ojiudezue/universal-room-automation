# v4.2.28 Code Review — Room Energy Baseline Persistence

**Tier:** 2 (Feature cycle scope: new DB schema + DAO + behavior change in 3 paths)
**Date:** May 5, 2026
**Pre-review baseline tag:** `pre-review-v4.2.28`

## Scope

Three files modified to fix the room `STATE_ENERGY_TODAY` inflation bug (e.g., `study_a_closet = 5306 kWh "today"` with `power = 0 W`):

1. **`database.py`** — new table `room_energy_baselines (room_id, sensor_id PK, baseline_value, baseline_set_at, needs_reset)`. Three new DAO methods.
2. **`coordinator.py`** — energy loop refactor: lazy-load baselines from DB, handle unavailable-at-midnight properly via `needs_reset` flag, stale-baseline recovery, sanity guard at 500 kWh delta cap.
3. **`__init__.py`** — register `cleanup_room_energy_baselines` in both nightly maintenance op lists.

## Reviews completed (per CLAUDE.md Tier 2 protocol)

### Review 1 (Core A) — Adversarial bug-class audit

| Severity | Finding | Status |
|---|---|---|
| CRITICAL | UTC vs local timezone mismatch (Bug Class #11) — `baseline_set_at` written via `dt_util.now()` (local) but cleanup cutoff via `dt_util.utcnow()` (UTC); string comparison would fail | **Pre-emptively fixed** before review completed: all 3 `save_room_energy_baseline` callsites now use `dt_util.utcnow().isoformat()` |
| HIGH | Race on first refresh — `_energy_baselines_loaded` flag check could double-load if concurrent `_async_update_data` calls slip through | **Fixed**: set flag BEFORE the await (`coordinator.py` ~line 1471) |
| HIGH | aiosqlite cursor `async for row in cursor` requires aiosqlite ≥0.19 | **Fixed**: switched to `await cursor.fetchall()` then iterate (database.py:3479) |
| HIGH | `SANE_MAX_DELTA_KWH = 200` too aggressive for legit multi-day EV/solar outages | **Fixed**: raised to 500 kWh (~10 days × 50 kWh/day on EV circuit) |
| MEDIUM | DB save failures only logged at DEBUG; lose visibility into write degradation | **Fixed** (rolled into Tier 2 sweep): 3 callsites upgraded to WARNING |
| MEDIUM | Backward-compat path on first run | **Accepted**: try/except wraps the load; returns `{}` on any error → falls through to existing `first_seen` logic |
| LOW | `entry.entry_id` stability assumption | Accepted as documented HA behavior |
| LOW | Midnight flag write logic clarity | Accepted; comment added |

### Review 2 (Core B) — Race / restart resilience / lifecycle audit

| Severity | Finding | Status |
|---|---|---|
| **CRITICAL** | **Restart at 6am scenario broken** — `_last_energy_reset` set to today-midnight in `__init__`; on first refresh `midnight_reset = False` and persisted (yesterday-midnight) baseline is used as-is → delta = 24h+ accumulation incorrectly attributed to "today" | **Fixed**: stale-baseline detection on load. If persisted baselines are pre-today-midnight (URA was offline across midnight), backdate `_last_energy_reset = yesterday-midnight` so midnight_reset fires and baselines reset to current_value. STATE_ENERGY_TODAY starts fresh from restart-time. Better than reporting 24h+ junk; cleanly self-corrects at next true midnight. |
| MEDIUM | Race on `_energy_baselines_loaded` (Review 2 caught same as Review 1 HIGH #1) | Already fixed |
| MEDIUM | DB write atomicity — failed save leaves in-memory ahead of DB | Accepted with warning-level logging upgrade |
| LOW | Sanity threshold 200 kWh (caught by Review 1, raised to 500) | Already fixed |
| LOW | Lazy-load happens in `_async_update_data` not `async_config_entry_first_refresh` | Accepted; functionally correct, ~1-5s later than ideal |
| LOW | No explicit test for 6am-after-midnight restart | Filed as future-cycle test |

### Edge case verification

| Scenario | Result |
|---|---|
| Restart 12:01am (just past midnight) | ✓ delta ≈ 1 min usage |
| Restart 6am same day | ✓ stale-baseline detector fires; baselines reset to current; energy_today restarts from now |
| Restart 11:59pm same day | ✓ baseline from this morning's midnight intact (baseline_set_at is from today); midnight_reset doesn't fire prematurely |
| Restart next day 6am after 24h+ outage | ✓ midnight_reset fires (today > yesterday) regardless |
| Sensor entity_id rename | ✓ stale row 90-day cleanup; no migration needed |
| New sensor mid-day | ✓ first_seen branch sets baseline = current_value; today's STATE_ENERGY_TODAY only counts post-now |
| Sensor unavailable at midnight | ✓ needs_reset flag set; stale recovery on next available read |
| Multiple rooms, same shared sensor | ✓ PRIMARY KEY (room_id, sensor_id) allows; each room tracks independently |
| Coordinator entry reload | ✓ `_energy_baselines_loaded = False` on new instance, force re-load |
