# v5.5.4 Freeze-Floor — Review D (Adversarial Completeness / Backstop Pass)

**Reviewer framing:** ADVERSARIAL COMPLETENESS — hunt a freeze-floor LEAK.
**Branch:** `feature/freeze-floor` (tip `7eb38733`), diff = `git diff develop..HEAD`.
**Invariant under test:** *"During a freeze (outdoor ≤ 35 °F), no URA code path emits a zone `heat_low` (`target_temp_low`) below 50 °F."*
**Spec:** `docs/planning/PLANNING_freeze_safety_range_shift.md` — "FINALIZED DESIGN (Option B)".
**Date:** 2026-06-17.

---

## VERDICT — LEAK FOUND: **YES** (two reachable freeze-concurrent paths emit `target_temp_low < 50` WITHOUT the floor)

The floor is placed at a SINGLE site — `_apply_freeze_floor(resolved.cool_low)` inside
`_async_apply_preset_overrides` (`hvac.py:1517`). It clamps **only** the preset-resolved
range written by the preset-apply path. Two other `set_temperature` writers emit
`target_temp_low` on the *same* HVAC decision cycle, *downstream* of the floored write,
and **neither routes through `_apply_freeze_floor`**:

| # | Leak path | file:line | Originates a sub-50 low? | Freeze-concurrent? | Severity |
|---|-----------|-----------|--------------------------|--------------------|----------|
| **L1** | **Pre-heat** (`_execute_pre_heat`) | `hvac_predict.py:1045,1052-1058` | **YES** — `pre_heat_temp = zone.target_temp_low + 2` reads the **stale live** low (pre-floor), can be < 50 | **YES — structurally** (gate is outdoor ≤ 35 = the freeze condition itself) | **HIGH** |
| **L2** | **Override compromise** (`_handle_normal_override` → `_apply_compromise`) | `hvac_override.py:808,871-873` | **YES** — `compromise_heat = expected_heat + heat_delta/2` can be < 50 on a downward manual override | **YES if a freeze is active** (override-driven, season-agnostic) | **MEDIUM** |

A backstop pass exists precisely to catch the site the clamp's author did not think to cover.
**L1 is that site** — and it is not a coincidental overlap: pre-heat's trigger temperature
(`PREHEAT_FORECAST_LOW = 35`, `hvac_predict.py:38`) is *identical* to `FREEZE_TRIGGER_TEMP = 35`
(`hvac_const.py:362`), and both read the **same** outdoor sensor (the floor's
`_get_best_outdoor_temp` delegates to `predictor._get_outdoor_temp()`, `hvac.py:1388`). When the
floor arms, pre-heat is eligible to fire **by construction**.

## L1 — PRE-HEAT (HIGH): the backstop leak

### Mechanism
`_async_evaluate` runs, per cycle, in this order:

1. **`hvac.py:868` `update_all_zones()`** — refreshes `zone.target_temp_low` from the **live
   thermostat attribute** (`hvac_zones.py:449`). This is the value the thermostat currently holds.
2. **`hvac.py:904` `_apply_house_state_presets()` → `_async_apply_preset_overrides()`** —
   the freeze floor clamps `resolved.cool_low` up to 50 and issues `set_temperature` with
   **`blocking=False`** (`hvac.py:1539`). Crucially it updates only `_last_emitted_range`
   (`hvac.py:1541`); it does **NOT** write back into `zone.target_temp_low`.
3. **`hvac.py:930` `_predictor.update()` → `_check_pre_conditioning()` → `_execute_pre_heat()`** —
   reads `zone.target_temp_low` (`hvac_predict.py:1045`) and emits
   `target_temp_low = zone.target_temp_low + 2` (`hvac_predict.py:1057`).

Because step 2's write is non-blocking and never updates the in-memory `zone.target_temp_low`,
step 3 reads the **stale, pre-floor** low from step 1. If a custom/edge preset (the exact case
the floor exists to catch) yields a live low below ~48 °F, then:

```
pre_heat_temp = zone.target_temp_low + 2  < 50  →  emitted UNCLAMPED
```

The floor's whole reason to exist (per spec line 12: *"catches a custom/edge preset set
dangerously low"*) is the precise case where the live low is < 48 — so the pre-heat `+2` lands
under 50 and pre-heat *overwrites the floor's correct 50 with a sub-50 value, later in the same
cycle.*

### Reachability gates (all default-satisfiable)
- **Master gate** `_is_pre_conditioning_enabled()` defaults **True** (`hvac_predict.py:719-721`).
- **Pre-conditioning master toggle** (HC `pre_conditioning_enabled`) default True.
- `not is_unoccupied` AND `zone.any_room_occupied` (`hvac_predict.py:614,1040`) — a normal occupied house.
- `season == SEASON_WINTER` (`hvac_predict.py:619`) — true during a real freeze.
- `outdoor_temp <= preheat_forecast_low` (35) (`hvac_predict.py:621`) — **identical to the freeze
  trigger**: whenever the floor is armed, this is satisfied.
- `OFF_PEAK_END_HOUR - PREHEAT_LEAD_HOURS <= hour < OFF_PEAK_END_HOUR` — a 1-hour pre-peak window
  each morning (`hvac_predict.py:622`). One-shot per day via `_pre_heat_triggered_today`.

### Concrete repro
- **Config:** a zone with a custom winter preset whose heat_low resolves to **47 °F** (below the
  50 floor — the case the floor targets). Pre-conditioning master ON (default). Occupied house,
  winter season.
- **State:** outdoor sensor reads **30 °F** (≤ 35 → freeze armed AND pre-heat eligible). Clock in
  the pre-heat lead window (one hour before off-peak ends).
- **Cycle N (freeze just armed, or any cycle in the lead window):**
  1. `update_all_zones` → `zone.target_temp_low = 47` (live).
  2. Floor fires: emits `set_temperature target_temp_low=50` (blocking=False). `zone.target_temp_low`
     still 47 in memory.
  3. Pre-heat fires: `pre_heat_temp = 47 + 2 = 49`; emits `set_temperature target_temp_low=49`.
  → **Net thermostat low for the day = 49 °F < 50 °F floor. INVARIANT BROKEN.**

Even in *steady state* (live low already driven to 50 by the floor on a prior cycle), pre-heat
reads 50 and writes 52 — safe. **But the leak window is exactly the dangerous transient: the
first freeze cycle, a slow non-blocking write, a thermostat that hasn't yet reflected the floored
50, or a custom preset whose live low sits in [48,50).** And because pre-heat is one-shot per day
(`_pre_heat_triggered_today`, `hvac_predict.py:625`), a single sub-50 emission **sticks for the
remainder of the off-peak window** with no re-floor until the next `_async_apply_preset_overrides`
re-resolves — which re-emits 50, but pre-heat may already have set the thermostat to 49 and the
floor's idempotent throttle (`_last_emitted_range`) still reads `(50, high)` so it **will not
re-correct** unless the resolved pair changes. The throttle map believes it emitted 50; it has no
knowledge pre-heat clobbered it to 49.

### Why the single-path placement is insufficient
The floor guards the *preset-resolution* writer only. It has **no authority over the live
thermostat low that pre-heat reads**, and no authority over pre-heat's own write. The spec's
self-description (line 20-21) — *"the existing idempotent set_temperature write means no spam …
auto-restore is free"* — assumes the preset path is the **only** `target_temp_low` writer. It is
not. Pre-heat (and override-compromise, L2) are independent writers.

## L2 — OVERRIDE COMPROMISE (MEDIUM)

`_handle_normal_override` (`hvac_override.py:784`) computes, on a manual user override of a zone
setpoint:

```python
heat_delta      = float(new_low) - expected_heat          # :806  (new_low = user's manual low)
compromise_heat = expected_heat + heat_delta / 2          # :808  (halfway toward the override)
```

then `_apply_compromise` emits `set_temperature target_temp_low = compromise_heat`
(`hvac_override.py:871-873`), **unclamped**. If the user manually drags the low setpoint well
below the preset (e.g. expected_heat = 60, user sets new_low = 38 → compromise_heat = 49), the
emitted low is **49 < 50**. This path is season-agnostic and fires whenever a manual override is
detected — so it is freeze-concurrent if a freeze is active. It is lower severity than L1 because
it requires an explicit user action and the values are bounded by the override delta, but it is a
genuine unclamped sub-50 emission during a freeze.

## RECOMMENDATION

**The single-path placement is a LEAK. Promote the floor to a CENTRAL CHOKEPOINT.**

Every `target_temp_low` emission should route through `_apply_freeze_floor` before the
`set_temperature` service call. Concretely:

1. **Minimum fix (seals L1 + L2 + the banking/release propagation caveats):** wrap the
   `target_temp_low` value at **each** `set_temperature` call site in
   `hvac_predict.py` (1057, 919, 849) and `hvac_override.py` (871) with the coordinator's
   `_apply_freeze_floor(...)`. Pre-heat (L1) and override-compromise (L2) are the two that can
   *originate* a sub-50 low and **must** be clamped; the banking/release/nudge sites should be
   clamped too so they cannot *propagate* a leaked low.
   - Pre-heat lives in `HVACPredictor`, override-compromise in the override engine — both already
     hold a back-reference to the coordinator (`self._hvac_coord` / `_override_arrester` owner), so
     `self._hvac_coord._apply_freeze_floor(low)` is reachable. Confirm the accessor at build time.

2. **Stronger fix (recommended):** introduce a single private emitter on `HVACCoordinator`, e.g.
   `_emit_set_temperature(entity, low, high)`, that applies `_apply_freeze_floor(low)` and issues
   the service call, and migrate **all** `climate.set_temperature` writers (preset apply, pre-heat,
   pre-cool, banking, release, override compromise/nudge/revert) onto it. This makes the floor a
   true invariant choke — no future writer can bypass it — which is exactly what a safety floor
   should be. The current design leaves the invariant defended at one of ~7 doors.

3. **Mutation/test gap to close:** the new behavioral file
   (`quality/tests/test_freeze_floor.py`) drives the preset-apply path only. Add a test that runs a
   full `_async_evaluate` cycle (or at least `_check_pre_conditioning` after a floored apply) with
   a sub-48 custom preset + outdoor 30 °F + winter + occupied + pre-heat window, and asserts the
   **final** captured `set_temperature target_temp_low ≥ 50`. Today that test would FAIL — proving
   the leak. Add the symmetric override-compromise test.

## Severity summary

| Finding | Severity | Originates sub-50 during freeze? | Must-fix before deploy? |
|---------|----------|----------------------------------|--------------------------|
| L1 pre-heat | **HIGH** | Yes (structural — same trigger temp + same sensor) | **YES** |
| L2 override compromise | **MEDIUM** | Yes (user-driven) | **YES** (cheap to fix alongside L1) |
| Banking/release/nudge propagation | LOW | No (re-emits a leaked low) | Recommended (free via chokepoint) |

**Bottom line for the backstop pass:** the invariant *"no path emits heat_low < 50 during a
freeze"* is **NOT** upheld. The floor guards one of several `target_temp_low` writers; the
pre-heat writer — which is gated on the *identical* freeze condition and reads a stale pre-floor
low — emits unclamped sub-50 in the exact custom-preset scenario the floor was built to protect.
Do not deploy single-path; promote to a central chokepoint (or at minimum clamp pre-heat + override
compromise).
