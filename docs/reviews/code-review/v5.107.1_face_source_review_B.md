## Cleared (holds because)

- **Index build and refresh lifecycle.** The face index is built inside `CameraResolver._build_indices` (`camera_resolver.py:615-676`), in the same single registry pass. Only `CameraIntegrationManager._get_resolver` (`camera_census.py:519-535`) constructs the resolver it uses. That method rebuilds lazily when `_resolver_dirty` is set, and `EVENT_ENTITY_REGISTRY_UPDATED` / `EVENT_DEVICE_REGISTRY_UPDATED` set the flag (`:495-510`). Those events cover a late Frigate entity add (create), a rename or unique_id-preserving entity_id change (update), and an enable or disable (update; disabled entities are skipped at `camera_resolver.py:623`). The unsubs are tracked and released in `async_shutdown` (`:537-546`). The cycle adds no listener, task or timer. Boot: the entity registry is restored from storage before Frigate loads, so the index is populated on the first access even when Frigate entities come up late.
- **No stale index held across rebuilds.** Every new call site fetches the resolver per call (`_face_source_resolver` → `_get_resolver`, `camera_census.py:3231-3238`). `face_name_entities_for_entity` reads the live `self._er.async_get` (an O(1) dict lookup). The S9 latch memo is keyed on resolver identity (`:5491-5499`), so a rebuild clears it.
- **Per-tick cost.** There is no registry walk on the tick path. S1/S2 are dict lookups into prebuilt indices (`face_name_entities_for_stem`). S5-S7 do one `er.async_get` per `_N` camera. `_get_face_name_aliases` iterates config entries until it reaches the integration entry, the same cost as the existing `_get_tracked_person_slugs`. The `_build_indices` sort is per device and small.
- **Reload-suppress discharge for `CONF_FACE_NAME_ALIASES`** (`__init__.py:7735-7739`).
