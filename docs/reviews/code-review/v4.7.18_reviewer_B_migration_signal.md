## Findings

### B-L1 — Dead `async_show_form` branch in Surface 2 save handler
- **Severity:** LOW
- **Bug class:** Dead code (no formal QUALITY_CONTEXT class)
- **File:line:** `config_flow.py` (post-D1 save handler in `async_step_zone_dynamic_preset`, lines ~6105–6155 at HEAD)
- **Detail:** After D1 stripped the inline bucket validation, the `if user_input is not None: errors = {}` block has no path that adds anything to `errors`. The `if not errors:` branch always runs, the `return self.async_show_form(..., errors=errors)` after it is unreachable for the new shape. Voluptuous-level coercion failures still surface via HA's normal data-entry-flow plumbing, so this is hygiene, not a functional bug.
- **Action:** Defer. Trim in a future hygiene cycle alongside the trailing 17 conf_keys in the `_build_dynamic_preset_schema` positional args (already documented as back-compat tolerance).

### B-L2 — Restart-time race: counter restore can clobber a freshly-incremented in-memory value
- **Severity:** LOW
- **Bug class:** #46 (lazy derivation) / #45 (concurrent reload race) — adjacent
- **File:line:** `dynamic_preset.py:403–432` (`restore_blocked_counter`) interacting with `sensor.py:6917–6936` (listener-then-restore order in `DynamicPresetActiveBucketSensor.async_added_to_hass`).
- **Detail:** The sensor subscribes to `SIGNAL_DYNAMIC_PRESET_TRANSITIONED` + `SIGNAL_DYNAMIC_PRESET_OVERRIDES_UPDATED` BEFORE `await self.async_get_last_state()` completes and BEFORE `_try_restore_blocked_counter()` calls `source.restore_blocked_counter()`. If an EC tick happens to fire the heat-wave gate inside this microsecond window for a cold-start zone (counter 0 → 1), the subsequent restore will UNCONDITIONALLY overwrite the in-memory counter with the previously-stored value (`if c > 0: self._relax_ceiling_blocked_count[zone_id] = c`). Net effect: a single increment can be lost on first-tick-after-restart for a zone whose previous-session count was non-zero. In practice the EC tick is on a 5-min cadence and the restore completes in microseconds, so the window is vanishingly small.
- **Suggested fix (future):** Take MAX of restored vs current in-memory: `self._relax_ceiling_blocked_count[zone_id] = max(self._relax_ceiling_blocked_count.get(zone_id, 0), c)`.
- **Action:** Defer. Counter is observational (not load-bearing on actuation).

### B-L3 — Orphaned translation keys in strings.json/en.json
- **Severity:** LOW
- **Bug class:** Hygiene
- **File:line:** `strings.json` / `translations/en.json` — `dynamic_preset_range_invalid` and `dynamic_preset_sleep_below_floor` are retained but their sole producer (`_validate_dynamic_preset_input`) was deleted in D2.
- **Detail:** Removing the bucket-required keys was correct. The two remaining keys above are now orphaned (no code path can surface them as errors). The `dynamic_preset_bucket_required_*` removals are symmetric across both files (verified). Keeping the orphans does no harm but adds drift risk if a future cycle resurrects validation under a different name.
- **Action:** Defer to next hygiene sweep. Document in cycle close-out.

### B-L4 — D4 dropdown labels bypass HA i18n machinery (acceptable single-locale workaround)
- **Severity:** LOW
- **Bug class:** HA pattern divergence
- **File:line:** `config_flow.py` (`async_step_hvac_dynamic_preset`, `_ceiling_mode_options` list at lines ~4218–4225)
- **Detail:** The 5 option labels (`Auto (recommended)`, `Conservative — skip above 85°F`, ...) are Python literals inside `SelectSelectorConfig(options=[...])`. HA's preferred pattern is `translation_key=...` + matching `selector.<key>.options.*` entries in strings.json. The integration is single-locale (en) so practical impact is nil, but the divergence diverges from the convention used elsewhere in the file.
- **Action:** Defer. Acceptable as-is given URA's single-install single-locale stance.

### 4. WPM accessor contract — CLEAN

- Heat-wave gate fires NO new signals. It only mutates per-zone counters + zeroes `cool_high_adjustment_f`.
- `SIGNAL_DYNAMIC_PRESET_TRANSITIONED` payload shape unchanged (still `{zone_id, previous_bucket, new_bucket, delta_f, now_iso}` at `dynamic_preset.py:728–733`).

- `SIGNAL_DYNAMIC_PRESET_OVERRIDES_UPDATED` from `energy.py:2812` continues to fire after every EC tick — sensor attrs (including the new D5 ones) refresh reactively.

### 6. Restart resilience — CLEAN (with B-L2 caveat)
