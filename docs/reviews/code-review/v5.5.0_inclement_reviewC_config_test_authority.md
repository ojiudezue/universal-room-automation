## Findings

### C-1 — Select dropdowns render raw internal keys, not the spec's plain-English labels — ⚠️ HIGH (config clarity)
**Bug class:** Configurability clarity (named-bucket dropdowns + plain-English labels).
**Files:** `config_flow.py:3502` (WARN_MIN_SEVERITY), `config_flow.py:3566` (CONDITION_CORROBORATION_MODE).
**Reasoning:** Both `SelectSelectorConfig(options=list(INCLEMENT_*_OPTIONS))` pass **bare string lists** as options, so HA renders the raw value as the label. The operator sees `any` / `majority` / `unanimous` in the corroboration dropdown — NOT the spec's operator-facing labels "Any provider stormy" / "Majority of healthy providers (recommended)" / "All providers stormy". WARN_MIN_SEVERITY is less bad (renders `Extreme`/`Severe`/`Moderate`/`Minor` — at least real words) but still drops the per-option guidance the spec table prescribed.
**This ignores an established in-repo precedent.** The DPM relax-ceiling dropdown (v4.7.18, `config_flow.py:4675–4691`) solves exactly this: it builds `[{"label": "<plain English — description>", "value": <internal key>}, ...]` SelectOptionDicts, explicitly noting "HA's SelectOptionDict only carries {label, value}… no `translation_key` plumbing exists elsewhere in this file." The inclement build should have copied that `{label, value}` pattern for both selects.
**Fix (in-lane, ~15 LoC):** Replace the two bare option lists with `{label, value}` dicts (label = spec's operator-facing text, value = existing internal key). No const change needed beyond the option dicts; values stay `any/majority/unanimous` and `Extreme/Severe/Moderate/Minor` so enum consistency (charge 5) is preserved. The corroboration `data_description` already carries the per-key meaning, so at minimum the corroboration labels must be promoted to readable form.
**Mitigation present:** the Advanced `data_description` for corroboration does spell out `'any'/'majority'/'unanimous'`, so a careful operator can decode it — which is why this is HIGH not CRITICAL.

### C-2 — Severity select options not severity-ordered / missing per-option description — ⚠️ LOW
**Bug class:** Configurability clarity.
**File:** `config_flow.py:3502`; `energy_const.py` `INCLEMENT_WARN_MIN_SEVERITY_OPTIONS = ["Extreme","Severe","Moderate","Minor"]`.
**Reasoning:** Order is high→low which is defensible, but the spec table's per-option guidance ("'Severe' (recommended) — Severe + Extreme", etc.) lives only in the field-level helper text, not on the options. Folds into the C-1 fix (use `{label,value}` with the recommended-marker on Severe). Low because the field helper already carries the full explanation.

### C-3 — `contributing_events` includes severity-demoted events — ⚠️ LOW (observability)
**Bug class:** Observability fidelity (not a correctness bug).
**File:** `inclement.py:238–240`.
**Reasoning:** When the severity filter demotes a passed-gate alert (warn→watch→notice), the event is still appended to `contributing_events` (only the gate-fail path goes to `gated_out_events`). Tier aggregation is correct via `_max_tier`, so behavior is right. But an event demoted all the way to `notice` will appear in `contributing_events` while contributing tier=notice — slightly misleading for the `active_alert_event` attr. Cosmetic; consider routing fully-demoted (→notice) events to a separate bucket if observability matters. Not blocking.

### C-4 — `int()` coercion on Advanced numbers can raise on malformed stored options — ⚠️ LOW (robustness)
**Bug class:** Malformed-config robustness.
**File:** `energy_battery.py:727–734`.
**Reasoning:** `int(opts.get(CONF_INCLEMENT_PARTIAL_HOLD_RESERVE_FLOOR, DEFAULT))` will raise `ValueError`/`TypeError` if a stored option is a non-numeric string (shouldn't happen via the NumberSelector, but options can be hand-edited / migrated). The whole `_inclement_decision` is wrapped so a raise degrades to `allow_discharge` (`energy_battery.py:794–801`) — fail-safe, not fail-dangerous — but it would silently disable holds. Cheap guard: `try: int(...) except (TypeError, ValueError): DEFAULT`. Low.

### C-5 — Redundant repeated `_get_current` calls in POWER_THREAT_EVENTS render default — ⚠️ LOW (cosmetic)
**File:** `config_flow.py:3494–3501`. The `default=` ternary calls `self._get_current(...)` 3× for the same key. Hoist to a local. Cosmetic.
