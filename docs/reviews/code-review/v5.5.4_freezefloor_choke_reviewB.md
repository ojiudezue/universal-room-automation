### LOW B-L1 — Banking-release throttle map stores pre-guard pair
`hvac_predict.py:864-865` writes `last_emitted[zone_id] = (base_low, base_high)` (pre-guard), but the chokepoint may floor `base_low` up to `FREEZE_FLOOR` when freeze is active. The DPM apply throttle (hvac.py:1545, which stores the post-guard `resolved_pair`) would then see a mismatch and benignly re-emit once. No correctness/safety impact (the re-emit writes the same floored value), only a single redundant write on the rare banking-release-during-freeze edge. Compare: the DPM path was correctly updated to store `(emit_low, emit_high)`; banking-release was not. Optional: apply `apply_setpoint_guards` to the stored pair for consistency.

### NIT B-N1 — Chokepoint log fires only when low changes
`hvac_setpoint.py:79` logs the floor raise only when `target_temp_low` is present and altered. A caller that passes only `target_temp_high` (e.g. nudge/compromise at override sites) never triggers the floor (low is None) — correct, no missing log. No action.

### NIT B-N2 — `FREEZE_FLOOR=50` vs deadband
`apply_setpoint_guards` enforces `high ≥ low + MIN_DEADBAND` after flooring (hvac_setpoint.py:55), so a floored low=50 with a low cool_high won't invert (A-HIGH-1 fix). Verified the deadband clamp only raises `high`, never re-lowers `low` — band widens upward, safe for cooling-dominant zones. No action.
