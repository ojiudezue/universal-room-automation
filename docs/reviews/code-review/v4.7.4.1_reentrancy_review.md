## Semantic Correctness -- Deferral Analysis

### Runtime trace (happy path):

1. `async_setup_entry` runs migration logic, computes `_zones_updated`, flags `_migration_needed=True`.
2. `hass.async_create_task(_v474_defer_customize_buckets_persist(...))` is called at line 2355.
3. With HA's default `eager_start=True`, the coroutine starts executing immediately.
4. `_v474_defer_customize_buckets_persist` calls `async_update_entry` (synchronous method despite `async_` prefix).
5. `async_update_entry` fires `_async_update_listener` synchronously.
6. `_async_update_listener` (line 3185) calls `hass.async_create_task(async_reload(entry_id))` -- schedules reload.
7. The reload coroutine starts eagerly, hits its first `await` (entry lock acquisition), and yields. The lock is held by the current `async_setup_entry`, so the reload suspends.
8. Control returns through the chain to line 2355 in `async_setup_entry`, which continues to completion.
9. `async_setup_entry` returns, releases the entry lock.
10. The reload task resumes, calls `async_unload_entry` then `async_setup_entry` again.
11. On second setup, `CONF_ZONE_DYNAMIC_PRESET_CUSTOMIZE_BUCKETS` is already set on all zones, `_migration_needed=False`, no task scheduled. Clean pass.

### eager_start concern (MEDIUM, acceptable)

The `eager_start=True` default means this is not a true deferral -- the coroutine runs inline. The re-entrancy is prevented NOT by scheduling delay but by HA's `ConfigEntry` lock that serializes setup/unload operations. The reload task queues behind the lock and waits until the current setup completes. This is the correct outcome, but the mechanism is subtly different from what the docstring implies ("after async_setup_entry returns"). The practical effect is identical -- the fix works correctly.

### Idempotency: VERIFIED

If the deferred task fires and succeeds, `customize_buckets` is persisted. On the reload-triggered second pass, `_zd.get(CONF_ZONE_DYNAMIC_PRESET_CUSTOMIZE_BUCKETS)` returns the persisted value (not `None`), so the `if ... is None:` check at line 2335 is false. `_migration_needed` stays `False`. No task scheduled. Clean exit.

If the deferred task fails (exception caught at line 3167), the migration retries on next entry load because the flag is recomputed from zone state each time. Non-fatal, self-healing.

### Entry reference safety: VERIFIED

`_new_options` is computed as a dict snapshot at line 2354. `entry` is passed by reference but since the coroutine executes eagerly (same event loop tick), there is no window for `entry` to become stale. Safe.
