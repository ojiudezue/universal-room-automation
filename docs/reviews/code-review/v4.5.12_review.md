## Review 1 (Core A) — domain logic, mental execution

Reviewer walked every new code path end-to-end:

### D7 per-zone sensors

**`_ACRampZoneSensorMixin._get_zone()`** — walks `zm.zones.values()` matching by `climate_entity`. Handles all None-paths (manager absent, hvac coord absent, zone_manager attr missing under either name `_zone_manager` or `zone_manager`). Returns None gracefully when zone removed from config but registry entry persists.

**`HVACACRampStateSensor.native_value`** — `getattr(zone, "ramp_state", "idle")` defaults to "idle" if the attribute is missing. Important for any future upgrade scenario where ZoneState gets a new state value before the sensor is registered.

**`HVACACRampLastActionSensor.native_value`** — declared `SensorDeviceClass.TIMESTAMP`. HA requires a `datetime` return. Code uses `datetime.fromisoformat(ts)` with try/except — if the stored ISO is malformed for any reason, returns None (renders as "unavailable"). Verified: `OverrideArrester._track_zone_action` writes via `dt_util.now().isoformat()` which produces a tz-aware string. fromisoformat handles it correctly.

**`HVACACRampKwhRateSensor` staleness math** — `(datetime.now(last.tzinfo) - last).total_seconds()`. Subtle gotcha: requires `last.tzinfo` to be present. Since v4.5.11's `_read_kwh_rate` writes `last_kwh_rate_ts = now.isoformat()` where `now = dt_util.now()` (tz-aware), the parsed datetime carries tzinfo. No naive-vs-aware mix. ✓

### D8 house-wide sensors

**Cache refresh cadence** — `_refresh_impact_cache` called at the end of every `check_ac_reset` cycle (every 5 min). Five DB reads per cycle (3 per-zone state reads + 2 aggregate queries), all via transient `_db_read` connections — does NOT touch the write queue. No back-pressure risk.

**RestoreEntity for `kwh_avoided_total`** — sensor restores last value on boot. Until the first decision cycle populates the live cache, `native_value` returns `_restored_value`. Once cache populates, live value takes precedence. Smooth transition.

**False-positive rate hidden until N ≥ 5** — `_refresh_impact_cache` sets `false_positive_rate = None` when `evals_total < 5`. HA renders None as "unavailable". The `min_sample_for_display: 5` attribute discloses the threshold to dashboards.

**Manual triggers excluded from FP math** — verified by reading `database.get_ac_ramp_kwh_avoided` (slice 1 code, line 4540ish): `WHERE event_type='nudge_evaluated' AND triggered_by != 'manual'`. The D8 sensor inherits this filter. Risk R6 from v4.5.11 plan satisfied.

### D10 diagnostic dump button

**`async_press` flow** — get db → query `get_ac_ramp_events_recent(days=7)` → also get aggregates via `get_ac_ramp_kwh_avoided(days=None)` → write JSON to `/config/ura_diagnostics/ac_ramp_<ts>.json` → fire persistent_notification with file path.

**Error handling** — DB query, file write, and notification each wrapped in try/except. Failure in any one logs but doesn't crash the button. The button itself remains operable for a retry.

**Self-contained dump** — includes `aggregates` section so offline analysis doesn't need the original DB to interpret event sequence. Good for sharing with support.

**Path safety** — `Path(self.hass.config.config_dir) / "ura_diagnostics"`. `mkdir(parents=True, exist_ok=True)`. Timestamped filename prevents collisions on rapid presses. ✓

## Review 2 (Core B) — races, lifecycle, concurrency

Reviewer specifically looked for what Core A typically misses.

### Race 1: cache write vs sensor read

`_refresh_impact_cache` updates `self._impact_cache` via `.update(...)` (atomic dict update for keys). Sensors read individual keys via `.get(key, default)`. Single-threaded event loop → no torn reads. ✓

### Race 2: kwh_avoided_total cache miss on first cycle

On HA restart, the sequence is:
1. Coordinator manager initializes
2. HVAC coord starts
3. Sensor platform loads
4. **Sensor's `async_added_to_hass` fires** — `_restored_value` loaded from HA Storage
5. Sensor's `native_value` queried by HA UI → `_get_cache()` returns None (arrester not wired to DB yet OR refresh hasn't run) → falls back to `_restored_value`
6. First HVAC decision cycle fires (within 5 min) — `set_database()` happens, then `_refresh_impact_cache()` runs
7. Cache populated → sensor's next `native_value` returns live value

Window of stale data: up to 5 min. Acceptable for a kWh-avoided totalizer where minute-level precision doesn't matter.

### Race 3: dispatcher signal vs entity not-yet-added

All new entities call `super().async_added_to_hass()` BEFORE subscribing to the signal. HA's framework guarantees the entity is fully registered (`async_schedule_update_ha_state` will work) before async_added_to_hass returns. No early-fire race. ✓

### Day-rollover behavior

`nudges_today` and `resets_today` are read from `ac_reset_state` keyed by `(zone_id, date)`. At midnight, `_today_key()` returns the new date. Next read returns 0 (new-date row hasn't been written yet). Between midnight and first decision cycle of new day (≤5 min): cache still holds yesterday's values. Sensors show yesterday's counts until refresh runs.

**LOW finding L1:** Stale "today" counts visible for up to 5 min after midnight. **Accepted** because the bug doesn't accumulate (next refresh corrects), the cost of mitigating (force-refresh on day-rollover detection) is ~30 LoC of conditional logic in `_refresh_impact_cache`, and no user has reported this as a problem.

### Restart resilience

- `_impact_cache` is in-memory only. Lost on restart. Sensors return defaults (0, None) until first decision cycle. Acceptable — same pattern as slice 1's `_nudge_in_flight` set.
- `kwh_avoided_total` Restore persists the **displayed** value across restart so the dashboard doesn't blink to 0 momentarily. Verified the restored value is FLOAT-parsed safely (try/except on `float(last_state.state)`).
- `ac_reset_state` table queried fresh on first cycle → today's counts re-derive from DB. ✓
- `ac_ramp_events` table queried for aggregates → totals re-derive from DB. ✓

### Timer / listener cleanup

Every dispatcher subscription wrapped with `self.async_on_remove(...)`. HA framework guarantees unsubscribe on entity removal. The D10 button + D7/D8 mixins all follow this pattern. No leaked listeners.

### DB transaction safety

All new reads use `_db_read()` context manager — transient connections, no write-queue contention. No transactions span multiple reads. ✓

### Cross-coord interaction

D7/D8/D10 surface is HVAC-internal. No new reads or writes against Energy, Presence, Safety, Security, or Notification Manager state. No new cross-coord coupling. ✓

### Concurrency on platform setup

If sensor platform and button platform both load concurrently (HA does this), both walk `hass.data` → `coord_manager` → `hvac` → `_override_arrester`. Read-only. No mutation. No race. ✓
