## LEAD FINDING — Is the dangerous sustained-freeze case tested?

**❌ NO. The hazardous scenario (freeze STILL active but 2h hold EXPIRED → enforcer restores `heat_cool` and yanks the zone off emergency heat into a possibly-cooling range) is NOT tested, and as written it CANNOT be tested by this file** because the tests never touch the real coordinator, the real `_emergency_heat_zones` dict, or the real freeze re-arm path. The only emergency-heat tests are "live hold → skip" (`test_emergency_heat_hold_live_not_clobbered`, line 110) and "expired hold → resume" (`test_emergency_heat_hold_expired_resumes_enforcement`, line 117). The "expired" test ASSERTS the enforcer fires (`is True`, line 121) — i.e. it asserts the exact behavior Reviewer A is analyzing as the freeze hazard, with no signal that a freeze may still be live. There is no re-arm / freeze-persistence test at all (no test references `_set_emergency_heat`, the freeze sensor, or a second hold being set after expiry).

This is the single most important gap in the cycle from a test-authority standpoint: **the test suite green-lights the dangerous path.**

## Findings

### C1 — Tests reimplement the guard instead of driving production code ❌
**SEVERITY: HIGH · Bug Class C5 (tautological / parallel-reimplementation tests)**
`quality/tests/test_heatcool_enforcer.py:28-56` defines `_enforcer_would_write(...)`, a hand-rolled mirror of the enforcer predicate. Every test in the file asserts against THIS function — none import `HVACCoordinator` or invoke `_apply_house_state_presets` (`hvac.py:1068-1103`). The docstring even admits it: "These tests mirror the enforcer's guard predicate exactly" (line 9).

Consequence: **the tests would NOT fail if the real enforcer were reverted, mutated, or deleted.** Reverting `hvac.py:1079` back to `zone.hvac_mode == "off"`, or deleting the `_supports_heat_cool` guard (`hvac.py:1080`), or removing the egress/ac-reset/emergency skips (`hvac.py:1069-1081`) would leave every test GREEN, because the mirror function is independent of production source. They are non-falsifying with respect to the code they claim to cover.

A real precedent for driving the loop end-to-end already exists in-repo: `quality/tests/test_v478_egress_window.py:223,352` builds a fake `hass.services.async_call` that records calls and asserts on captured `set_hvac_mode` payloads after `async_tick`. `test_v4713_*` and `test_v4715_universalize_veto.py` also drive the real `_apply_house_state_presets`. The new file should have followed that pattern. **Must-fix:** at least one test must instantiate the coordinator (or call the real method with fakes) and assert a `set_hvac_mode=heat_cool` service call is/ isn't emitted for each gating case, so a reversion fails red.

### C2 — Sustained-freeze-beyond-2h scenario uncovered ❌
**SEVERITY: HIGH · Bug Class C5 (coverage gap on the dangerous path)**
See Lead Finding. No test models "hold expired AND freeze still live." Because C1 means the dict/freeze path isn't exercised at all, even the recovery-correctness question ("does the enforcer re-read the freeze sensor before yanking heat?" — it does NOT; `hvac.py:1071-1077` is purely time-bounded, `test_emergency_hold_does_not_protect_a_cool_drift` line 124 documents this as intentional) is asserted only against the mirror. **Must-fix (paired with A's verdict):** if A concludes the time-only expiry is acceptable, add an end-to-end test that proves expiry→enforce against the real method; if A concludes a freeze re-check is required, this file's `test_emergency_heat_hold_expired_resumes_enforcement` is asserting the wrong behavior and must change.

### C3 — Mutation sense: skips removable silently ⚠️
**SEVERITY: HIGH (subsumed by C1) · Bug Class C5**
Direct answer to the mutation question: **deleting the `_supports_heat_cool` guard, the egress skip, the ac-reset skip, or the emergency skip would each leave ALL tests passing.** The corresponding mirror branches (lines 44, 48, 52-56) are independent constants. The `heat_only`/`cool_only` "never forced" tests (lines 84-89) test the mirror's `supports_heat_cool` param, not `_override_arrester._supports_heat_cool` (`hvac_override.py:894`). No mutation of production source is caught.

### C5 — `_emergency_heat_zones` typing + cleanup hygiene ⚠️
**SEVERITY: LOW · Bug Class: RAM-state hygiene**
Declared `self._emergency_heat_zones: dict[str, Any] = {}` at `hvac.py:221`; values are always `datetime` (`hvac.py:1689`). Annotation should be `dict[str, datetime]` for self-documentation — `Any` hides the contract. **Growth bound:** keys are `zone_id` (finite, == number of zones), so the dict is intrinsically bounded; not an unbounded-growth hazard. **Cleanup:** the only purge is the lazy `del` at `hvac.py:1077`, which fires only when a held zone is re-evaluated by the enforcer loop. A zone whose emergency heat expires while the zone is simultaneously egress-paused (`continue` at line 1070 short-circuits BEFORE the hold-expiry check at 1073) will keep its stale expiry entry until the egress pause lifts — harmless (bounded, stale value is just an old timestamp) but worth a one-line note. **No test exercises the real dict's set/expire/del lifecycle** (C1 root cause again). LOW because the surface is small and bounded; recommend (not must-fix) one end-to-end test asserting the dict is populated by `_set_emergency_heat` and pruned after expiry.

### C6 — `EMERGENCY_HEAT_HOLD` copied, not imported ⚠️
**SEVERITY: LOW · Bug Class C5 (drift risk)**
`test_heatcool_enforcer.py:25` re-declares `EMERGENCY_HEAT_HOLD = timedelta(hours=2)` as a literal instead of `from ...hvac import EMERGENCY_HEAT_HOLD`. If production changes the window to e.g. 90min, the tests stay green against the stale 2h copy. Couple the test to the production constant.

## Verdict (Reviewer C): **FIX-THEN-SHIP**
The production change itself is not implicated by my lane (A/B own that). But the **test layer does not protect it**: C1/C2/C3 mean the enforcer, all four skips, and the dangerous expiry path could be reverted or mutated with the suite staying green — and the one emergency-heat behavior that IS asserted (`expired → enforce`) is the exact path Reviewer A is scrutinizing as a freeze hazard. Per Tier 2-DB Review C charter (test fixtures must drive production code paths, not their own logic), this fails the test-authority bar.

**Must-fix before ship:** (C1) add ≥1 end-to-end test driving real `_apply_house_state_presets` with fake `hass.services` (egress precedent), asserting `set_hvac_mode=heat_cool` is/isn't emitted per gating case so a reversion fails red; (C2) once A rules on time-only-vs-freeze-recheck expiry, add the sustained-freeze test against the real method (or correct `test_emergency_heat_hold_expired_resumes_enforcement` if A requires a freeze re-check).
**Should-fix:** (C6) import the real constant; (C5) `dict[str, datetime]` + dict-lifecycle test.
