## Cleared (holds because)

- **Legitimate action not suppressed.** In-window holds take the `_decide_hold` path unchanged. `_apply_prepare` returns `base` before any prepare fields on `full_hold` (`inclement.py:1301`) and when there is no prepare set (`:1257`). Table WSW/Extreme Cold/Freeze rows have no overrides, so `TABLE_SELECTION` holds (zero-override golden is Review A/C's lane). Stage A floor readers (`energy_battery.py:6937`, `:7155`) and ledger (`energy.py:9558`) read the registered field as planned. Re-grep found exactly the 7 §4.3 readers, with no eighth.
- **No-op path.** No alerts: `_apply_prepare` purges and returns `base`. The decision, reserve writes, CFG and ledger rows are unchanged. The one difference is an additive `inclement_selection` attr (`{"alerts": [], "overrides": ...}`). The removed `power_threat_events`/`warn_min_severity` cfg keys had no reader at base (grep).
- **Options change without reload.** All four override keys are in both `_NO_LIVE_ATTR_KEYS` and `OPTIONS_RELOAD_SUPPRESS_KEYS` (`__init__.py:7464-7520`). The form keys are popped before save (`config_flow.py:6189-6190`), and the save is gated by `if not errors` (`:6413`). Both the decision (`_inclement_config`, `energy_battery.py:2634-2645`) and the ledger (`_get_cm_options`, `energy.py:8367`) re-read live entry options every tick, so a change takes effect on the next tick everywhere. Alert memory stores the raw alert and is re-classified per tick through the selection, so a removed hold product drops out next tick (leaves prep, purged). A removed buy product sets eligible to False, which deletes the engaged latch and S (`inclement.py:1296-1300`). CFG then falls through.
- **Restart.** The latch and S are RAM, as stated. `_tou` is set in the constructor (`energy_battery.py:741`), so the first post-boot tick can schedule. A fresh S includes the current slot, so a mid-buy restart resumes.
- **Timers/tasks.** No new task, listener or `call_later` in the diff. Both `get_forecasts` calls are wrapped in `asyncio.timeout(20)` inside `async with _refresh_lock`. `TimeoutError` is caught by the existing `except Exception`, and the lock is released by the context manager (`weather_manager.py:413-435`, `:905-915`).
- **Cross-coordinator.** The buy keeps the arbitrage CHARGE / attain yields and the blind refusal (`energy_battery.py:6452-6455`). `force_redispatch` and the write-verify re-send replay `_effective_reserve_desired`, which already holds the folded registered floor. The EVSE overlay is max-raise only. The `_inclement_decision` cache is per `now`, and it is called only from `determine_mode` (`:6123`, `:6343`), so attribute reads never freeze S.
