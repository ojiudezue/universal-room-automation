## Cleared (holds because …)

- **`quiet=False` is byte-identical.** Every NM change is guarded `if quiet:` or `and not quiet`, or adds `quiet=quiet` to the keyword-only `_send_pushover` (default False). The other `_send_pushover` callers (`:3189`, `:4586`, `:5531`, `:5561`, `:5890`) do not pass it. Pushover priority, the Companion `is_critical` value, the response menu, panel, TTS, lights and `_enter_alerting` all match the base when quiet is False.
- **What quiet skips:** panel, TTS, lights, the response menu, the Pushover siren and priority 1, the Companion critical sound and safe-word actions, and live `_enter_alerting`. **What stays:** quiet hours/DND, silence, the safeword perimeter window, dedup, boot-settle, the routing matrix, buckets, the `notification_log` and audit rows (see #1), the activity log, the `nm_alert_dispatched` anomaly, `_last_notification` and the counters.
- **Dedup and cooldown.** The dedup key is `coord:title:location` (`:4652`). The follow-up title differs, so it neither consumes nor is swallowed by the original's key. The perimeter `_last_alert` cooldown is not touched by the follow-up. Boot-settle can suppress a follow-up inside the boot window, which is acceptable.
- **At most once / supersession.** The pending entry is popped before `async_create_task`. The `_tick` guard `self._pending_followups.get(cam_key) is not state` drops orphan ticks. `_arm_identity_followup` cancels any prior entry first on every successful dispatch. Demoted, LOW and VLM-demoted alerts never arm: `severity <= LOW`, `d["demoted"]` and `severity_after != severity.name` are checked against the D10.5 record with the same `at` (D10.5 and the dispatch share `now`, `perimeter_alert.py:1569` and `:1855`, and the same `cooldown_key`).
- **Timer lifecycle.** The chain is one live `async_call_later` per key. `unsub` is stored and cleared, and teardown (`perimeter_alert.py:1272-1274`) discharges every key after setting `_active=False`. Arm checks `_active`, which covers teardown during the original's `await async_notify`. Reload builds a fresh manager after the old one's teardown. The chain is bounded at 18 ticks.
- **Identity bar.** It calls the same `_known_identity_for`: floor `max(0.9, KNOWN_MIN_CONF)`, egress bus ±15 s, scored face ≥ 0.9, and unscored Frigate only with `_nonface_agrees` (boot-excluded). This matches D10.5 and §5.5(a): annotate only, never a severity change.
- **Reload allowlist and switch.** The key is added to `INTEGRATION_OPTIONS_RELOAD_SUPPRESS_KEYS` and fresh-read through `_options_flag`.
