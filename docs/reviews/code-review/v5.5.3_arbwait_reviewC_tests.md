## Findings

### C-INFO-1 — Global monkeypatch mutation is aggregate-only (NOT a defect; documented)
**file:** test L562-608, L611-645, L648-672 · **severity: INFO**
`_floor_passthrough` replaces `BatteryStrategy._floor_reserve` on the class
(`monkeypatch.setattr(type(strat), ...)`). That removes the clamp from ALL 6
sites simultaneously, so on its own it could NOT detect a single site that
bypassed the helper. The builder's own docstring (L556-558) acknowledges this
and correctly defers per-site proof to the behavioral tests + the cycle
report. My real source mutations above supply the per-site proof the
monkeypatch cannot. Acceptable as written; flagged so future readers don't
over-trust the parametrized test as a per-site guarantee.

### C-INFO-2 — HOLD/CHARGE/attain no-op sites only detectable via pathological config
**file:** test L280, L324, L385, L428 · **severity: INFO**
Sites 1/2/4/5 clamp `_peak_buffer_target` (default 80), which under the
default floor (50) is a no-op (`max(80,50)=80`). The dedicated tests force
`_peak_buffer_target = 40` to make the clamp load-bearing. This is the CORRECT
way to exercise a guard whose default-config effect is a no-op — without it
the mutation would leave the suite green and the site would read as untested.
Confirmed the tests do this; coverage is real, not accidental.
