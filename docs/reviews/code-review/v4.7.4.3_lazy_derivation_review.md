## Findings

### CRITICAL-1: Reverted v4.7.4.2 dead-import fix (runtime breakage on HA 2026.5.4+)

**File:** `config_flow.py:5537-5543`
**Bug Class:** #46 extension / new (dead import reintroduction)
**Severity:** CRITICAL

The v4.7.4.3 commit reintroduced the `from homeassistant.components.selector import (selector, NumberSelector, ...)` block inside `async_step_zone_dynamic_preset`. v4.7.4.2 (commit c380668, on develop) explicitly deleted this import because:
1. HA 2026.5.4 moved selectors to `homeassistant.helpers.selector` -- the old path raises `ModuleNotFoundError`.
2. None of the 5 imported names are used in the function body. Verified by AST walk: `selector(`, `NumberSelector(`, `NumberSelectorConfig(`, `NumberSelectorMode.`, `BooleanSelector(` -- zero occurrences in `async_step_zone_dynamic_preset`.

**Root cause of regression:** The worktree branched from the merge of v4.7.4 (commit 7772b42), which includes v4.7.4.2's fix. But the builder's working copy of config_flow.py appears to have been based on the v4.7.4 source (pre-v4.7.4.2), so the diff undid the v4.7.4.2 fix.

**Impact:** Opening the Zone Dynamic Preset form on HA 2026.5.4+ will raise `ModuleNotFoundError` and show an empty error modal. The form is completely inaccessible.

**Action:** Delete the import block at lines 5537-5543 and replace with the v4.7.4.2 comment documenting why. Alternatively, simply delete the lines -- the comment is already in v4.7.4.2 on develop.
