## Tier-3 elevation rationale

The Optimization Coordinator is a shared decision-primitive: it emits findings, writes to `optimizer_findings`, dispatches NM digests, and (per this cycle) begins writing shadow-accuracy samples that will feed a future L2 auto-apply promotion. The failure mode this cycle guards against is **one missed write channel** silently re-flooding the DB — the exact shape of the v5.2.1 rollback incident. Standing policy: regression-prone shared primitive → Tier 3. Framings chosen (A/B/C/D) with the explicit requirement that D re-enumerate **the entire write-channel surface** including code that pre-dates this cycle.

## Falsifiable invariant (stated up front, per Tier-3 discipline)

> **Under any legal-config, reachable OC cycle, no more than 2 counted "finds-table batches" (tier-1 emit + LLM emit, each counted as one write-volume unit) shall land in the `optimizer_findings` / `ura_activity_log` / notification / shadow-sample / digest channels combined within a single OC cycle. When the tripwire latches, ALL five write channels must be suppressed until restart.**

Two caveats recorded with the invariant:
1. **Invariant wording is per-cycle, not per-finding.** L2 promotion (future) that emits `ura_activity_log` rows *per finding* would legitimately exceed 2/cycle at high finding counts — the threshold and unit must be re-tuned at promotion time. Cross-ref: optimizer-autonomy campaign backlog.
2. **Threshold arithmetic:** ceiling = 5 counted units/cycle × 12 cycles/hr × 2.5 safety = **150/hr** (up from the initial 60 in the plan; D-LOW-1 re-tune). Below 150 = normal; ≥150 = latch.

**Final status:** HELD across all four D clauses after fix-up. See D re-enumeration section.

## Recommendations for `docs/QUALITY_CONTEXT.md`

Two new candidate bug classes surfaced this cycle that recur strongly enough to warrant explicit naming:

1. **"Tripwire / telemetry blind to the channel it was built for."** Instrument the *dangerous* path, not the *convenient* one. If a tripwire is built to prevent a historical incident, verify by name that it counts and gates the *specific channel* implicated in that incident. B-HIGH-1 / D-HIGH-1 / D-HIGH-2 are all this class; the tripwire counted `optimizer_findings` (easy to instrument) and missed `ura_activity_log` (the actual v5.2.1 flood channel).

2. **"Partial state consumed as final."** A short-circuit or threshold evaluated against a *running* per-cycle count rather than the *fleet total* fires prematurely during fan-in. A-HIGH-1 is this class. Sibling to Bug Class #7 (stale data source) but distinct: the data isn't stale, it's incomplete-by-design and the consumer treats it as complete.

Both recur across cycles (channel-blind: v4.6.1.1 dispatch shape, v5.2.1 write flood, this cycle; partial-state: numerous per-room fan-in bugs). Naming them makes future planners state the channel-list and the completeness-condition up front.
