## Cleared (holds because)

- **INV-3 / `sensor_global_face` exclusion.** `_is_frigate_face_name_entry` requires `platform == "frigate"`, domain `sensor` and `unique_id.split(":")[1] == "sensor_recognized_face"` exactly (`camera_resolver.py` new predicate). `sensor_global_face` fails segment 1, and a non-string uid returns False. Disabled entities are skipped before the predicate runs (index loop, `disabled_by` guard at the top of the loop).
- **Device join and ordering.** The index is built in the single `_build_indices` pass (only caller is `__init__:560`, so there are no duplicate appends on rebuild). It is sorted bare first, then `_N`, then lexically, which reproduces the legacy bare-then-`_2` order.
- **Exact-stem rule and `_2` base equality.** `face_name_entities_for_stem` uses the raw stem only. A suffixed face sensor is returned only when its base equals the stem, so `garage_a_2` / `foo_2` style keys cannot reach `foo`'s sensor. A renamed sensor (base None) goes through the device. When the registry is empty, the fallback is the legacy built pair (`camera_census.py` S1 and S2), byte-identical apart from the counter increment.
- **Engine fallback (D4) and dedup.** `face_engine_tag` returns `_FACE_ENGINE_FAMILY[integ]` or the hint, so it never returns `""` or `"unknown"`. `_face_leg_engine` also falls back to the hint for a None, stub or non-string resolver. Truth table for one stem with the latch fresh:

  | entity leg | membership hit | synthetic engine | dedup |
  |---|---|---|---|
  | Frigate device → `frigate` | yes, copied | `frigate` (copied) | merges, n=1 |
  | device missing → hint `frigate` | yes | `frigate` | merges |
  | device first identifier non-Frigate (merged device) → e.g. `reolink` | no | `_reg_ids[0]` → same device → `reolink` | merges (label is display-only) |
  | no live entity leg | n/a | `frigate` | n=1, no duplicate |
  | different canonical slug | `_skip_synthetic` (pre-existing) | n/a | n/a |

  No path creates two Frigate legs with different engines for one physical camera, so the spurious 0.75 cannot occur. The `_has_f2` probe survives only on the empty-registry branch, where it picks the sentinel, never the engine.
- **INV-4 (S7 can only decrease).** `camera_census.py` S7 device-join branch: a None result (no face sensor, kill switch off, exception, or every candidate unusable via `_first_usable_face_entity`) does one `append((area_id, count))` and `continue`. That is the legacy value. Otherwise the code falls through to the shared freshness block: fresh gives `max(0, count-1)`, otherwise `count`, appended once only if > 0. In every case the contribution is ≤ legacy. Bare `_person_occupancy` cameras take the untouched `else` branch. `_device_derived_face_entity_id` catches the exceptions from the resolver call and from `_first_usable_face_entity`.
- **S5/S6 restructure.** The old `if None: continue` moved to `if face_sensor_id is not None` (S5) or kept as `continue` (S6). Bare-camera behaviour is unchanged.
- **Alias parsing.** `_norm_face_name` matches the canonicalizer's normalisation. Splitting on the first `=` handles a value with no `=` (warn once) and an empty key (never matches). The `person.` prefix is stripped after normalisation, case-insensitively. The alias runs after the direct tracked match and before the first-token match (it beats a fail-closed ambiguous head, per the plan). An empty list returns `""` before any work. `face_alias_person_slug` returns None for guest targets, so presence never builds `person.guest:*`.
