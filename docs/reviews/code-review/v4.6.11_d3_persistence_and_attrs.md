## Findings

### CRITICAL — fixed

**C1 — Listener leak in `SafetyEventsSummarySensor.async_will_remove_from_hass`**
*Bug class: #38 (lost unsubscribe).* Override did not call `super()`, leaving `AggregationEntity._agg_retry_unsub` (a 5s startup-retry timer) unsubscribed on entity removal. Fix: added `await super().async_will_remove_from_hass()` as the first line.

**C2 — Untracked `async_create_task` fired from synchronous property accessor**
*Bug class: #19 (untracked background tasks).* `native_value` (a `@property`) spawned a fire-and-forget refresh task on every cache-stale read with no reference, no re-entry guard, no teardown cancel. Multiple HA state reads against a stale cache could pile up overlapping DB queries. Fix: track `self._refresh_task`, guard against re-entry (`is None or done()`), cancel in teardown.

### HIGH — fixed

**A.H1 ≡ C.H3 — Read query routed through write queue**
*Bug class: #26 (high-frequency DB reads) + architectural.* `SafetyEventsSummarySensor._refresh_cache` used `db._db()` (the serialized write context manager) for a SELECT. With the 60s cache TTL, this would occupy a write queue slot once per minute, blocking real writes (`save_baselines`, `save_anomaly_event`, `activity_logger`). Fix: `_db()` → `_db_read()`.

### HIGH — deferred (logged)

**C.H1 — Test severity-rank key type diverges from production**
Test helpers in `test_v4_6_11_dashboard_attrs.py` use `_SEVERITY_RANK = {"nominal": 0, ...}` (string keys) while production at `manager.py` uses `{AnomalySeverity.NOMINAL: 0, ...}` (enum keys). `AnomalySeverity` is a `StrEnum`, so dict hash-equality currently aligns the two paths and the tests pass. The divergence is real but cosmetic for current behavior. **Deferred** to a test-infrastructure cleanup cycle — fixing requires either importing real `AnomalySeverity` into HA-free unit tests (non-trivial) or aligning helper logic line-for-line with production (risk of subtle test mutation). Acceptable risk for v4.6.11 because (a) tests currently exercise the equivalent path, (b) production code is verified separately by source-grep tests.

**C.H2 — Tests replicate production logic inline instead of driving production code paths**
Known limitation of HA-free unit testing. Reviewer C confirmed the `TestD1SimulatedRestart` gold-standard test does import and drive real `AnomalyDetector` for the highest-risk path (persistence). Source-grep tests cover structural presence. **Deferred** as test-infra debt — does not block this cycle.

### MEDIUM — fixed

**A.M1 — `active_count` bypassed suppressed-metric filter**
`manager.py:570` used raw `_active_anomalies` list while `get_worst_severity()` uses `_persisted_active_anomalies()`. This created an inconsistency where `status="nominal"` could ship alongside `active_anomalies>0`. Fix: call `det._persisted_active_anomalies()` with fallback to the raw list if the method isn't available.

**A.M2 / C.L4 — `_SEVERITY_RANK` rebuilt on every `get_summary()` call**
Hoisted to module-level `Final[dict[AnomalySeverity, int]]` constant. The pre-existing duplicate at `get_system_anomaly_status()` (lines 701-706 in baseline) now references the same module constant — also addresses A.L2 (duplicate mapping drift risk).

**A.M3 — `house_state` missing from CM anomaly payload**
Analytics queries grouping `anomaly_log` by `house_state` would have missed CM rows. `save_anomaly_event` DAO reads `payload_dict.get("house_state")` (database.py:4642). Fix: read `_house_state_machine.state` from CM, set on context dict before AnomalyEvent construction.

**B.M1 — CM `save_baselines` cadence divergence undocumented**
Reviewer B's pipeline trace confirmed cadence is intentionally different from peers (CM saves after every observation because setup_duration fires exactly once per boot; peers save at teardown). Without a comment, a future reviewer could "align" CM to the peer pattern and break the persistence guarantee. Fix: explanatory comment at the save_baselines call site.
