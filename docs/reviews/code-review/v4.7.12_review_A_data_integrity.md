## A1 (HIGH) — fresh vs upgrade column order divergence

**Fresh-install order:** `... resolution_notes, anomaly_type (col 16), event_class, recovery_at, correlation_id, entity_id, room_id, person_id`

**Upgrade-install order:** `... resolution_notes, event_class, recovery_at, correlation_id, entity_id, room_id, person_id, anomaly_type (col 22)`

Rebuild dance lands the upgrade order. The fresh CREATE TABLE at 685-702 was modified to add `anomaly_type` at the end of the BASE column list — but the v4.6.1 ALTER block (1226-1251) still adds 6 cols after it. This directly violates the planning doc §10 invariant: "Fresh-install CREATE TABLE produces a row layout identical to an upgrade-installed table."

No `SELECT *` consumers today, so not an immediate runtime bug; but v5.0 column drop will be more painful, and the Reviewer A checklist explicitly required this check.

**Fix (preferred):** Remove `anomaly_type` from the fresh CREATE TABLE at 685-702; let the v4.6.1 ALTER tuple list at L1241 add it last in both paths. Add `test_fresh_vs_upgrade_schema_column_order_identical` to lock the invariant.

## A2 (MEDIUM) — backfill rowcount clamp masks `-1`

Location: `database.py:1550`. The `if cursor.rowcount >= 0 else 0` clamp silently maps `-1` to `0`, indistinguishable from a normal empty-table backfill. On a real machine with thousands of historic rows, "0 rows backfilled" is the only signal something went wrong.

**Fix:** log WARNING if `cursor.rowcount < 0`.

## A3 (MEDIUM) — existing readers still on `event_class`

Locations:
- `sensor.py:11806-11811` — `RecentAnomaliesSensor` groups by `COALESCE(event_class, 'point_in_time')`
- `button.py:1143-1152` — diagnostic dump SELECTs `event_class`

Dual-write guarantees equality during the v4.7.12 window so these readers still work. But v5.0 drop has now extra surfaces to migrate. Convergent with C-M3 (which flags `cleanup_anomaly_log`).

**Fix (in-scope, cheap):** `SELECT COALESCE(anomaly_type, event_class, 'point_in_time')` in all three reader sites.

## A4 (LOW) — backfill exception handler

If backfill UPDATE fails, `user_version` is NOT set to 4712 (retry-safe), but every subsequent emit lands with `anomaly_type` defaulted to `'point_in_time'` and historic regime_shift rows continue to show `'point_in_time'`. WARNING level is insufficient.

**Fix:** promote to ERROR (or surface to diagnostics coordinator).

## A5 (LOW) — redundant PRAGMA `table_info` in v4.6.7 rebuild
