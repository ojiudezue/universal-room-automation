# Code Review — v5.12.0 Substrate Re-subscribe on Room Entry Lifecycle (Tier 2-DB)

**Cycle:** Restore pre-v4.7.24 per-room-onboarding guarantee — `OccupancySubstrate` re-subscribes when a ROOM `ConfigEntry` is added / removed / options-edited.
**Plan:** `docs/planning/PLANNING_substrate_resubscribe_on_room_add.md`
**Branch:** `feature/substrate-resubscribe-v5.12.0` · **Baseline tag:** `pre-review-v5.12.0`
**Build commit (pre-review):** `89db3247` · **Fix-up commit:** `88c1acea`
**Reviews:** 3 framing-disjoint (A local-correctness / B integration + lifecycle + race / C test-authority-via-mutation + adversarial completeness) + validator + focused re-review. **Final verdict: SHIP.**
**Date:** 2026-07-10

## Framing

This is a **regression fix**, not new capability. Commit `e165e1cb` (v4.7.24 substrate unification, 2026-06-05) centralized per-room `async_track_state_change_event` subscriptions into the substrate constructed once at `PresenceCoordinator.async_setup` — and as an unintentional side effect **lost the per-entry lifecycle hook**. Every ROOM entry in the house predated the substrate cycle, so the regression stayed invisible for 34 days until "Master Bath Toilet" was onboarded 2026-07-09 08:23 without a restart and rode the ~34s room-coordinator poll (median raw-motion → light ~11s, worst 34s) instead of latching event-driven in <3s. The acceptance bar for this cycle is exactly the pre-June-5 behavior: **a room added without restart is event-driven from ROOM setup.**

## Falsifiable invariant (per plan)

*After any ROOM `ConfigEntry` transitions to LOADED, UNLOADED, or has its options updated, the `OccupancySubstrate` subscription set equals the union of `CONF_MOTION_SENSORS ∪ CONF_MMWAVE_SENSORS ∪ CONF_OCCUPANCY_SENSORS` across all currently-LOADED ROOM entries — with no observable dispatch gap and no double-dispatch during swap — without requiring an HA restart.*

Reviewer C (adversarial completeness) was tasked with falsifying exactly that.

## Bug-class frequency + recommendations

- **Centralized-subscription-loses-per-entry-lifecycle-hook** — 1 (the parent regression itself, v4.7.24 → v5.12.0). **Recommend QUALITY_CONTEXT.md gain a new bug class:** when centralizing a primitive out of a per-entry setup path, the entry lifecycle hooks the old path silently satisfied must be re-listed and re-attached explicitly. A one-line audit rule ("what did the OLD per-entry path provide that the NEW centralized path does not?") would have caught this at the v4.7.24 review.
- **Test injects state production never writes** — 3 (C-HIGH-1/2/3 all failed the mutation-red/green bar because the tests wrote to seams production never uses). **Recommend a companion bug class:** any test whose failure requires production to write to a test-owned seam is a stub-mirror; the mutation-anchored rewrite pattern used here (drive real HA dispatcher through real substrate) is the fix.

- **Bug Class #38 teardown race → zombie listener** — 1 (B-HIGH-1).
