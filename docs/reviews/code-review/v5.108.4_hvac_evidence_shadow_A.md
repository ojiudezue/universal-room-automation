## Cleared (holds because)

- **DDL / idempotent create:** `CREATE TABLE IF NOT EXISTS` and `CREATE INDEX IF NOT EXISTS idx_hvac_ev_shadow_ts` sit inside `_create_table_safe` (`database.py:1367-1387`), in the same per-boot init block as `optimizer_shadow_samples`. On an existing DB the first boot creates the table and later boots no-op. A failure is isolated: it is appended to `failed_tables` and rolled back, and other tables are unaffected. No ALTER, no schema-version gate, no touch on any existing table.
- **Write path:** the write goes through `self._db()`, which IS the `_write_queue` producer (`database.py:580-699`: enqueue `(_execute, future)` onto the single serialized worker). It bypasses ActivityLogger, but not the queue. Each drain is one queue item, one `executemany` and one commit (`database.py:7746-7756`), with no per-row writes. Rows missing any of the 4 NOT NULL fields are skipped before SQL. An empty batch makes no queue item (`hvac.py:5244` returns early, and the DAO returns 0).
- **Task tracking:** `_drain_hvac_evidence_shadow_rows` creates the task through `_track_task` → `_pending_tasks` (`hvac.py:2033-2040`), which `async_teardown` cancels (`hvac.py:8495-8497`). The decision path never awaits it. The coroutine duck-check prevents a MagicMock DB from leaking a coroutine.
- **Drain placement:** the drain follows each of the 3 `update_room_conditions` callers (boot `:1582`, tick `:2341`, fast run `:6001`). The daily reset (`:2298`, exposure flush) runs earlier in the same `_run_decision_cycle`, so exposure rows drain on that same tick.
- **Prune:** `WHERE timestamp < cutoff` (older than the window) is the correct direction. Batches of 1000 by rowid subselect, a 500-batch cap and 0.1 s sleeps give one queue item per batch, so the prune does not monopolise the writer. The window is clamped to ≥ 1. It is registered in `nightly_cleanup_ops` (`nightly_maintenance.py:57-59`) with `{}` kwargs, and the runner calls `getattr(db, name)(**{})`, which uses the 180-day default. Both timestamp sides are UTC `isoformat()` (`+00:00`), so the lexical compare is sound. The timestamp index covers both the prune and the verdict's `timestamp >= :since`.
- **Write volume:** episode rows are capped at 96 per zone per day plus 1 `capped` row (3 zones → ≤ 291/day). Exposure is ≤ zones × states per day. A drain happens only when rows exist, so the expected rate is a few batches per hour, which does not threaten `_write_queue` health (contrast the 2026-06-09 per-cycle flood).
- **Verdict SQL vs DDL:** every column it reads exists (`row_type`, `timestamp`, `house_state`, `kind`, `outcome`, `duration_s`, `opened_s_after_boot`, `details_json`). The JSON keys `refresh_failed_rooms` and `pending_rooms` are always written (`hvac_zones.py` `_ev_shadow_finish`). Boolean `SUM(expr)` and two-argument scalar `MAX` are valid SQLite. `premature / occ_zone_h` is INT/REAL, so it is real division, and `occ_zone_h > 0` is guaranteed because exposure rows are written only when secs > 0. `ref_rate` uses `* 1.0` with `NULLIF`.
- **Untouched surfaces:** the diff adds no `ActivityLogger` call, no `ura_activity_log` write, no dispatcher signal and no `ura_action` bus event, and it does not touch the last-activity sensor. No existing table, index, DAO or reader changed (`database.py` diff is purely additive: the DDL block and two new methods).
