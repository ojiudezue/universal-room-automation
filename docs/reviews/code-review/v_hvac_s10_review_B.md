## Cleared (holds because)

1. **Observer cadence and noise:** `update_zone_climate_state` is called only from the boot refresh (`hvac.py:1562`), every full tick via `update_all_zones` (`:2315`), zone fast runs (`:5904`, limited to 60 s per zone) and the pre-arrival end (`:7318`). There is NO state listener. A stamp needs the readable `(preset_mode, hold_activity)` pair to differ between two reads, so attribute-only refreshes (temperature, humidity, `hvac_action`) never stamp. `unavailable` returns early without touching prev (`hvac_zones.py:673`). `unknown` maps to `""` and counts as unreadable.
   - **Nudge:** a 2-min `manual` every ~25 min gives at most 2 stamps, then a gap of 20 min or more, so the episode releases. Nudges alone never chain to 4 h.
   - **Zone_2 Bryant schedule:** 4 transitions a day, about 10-15 min held each.
   - **Zone_1 §9.9:** held for the whole split. That is intended, but see B-M1 and B-M2.
   - Fast runs sample more often. That can add stamps on a flapping zone but never creates one on a steady zone.
2. **Carrier `none` hold:** `ha_carrier/climate.py:261-269` publishes None for no hold, and `:432` sets `hold_activity` optimistically on `set_preset_mode`. So none → away → none from S1, S11, the arrester or a resume stamps on the next observation, as intended. S10's own `set_activity_setpoint` places no hold and changes no activity, so there is no self-stamp feedback loop. A Carrier reload goes `unavailable` (skipped), and the recovery read can add one extra stamp at most: one more ≤ 600 s deferral, which is benign and arguably correct after a reload.
3. **Lifecycle:** `ZoneState` is built only in `async_discover_zones` at setup (`_handle_zm_zones_updated` does not rediscover). The observer runs for every zone regardless of rollout, so a zone added mid-episode honours its live stamp, and a zone removed has its latch pruned (A-L2). The trip-wire runs once per full tick, after switch resolution, inside try/except. The ledger write goes through `_track_task`, so no untracked task. Gating the switch-OFF restore pass only delays restore while the pair keeps changing; in steady state it proceeds 10-15 min after the last change.
4. **Byte-identical no-op path:** on a non-rollout zone without a snapshot, `_s10_pass` `continue`s before `_s10_zone_skip_reason` (`:4555-4562`). The observer touches only the 4 new RAM fields. On ecobee/Generic the `hold_activity` attribute is absent, so the observation is `""`, unreadable, and the gate is inert. Rollout empty means the trip-wire returns early.
5. **Failures reset vs the latch/NM path:** the `latched` early return (`:4676`) precedes both callers of `_s10_success`, so the reset can never unlatch. APPLIED is untouched (ruling A4). `emit_raised` still counts toward the latch.
6. **Trip-wire flood:** at most once per zone per LOCAL day (A-L1). The latch clears on release, on a missing zone and on rollout removal. It cannot false-fire after a restart (RAM reset, seed without stamp).
