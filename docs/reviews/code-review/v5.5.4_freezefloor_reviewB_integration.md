## Item 2 — No fight with the v5.5.2 heat_cool enforcer ✅
The clamp acts only on `resolved.cool_low` → `emit_low` (`hvac.py:1517`) and writes `target_temp_low`/`target_temp_high` via `set_temperature` (`hvac.py:1531-1540`). It **never calls `set_hvac_mode`** and never changes the zone's mode. The enforcer (`hvac.py:1066-1094`) only writes `set_hvac_mode=heat_cool` when `zone.hvac_mode != "heat_cool"`. Since the clamp keeps the zone in heat_cool, the enforcer's guard is False → nothing to revert. The enforcer's design note (`hvac.py:1060-1065`) confirms single-mode `heat` was the thing it reverted; removing that emitter eliminates the documented conflict. ✅ No oscillation path.

## Item 3 — No fight with egress / AC-reset / away ✅
- **Egress:** the apply loop skips egress-paused zones with `continue` at `hvac.py:1488-1492`, which is positioned **before** the clamp at `hvac.py:1517`. A freeze clamp therefore cannot write `set_temperature` to an egress-paused `off` zone. ✅ (The enforcer loop has the same egress skip at `hvac.py:1067`.)
- **AC-reset:** AC-reset is honored only by the enforcer (`has_active_ac_reset`, `hvac.py:1072`). The apply path doesn't special-case AC-reset, but AC-reset sets mode `off` outside this writer; the clamp only adjusts the low bound of the next normal `set_temperature` — no new oscillation introduced vs. pre-fix behavior.
- **away/vacation:** `SEASONAL_DEFAULTS` (`hvac_const.py:367-389`) lows are 58–62 (summer away 60, winter away 60, shoulder away 62, all vacation 58) — all ≥ `FREEZE_FLOOR=50` → `_apply_freeze_floor` returns input unchanged → **no-op** for standard presets. ✅ Clamp only bites a custom/edge preset below 50, exactly as specified.
- **No oscillating-writer pair found.** The clamp can only *raise* `emit_low`; the idempotent throttle (`hvac.py:1521-1524`) caches `(emit_low, emit_high)` so a steady freeze writes once. No other writer lowers `target_temp_low` back below the floor while freeze is active.

## Item 4 — Fail-open ✅
- Missing outdoor temp: `_get_best_outdoor_temp` (`hvac.py:1376-1392`) returns `None` if predictor absent, read raises (caught, `noqa BLE001`), or `predictor._get_outdoor_temp()` returns None. The real `_get_outdoor_temp` (`hvac_predict.py:1096-1106`) returns None on no-entity / `unavailable` / `unknown` / non-float — robust.
- `_update_freeze_active` (`hvac.py:1407-1416`): `temp is None` → `self._freeze_active = False` (never holds a fabricated freeze). No crash path; the whole read is try-wrapped.
- Freeze inactive → `_apply_freeze_floor` returns `cool_low` unchanged → normal presets. ✅

## Item 5 — Restart resilience ✅
`_freeze_active` is RAM-only (`hvac.py:236`, init `False`), explicitly **not** RestoreEntity (comment cites Bug Class #52 unavailable-coercion avoidance — correct call). On the first post-boot `_async_apply_preset_overrides`, `_update_freeze_active()` runs (`hvac.py:1474`) before any zone resolves and re-derives from the live outdoor reading. Worst case at boot: outdoor sensor is briefly `unknown` → `_get_outdoor_temp` returns None → freeze treated inactive for that cycle → no wrong clamp; it arms on the next cycle once the reading is live. There is **no boot window where it wrongly clamps** (clamp requires a live ≤35 reading) and the only "wrongly fails to clamp" window is the sensor-warmup gap, which is inherent and bounded by the decision cycle — acceptable, and a freeze persists in the outdoor reading so it self-corrects. ✅
