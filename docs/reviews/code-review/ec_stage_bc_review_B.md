## Cleared (holds because …)

- **WPM timer lifecycle.** The unsub is appended to `_unsub_handles` (`weather_manager.py:239`). The first refresh and every timer refresh go through `_pending_refresh_tasks` with a discard callback (`:815-829`). `async_teardown` unsubs, then cancels and gathers the tasks (`:245-257`). The integration unload pops and tears down the WPM (`__init__.py:5907-5910`), and a CM reload constructs a fresh one (`:3782`). The boot path is not blocked: the first refresh is a task, not awaited. Both refresh paths take the WPM-C1 lock (`:441`, `:835`).
- **never_fetched vs stale.** `hourly_outlook` returns None for providers with no `_hourly` entry, a stale `fetched_at` (> `FORECAST_STALE_MIN`), or an unavailable state, and None means a no-op in fusion. Covered by `test_forecast_first_tick_never_fetched` and `test_forecast_timer_torn_down`. The residual boot gap is B-MED-1.
- **Per-tick hooks.** `_inclement_rows_tick`, `_storm_guard_tick` and `_grid_buy_notify_tick` are synchronous, each wrapped in its own try/except, and placed after `determine_mode` and before the first await (`energy.py:6453-6460`), alongside `_outage_ledger_tick`. An exception cannot reach the decision cycle, and an early return in `determine_mode` (grid disconnect, blind) still runs them. NM and anomaly sends use `async_create_task`. They are fire-and-forget on the same pattern as existing EC NMs.
- **Per-tick entry reset.** `_tick_grid_buy` / `_tick_preonset_engaged_id` are reset at the top of `determine_mode` (`energy_battery.py:5916-5917`), before any early return.
- **Storm Guard boot/restart.** The first readable value seeds (`prev is None`). `on` at boot is log-only. unavailable/unknown leave `_storm_guard_last` untouched, so an on→unavailable→on sequence does not re-fire. A CM rebuild re-seeds and does not re-fire.
- **Precedence.** The pre-onset leg yields to arbitrage CHARGE and attain charging (`energy_battery.py:6350-6351`). A full_hold returns before the prepare fields (`inclement.py:981`), so it shadows the leg. The latch advances leg-independently. Leaving the bottom rate drops `pre` and the TOU branch takes over (CFG off); returning to the bottom rate with `"engaged"` resumes without the solar test (by design). At Onset the alert leaves the prepare set and the latch key is deleted (`inclement.py:948-951`), so the warn ladder governs. A continued buy there is a new (zone, id) episode, which is one NM by the spec's key definition. Polygon cap is stateless (§D-B2a), so it has no restart surface.
- **Stage A no-op path.** With `INCLEMENT_PREONSET_LEAD_H=0` the prepare set is empty and `_apply_prepare` returns `base` unchanged (`inclement.py:952-953`). With the option False, `_grid_precharge_on_hold` short-circuits every buy gate. The floor-only prepare raise is the specified D-B6 behaviour, not a regression. The goldens test pins this.
- **Number + options apply.** `InclementPreonsetFloorNumber` writes only `entry.options[inclement_preonset_floor]`. The key is in both `_NO_LIVE_ATTR_KEYS` and `OPTIONS_RELOAD_SUPPRESS_KEYS` (`__init__.py:7457`, `:7500`), so changing it does not reload the CM, and `_inclement_config()` re-reads it every tick. The blind slider's unique_id is unchanged after the refactor (`_uid_suffix` keeps the literal). Registered once (smoke test `test_number_platform_registers_inclement_preonset_floor` passes).
- **Legacy threat-list repair.** `_check_legacy_threat_list` is idempotent (`async_create_issue` keyed) and never writes options. Restoring the default does not delete the issue (cosmetic; not filed).
- **envoy_available reset at the pre-onset site:** fixed correctly (`energy_battery.py:6388-6392`). The full-hold site is B-LOW-2.
