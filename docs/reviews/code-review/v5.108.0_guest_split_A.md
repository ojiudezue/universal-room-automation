## Focus areas cleared (holds because)

- **Night-fraction arithmetic** (`database.py` new fn): episodes are clipped per window, and the denominator is real elapsed time from the tz-aware bounds, so DST nights are 7 h or 9 h. Resident cuts are applied one after another, so overlapping cuts are idempotent. Paired episodes never overlap, so the sum cannot double-count. A zero-length window returns 0.0, with no division by zero. Room choice is the max fraction, and a night qualifies if ANY room qualifies (`presence.py` `best` loop).
- **Clocks**: occupancy bounds go through `_naive_utc`, and `_occupied_episodes_between` compares naive UTC strings. `person_visits` bounds use `datetime.fromtimestamp(ts)` (naive process-local) and rows use `naive.timestamp()`; these are exact inverses on any host TZ, and both are pinned by the `_utc_host` / `_local_host` tests. The one-day string margin covers both the `' '` and `'T'` separators: `'T' > ' '` only widens the lower bound, and the upper bound is past every window. `_run_inference` passes `now = dt_util.now()`, which is local and aware, to both `_is_sleep_hour(now.hour)` and `_guest_stay_tick`, so the windows and the night yield use local wall-clock time.
- **Night windows**: `guest_night_window` handles both wrapping (22→6) and non-wrapping (1→6) windows. `guest_last_completed_night` steps back one day while the window end is after now; the boundary is pinned by `test_window_end_boundary`. The walk uses the same `engine.sleep_start/end_hour` as `_is_sleep_hour`, so it is consistent with the night yield.
- **Latch entry and exit**: the walk starts False and turns on at q ≥ K over the last L nights, off at q = 0 (L straight misses). `since` is the window end of the night that turned it on. K is clamped to 1..L and L to at least 1 (`_guest_stay_params`).
- **35-night replay and trip-wire boundary**: replay is clamped to `max(R, L, D + L)`, which gives 35 here. The span is R + L − 1 = 37 nights, and the first evaluated index is L − 1. A stay longer than the walk keeps getting `since` re-dated to about 35 days ago, which is more than 28, so D4 still fires. The firing test is strict `>`. `0` disables it. Pinned by `test_replay_clamp` and `test_fires_on_stay_longer_than_bound`.
- **Composition and no flap**: HOME_* with the latch on during sleep hours cannot enter GUEST, because `infer()` checks sleep hours (`presence.py:1404`) before guest entry (`:1425`). In GUEST at a sleep hour, compose returns False, the GUEST exit (`:1399`) proposes HOME_NIGHT, and then SLEEP follows. There is no HOME_NIGHT↔GUEST oscillation. With the rule OFF the result is `room` (golden byte-identical fixture).
- **visitors_present legs**: `room` and `cam` are False outside HOME_*/GUEST, because the existing else-branch forces them. `cam` is forced False in GUEST, which is harmless because the GUEST state alone turns the sensor on. The stay leg is `rule and latch and switch`. Both gates are already masked by the Guest Detection switch (`presence.py:6268`, `:6330`), so switch OFF means the sensor follows GUEST only, as documented. `since` resets on off.
- **None / empty DB**: no database means no scheduling and no walk, and the tick retries. No guest rooms means `per_room` is empty, the latch stays False, and the day is evaluated. No windows returns `[]`. Unparseable visit rows are skipped. Teardown cancels the task, and `CancelledError` is not swallowed by `except Exception`.
