## Cleared (holds because…)

- **D5 and D10.5 in-flight key.** There is no `await` between the in-flight check (pa.py:1342) and the gate's
  `_dispatch_in_flight.add` (D5 ~4639, D10.5 ~4941 and ~4957). D3, severity, linker and burst are all synchronous, so a
  sibling edge always sees the key. Every exit releases it:
  - timer fires: the key is kept through `_async_finish_perimeter_dispatch`, re-added at :1762 (idempotent), then
    released in `_do_dispatch`'s `finally` (:1865);
  - teardown: the future is resolved (:1217-1227), `_active=False` makes the wait return False, and the key is
    discarded (:4530-4532 and :1535-1536);
  - `is_stopping`: same path as teardown;
  - BaseException inside the hold: discarded at :4528;
  - NM absent: discarded at :1701;
  - an exception in finish: discarded at :1547-1549.

  Teardown also clears the set at :1211. Vehicles use the separate `_vehicle_in_flight`, so there is no cross-release.
  No new task is created: the hold is a future plus a tracked timer, and the handler task is HA-tracked as before.
  A second edge during the hold makes exactly one notify, and its `_record_leg_fire` still runs at the edge (:4158),
  so corroboration stays visible.
- **D5 persistence.** Saves go through `async_delay_save(..., 30)` and only fire when finalisation changed something,
  so the write rate is at most one per 30 s. Restore runs in setup. A corrupt file (load raises) leaves
  `load_ok=False`, and malformed data makes `load_dict` return False. Either way the tracker starts empty: 0 samples,
  not eligible, which fails open. The agreement timer only reschedules while `_active` and is unsubscribed at teardown.
- **D10 egress and H5.** Perimeter-only cameras still read the global `_last_egress_time` (`_egress_stamp_for`), so
  they behave exactly as before. Egress sensors go through the same `_append_sensor` (:517-529), so a per-camera stamp
  is keyed by the camera entity. Egress-only cameras (garage_a_2/b_2) therefore still suppress dual-role cameras. A
  dual-role camera ignores stamps from itself and from co-viewing dual-role cameras, including its own zone-excluded
  camera-level leg, which stays subscribed for egress and maps to the same camera.
- **D7.** The first-wins digest chain now falls through to iMessage when WhatsApp returns False. The selected-set path
  matches the plan (no fallthrough). The three "ignore" sites add no rows. `per_person_fired` is now built from what
  actually fired for each recipient. `_update_channel_health` has no send path, so there is no recursion. A `wa_bridge`
  entry that is not loaded either does not register the service (falls back to `whatsapp`, which raises and returns
  False) or is caught as `entry_not_loaded`.
- **Suppress-set keys.** All four keys are read fresh through `_get_integration_config()` (pa.py:5017-5021) on every
  alert. A repo-wide grep finds no other consumer, so no cached reader is missed. `CONF_PERIMETER_ZONE_SENSORS`,
  `CONF_PERIMETER_CAMERAS` and `CONF_EGRESS_CAMERAS` stay off the set (the reload path, since D11 is not built). The
  config-flow pop stops an untouched empty zone list from adding a new key and turning a suppressed save into a
  reload. `PerimeterVlmGateSelect` inherits `ChatterModeSelect.async_select_option`, which writes `self._conf_key`, so
  it writes the right key.
- **Unload and reload.** `__init__.py:3480` creates a new manager per setup. Teardown releases the identity listener,
  the agreement timer and every pending hold. The `frigate_events` and linker-ready listeners are unchanged.
- **XCORR, linker, digest.** `nvr_family` gives the same result as before for today's frigate2 + protect legs. D5
  only acts on a camera's first alert in the window (its own count, H2), and burst acts on the second and later, so
  they never demote the same alert. Burst's `_last_burst_decision` is untouched. The linker call signature matches
  (exterior_track_linker.py:925).
