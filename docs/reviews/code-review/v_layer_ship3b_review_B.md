## Cleared (holds because)

- **No-op path, one-camera devices.** With device level on, `_key_reading` iterates `(cam,)` and `member_reading` maps unknown / restored to None, exactly the old `camera_state` no-opinion branch. The live value and the clear branch are unchanged, and `camera_is_dead` / `camera_hold_expired` fold over `_key_members` = `{cam: (cam,)}`. `_ensure_resolution`'s cache key includes the device-level flag. With every 3b knob off, `build_twin_map` returns `{}`, `page_camera_key` = own camera, `room_page_policy` = PAGE, scope is empty and `house_tracker_for` is None. The owner tick still computes sets and runs the house tracker's `evaluate`, with its answers gated and its pages discarded. That changes no outcome.
- **Room/owner double dispatch.** Rooms suppress pages and recoveries for in-map devices. The owner pages only groups in scope: Wr ∪ U, computed from the same `room_stream_input_entities` as the room watch (area via `CONF_AREA_ID` on both sides, `coordinator.py:3446-3452`). Owner S1 keys `("<group>", key)` never collide with room keys. Adoption runs via `_any_latched` on every successful rebuild (`_adoption_sweep_due`) and at first sets-ready. Midnight: `ALREADY_SENT` = in `_STUCK_SIGNAL_NOTIFIED` (any date), and owner HIGH latches are per episode, not per day. A CM reload drops the owner's MEDIUM state, but the re-send reads ALREADY_SENT, so no duplicate.
- **Debounce / teardown.** One `async_call_later` handle; `_queue_event` and `_on_debounce` check `torn_down` first. Teardown cancels the handle, unsubscribes both bus listeners and the interval, cancels tracked tasks and pops the data key only if it is `self`. Setup tears down any previous owner. The teardown sits in the CM branch of `async_unload_entry` before `async_unload_platforms`.
- **Untracked tasks.** Owner sends and recoveries go through `_track` (task set + done callback). The room sends keep the pre-existing `untracked-ok` pattern.
- **Latch after send.** S1 and S2 latches are set only in `mark_paged` (SENT / ALREADY_SENT). `_inflight` blocks a second send while one is pending. `today` is the same local date on both sides (`now.date()` in `evaluate` and in the coordinator).
- **Restart.** Owner state is RAM. `_lost` admits a never-real device only after `CAMERA_TWIN_BOOT_SETTLE_S` from `_setup_at`. A group still dead after a restart pages once more (accepted in plan §6.6).
- **Cross-coordinator.** The house fallback is consulted only when the room fold is None and only for U ∪ sticky. Tier-1 inputs are room-watched, so the G7 ledger anchor's per-input view and the empty-house anchor are unchanged. A future multi-camera Tier-1 input could only add a hold, which blocks the anchor (safe direction). D6 Source 3 now skips a dead foyer camera via the house tracker (intended; it lets D6 release). Zone tier and census get the device-level hold up to 900 s (the named, operator-accepted cost). The fan veto only skips. No reader takes a twin's reading, and `physical_camera_dead` is read only by pages and diagnostics.
- **Owner not in the room fold.** The private attribute is `_unwatched_tracker`, not `_camera_stream_health`.

## Note

The `map_ready` deferral (`deferral_active`) cannot be reached in production, because `async_setup` builds the map synchronously before the owner is visible to the rooms. It is harmless. B-M1 is the real "owner present, not ready" window.
