# v4.5.13.1 — HVAC Zone Dedup Hotfix — Code Review

**Date:** 2026-05-12
**Tier:** 1 (hotfix — single staff-engineer review per CLAUDE.md)
**Type:** Surgical fix for v4.5.12 zone duplication bug found in live validation

## What changed

Single architectural change: a shared helper `iter_canonical_hvac_zones(hass)` in `domain_coordinators/hvac_zones.py` replaces three independent zone-iteration loops in `sensor.py`, `button.py`, and `number.py`. The helper mirrors `ZoneManager.async_discover_zones` dedup semantics in a sync, side-effect-free form usable during platform setup.

## Context — the bug

User's install: 4 home zones, but only 3 physical HVAC zones (Entertainment + Master Suite share `climate.thermostat_bryant_wifi_studyb_zone_1`). v4.5.12 created 4 sets of D7 sensors (duplicating the shared zone), and the phantom `Zone 4 Status` sensor displayed `unknown` because it referenced a ZoneManager zone that never existed. button.py + number.py had local dedup helpers but used a different zone_id derivation than ZoneManager, creating cross-platform unique_id drift.

### Behavior assertions (mental execution)

**Helper dedup walkthrough for user's 4-zone install:**
1. "Back Hallway" → thermostat `climate.back_hallway_zone_3` not seen. `_zone_id_from_thermostat_pure` matches `zone_3`. Added.
2. "Entertainment" → thermostat `...studyb_zone_1` not seen. Matches `zone_1`. Added.
3. "Master Suite" → same thermostat — merge into existing. zone_name becomes "Entertainment + Master Suite".
4. "Upstairs" → thermostat `...up_hallway_zone_2`. Matches `zone_2`. Added.

Result: 3 canonical zones. Matches ZoneManager runtime. Confirmed by `test_helper_user_canonical_3_zone_install`.

**Zone_id alignment across 4 sites for `climate.thermostat_bryant_wifi_studyb_zone_1`:**
- ZoneManager.async_discover_zones → `zone_1`
- sensor.py D7 setup → `zone_1` → unique_id `ura_hvac_ac_ramp_state_zone_1`
- button.py force/cancel/clear-lockout → `zone_1` → unique_id `ura_hvac_ac_ramp_force_nudge_zone_1`
- number.py kwh_threshold slider → `zone_1` → unique_id `ura_hvac_ac_kwh_threshold_zone_1`

All 4 surfaces converge. Cross-platform consistency achieved.

**Edge cases mentally executed:**
- Empty config → `[]`
- ZM entry with no zones → `[]`
- Zone without thermostat → skipped
- 5+ home zones sharing 1 thermostat → merge into 1 with chained name
- Two distinct thermostats with same `_zone_N` suffix → collision falls through to auto-numbering

**Platform setup ordering:** `hass.config_entries.async_entries(DOMAIN)` is safe at platform setup time. Zone Manager entries exist when CM forwards platforms. If a ZM entry is mid-creation (impossible at the platform-setup call site), helper returns `[]` — same observable result as v4.5.12's broken path.
