## The two CRITICALs

### CRIT-1 — the allowlist install was DEAD CODE (found by Reviews A and B independently)

`set_allowed_cameras` had exactly one caller — `perimeter_alert.py:385`, inside
`PerimeterAlertManager.async_setup()`, guarded by `hass.data[DOMAIN].get("exterior_track_linker")`.
But `__init__.py` awaits that setup at line 2414 and only registers the linker at line 2451.
**The guard always evaluated None; the install never ran on any boot.** `SIGNAL_EXTERIOR_LINKER_READY`
was dispatched but `PerimeterAlertManager` never subscribed (only `switch.py:5705` did).

Two consequences:
1. **This — not the fail-open branch — is the true root cause of SECC-1.** The orchestrator's original
   diagnosis stopped one "why" short: observed `ignored_offlist_events` empty + interior tracks and
   concluded "the allowlist admits them" rather than asking why the allowlist was *empty*.
2. **The initially-built fix would have been far worse than the bug.** Fail-closed against a
   never-installed allowlist flips "admit everything" into "reject everything" — exterior tracking
   silently dead house-wide on every restart, unrecoverable without a parent reload (itself banned).

**Fix:** subscribe to `SIGNAL_EXTERIOR_LINKER_READY` and install there (unsub tracked); WARN instead
of silently no-oping when the linker is absent; add `_allowlist_installed` so the linker keeps the
**pre-fix admit-all behavior during the bootstrap window** and only fails closed *after* a successful
install — chosen over reordering setup because it cannot drop a real perimeter event; plus a
boot-sanity WARNING if perimeter cameras are configured but the allowlist ends up empty.

### CRIT-2 — two tests were silently not running (Review C)

A re-indent left `test_max_age_sunsets` and `test_restart_leaves_off` as **inner functions** of another
test, so pytest never collected them. `test_restart_leaves_off` was the only test pinning post-restart
arrester state — the exact area under active discussion. Verified: 0 collections before, 3 after.

## Bug classes for QUALITY_CONTEXT.md

1. **Silent no-op guard across setup ordering** — `hass.data[DOMAIN].get(<sibling>)` inside
   `async_setup` with no READY-signal fallback and no log on the None branch. The install looked
   correct in review for months. *Rule: any sibling lookup in setup must either be ordering-verified
   or paired with a READY subscriber, and must never fail silently.*
2. **Fail-closed without a wire-up guarantee** — hardening a gate whose configuration path is broken
   converts a leak into a total outage. *Rule: before flipping a default to deny, prove the allow-list
   is actually populated at runtime.*
3. **Tautological test oracle** — deriving the expected value from the production expression under
   test. *Rule: the oracle must be independently authored; drill it by perturbing the input domain
   (add a vocabulary member), not just the production site.*
4. **Hollow source anchors** — grep-for-string tests that survive the behavior being removed.
   Recurred here *inside the fix for it*, which argues for treating it as a standing review item.
