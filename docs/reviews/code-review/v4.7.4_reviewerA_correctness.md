## Bug Findings

### HIGH-1: Surface 2 `customize_buckets` read from wrong scope (Bug Class #2 adjacent)

**File:** `config_flow.py:5625`
**Severity:** HIGH

`CONF_ZONE_DYNAMIC_PRESET_CUSTOMIZE_BUCKETS` is defined **inside** the `customize_buckets_section` section in the schema builder (`_build_dynamic_preset_schema`, line 5768-5771). When HA delivers section data as a nested dict (modern HA behavior), this key will be inside `_buckets_raw`, NOT in `user_input` directly.

However, the read at line 5625 is:
```python
customize_buckets = bool(user_input.get(CONF_ZONE_DYNAMIC_PRESET_CUSTOMIZE_BUCKETS, False))
```

In the nested delivery case, `user_input` will not contain this key. The read will always return `False`, meaning:
1. Validation via `_validate_dynamic_preset_input` is **skipped** even when the user has checked `customize_buckets=True`
2. Invalid bucket ranges (e.g., `cool_low > cool_high`) pass without error

**Impact:** Users can save invalid per-bucket configurations without form validation catching the error. The invalid values are still saved (the save path correctly extracts from `_buckets_raw`), but the deadband check is bypassed.

**Fix:** Read `customize_buckets` from `_buckets_raw` with fallback:
```python
customize_buckets = bool(
    _buckets_raw.get(CONF_ZONE_DYNAMIC_PRESET_CUSTOMIZE_BUCKETS,
                     user_input.get(CONF_ZONE_DYNAMIC_PRESET_CUSTOMIZE_BUCKETS, False))
)
```

### MEDIUM-1: Dead code `_ALL_BASELINE_CONFS` in `async_step_hvac_baseline_presets`

**File:** `config_flow.py:4000-4001`
**Severity:** MEDIUM

```python
_ALL_BASELINE_CONFS = [ck for rows in (_SUMMER_ROWS, _SHOULDER_ROWS, _WINTER_ROWS)
                       for ck, hk, _c, _h in rows for ck in (ck, hk)]
```

This variable is defined but **never referenced**. The actual reset logic in `async_step_hvac_baseline_presets_reset_confirm` re-imports and re-lists all 24 CONFs independently.

**Impact:** No runtime impact. Misleads future developers into thinking the list is consumed somewhere.

**Fix:** Delete lines 3999-4001.

### MEDIUM-2: `CONF_SLEEP_ENABLED` read in wrong scope in Surface 2 (same pattern as HIGH-1)

**File:** `config_flow.py:5625` (save path interaction)
**Severity:** MEDIUM

`CONF_SLEEP_ENABLED` was moved into the `sleep_section` in the D3 schema builder (line 5804-5806). The `_validate_dynamic_preset_input` helper reads `CONF_SLEEP_ENABLED` from its input dict. When `customize_buckets=True` and validation runs, the flat dict at line 5628 only merges `_buckets_raw`, not `_sleep_raw`. If `CONF_SLEEP_ENABLED` is nested under `sleep_section`, the validator will read `False` and skip sleep validation even when the user has enabled sleep ranges.

**Impact:** Invalid sleep-preset ranges pass validation when both `customize_buckets=True` and `sleep_enabled=True`. The values are still saved correctly (save path merges both sections), but validation is incomplete.

**Fix:** In the `if customize_buckets:` block, also merge `_sleep_raw` into `_flat_for_validate`:
```python
if customize_buckets:
    _flat_for_validate = {**user_input}
    for _k, _v in _buckets_raw.items():
        if _k not in _flat_for_validate:
            _flat_for_validate[_k] = _v
    for _k, _v in _sleep_raw.items():
        if _k not in _flat_for_validate:
            _flat_for_validate[_k] = _v
```

### LOW-1: Redundant `isinstance(_buckets_raw, dict)` check in save path

**File:** `config_flow.py:5658`
**Severity:** LOW

```python
if isinstance(_buckets_raw, dict) and not isinstance(_v, dict):
```

`_buckets_raw` is always a dict (either the nested section dict or `user_input` itself). The `isinstance(_buckets_raw, dict)` check is always True and therefore redundant. Same for `_sleep_raw` at line 5660.

**Impact:** No functional impact; minor code clarity issue.
