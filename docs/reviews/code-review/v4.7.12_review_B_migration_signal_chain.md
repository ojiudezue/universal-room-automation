## Findings

### M-B1 (MEDIUM) — DAO error-log key "anomaly_type" misleads on legacy events

**Location:** `database.py:4810-4813`. The exception path logs `anomaly_type=%s` but reads via `getattr(event, "anomaly_type", getattr(event, "event_class", "?"))`. Legacy/duck-typed events still using `event_class` will be miscategorized in the log. Not data integrity — pure observability mislabel.

**Fix:** rename log key to `discriminator=%s` (neutral about source attr), OR emit two keys.

### M-B2 (LOW) — `__post_init__` does not coerce `None`

**Location:** `anomaly_event.py:246-260`. `isinstance(None, str)` is False, so a caller passing `anomaly_type=None` is NOT caught. Caught silently by DAO fallback at `database.py:4768` as `"point_in_time"`. Plan §D2 said "never rely on the default." **Convergent with C-M1.**

**Fix:** add `if self.anomaly_type is None: raise ValueError(...)` to `__post_init__`.

### M-B3 (LOW) — No byte-equivalence test for activity_logger details

**Location:** `energy.py:3317-3365`. The `anomaly_type` → `anomaly_subtype` rename touches 6 references including `details["type"]`. No regression test asserts `activity_logger.log` receives the pre-cycle-equivalent payload. If any future cycle drops a reference, dedup window could collapse formerly-distinct subtypes.

**Fix:** add one test mocking `activity_logger.log` and asserting call args for `_emit_circuit_anomaly_event`. Defer to D4 follow-up.
