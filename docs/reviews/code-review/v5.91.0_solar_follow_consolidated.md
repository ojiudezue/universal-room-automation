## CODE FIXES

### HIGH
- **CF-1 pop-before-write (CONVERGENT ×3: A-MED-4, B-HIGH-2, D-MED-5).** `_restore_pass` `energy_pool.py:3873` pops `_original_amps` BEFORE the awaited `_write_amps` (swallowed except) → a failed restore write loses the saved value permanently. Same shape at boot-reconcile `:4199` (`_touched.discard` runs even when the write raised). **Fix: write first, pop/discard only on success.**
- **CF-2 reentrancy guard on `_tick` (B-HIGH-3).** `async_track_time_interval` does not await the prior invocation; a >60s tick overlaps → double-capture, double-`_persist`, halved confirm gate, unverified write. **Fix: `asyncio.Lock` or `_in_flight` bool with immediate log-once return.**
- **CF-3 strand-on-disable (B-HIGH-1).** `_restore_pass` runs once on the `_was_enabled` edge then never again; a bay held by a peer/DP at that moment is skipped (`continue`) and stranded at 6A forever. **Fix: keep attempting `_restore_pass` on each disabled tick while `_original_amps` non-empty (defer, don't drop).**
- **CF-4 `_boot_reconcile` cluster (D-HIGH-1/2/3, B-MED-1) — fix together.**
  - (a) It is the ONLY write path with no `_stronger_peer_holds`/`_paused_by_dp` guard → can write 48A into a load-shed-suppressed bay (INV-SF-7). Add the two-clause guard; skip (don't discard) when held.
  - (b) One-shot latch (`_did_boot_reconcile=True` unconditional at `:4004`); a bay whose limit entity is `unavailable` at boot takes `continue` and is never retried → stuck at 6A. **Latch only when every `_touched` member resolved** (or drop the latch, let the pass self-empty via discard).
  - (c) The disabled gate (`:3985`) returns BEFORE `_boot_reconcile` (`:4002`) → un-throttle backstop unreachable on the disabled path. **Run `_boot_reconcile` before the enabled gate.** NOTE: (c) makes (a)'s missing guard reachable on more paths — fix (a)+(c) together.
- **CF-5 STALE_POWER unbounded hold (D-HIGH-4) — money leak.** `energy_pool.py:4119` holds a stale bay at current amps with no ceiling; a wedged Emporia power sensor pins 48A/11.5kW peak-tariff grid import indefinitely (falsifies INV-SF-4). **Fix: bound the hold — after k consecutive stale ticks (or `SOLAR_FOLLOW_STALE_GRACE_S`) treat the bay as non-drawing and target MIN.**

### MED
- **CF-6 nameplate sanity clamp false-trips on battery discharge (A-MED-1).** `S_eligible` includes battery discharge but is compared to solar nameplate → at peak with the battery discharging it exceeds `nameplate·1.15`, WARNs, `_handle_blind`, kills modulation exactly at peak. **Fix: bound against `nameplate·1.15 + fleet_max_draw`, or compare `-grid_W` alone (exclude add_back).**
- **CF-7 add_back re-calls `_get_evse_state` (A-MED-2).** `:4074` re-reads state for step-3-admitted bays; if the power sensor flips `unavailable` between the two calls the v4.2.19 fallback returns fabricated 7600W and inflates `S`. **Fix: stash the step-3 state dict and reuse it.**
- **CF-8 EVSE freshness fails OPEN + naive-datetime bug (A-MED-3).** Per-EVSE `last_updated` missing → bay admitted to DRAWING (fail-open; opposite of the grid gate). And both sites do `x.replace(tzinfo=utc)` on a naive stamp → a naive LOCAL stamp reads as UTC (+18000s in CDT) → permanently stale/inert. **Fix: EVSE gate fails closed (→STALE_POWER) on missing stamp; reject naive datetimes rather than stamping UTC.**
- **CF-9 restore-timeout footgun (D-MED-6).** `_restore_solar_follow_state` is last under a 15s `wait_for`; on timeout `_db` stays None (persist no-ops all session) and `_did_boot_reconcile` keeps its `__init__` default of **True** (backstop off). **Fix: default `_did_boot_reconcile=False`; attach `_db` at construction / outside the timeout.**
- **CF-10 Confirm-value setup ordering (B-MED-2).** `_up_min_ticks` seeded only from the const; the Number's `_push` is one-shot with no retry, and nothing reads `energy_excess_solar_confirm` from the coordinator. **Fix: read the CONF key in `EnergyCoordinator.__init__` so the options value is authoritative regardless of entity timing.**
