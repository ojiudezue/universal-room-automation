**Cycle:** `feature/arbitrage-wait-floor` (df57ab1e) vs `develop`
**Framing:** STATE-MACHINE INTEGRITY + CHARGE-NOT-SUPPRESSED + BYTE-IDENTICAL + no C2-CRIT-1 regression + RESTART
**Reviewer:** B (of FOUR framing-disjoint). A=clamp-arithmetic, C=tests, D=completeness.
**Verdict:** ✅ **SHIP.** Zero CRITICAL/HIGH. The clamp is a pure RAISE-only floor that is read nowhere by the state machine; every phase/latch/boundary transition is driven by SOC / TOU-period / mins, never by `reserve_level`.

## 1. CHARGE NOT SUPPRESSED — the key risk ✅

**The clamp can only RAISE a reserve floor, never lower a charge target.** `_floor_reserve` (energy_battery.py:1456-1472) is a pure staticmethod returning `max(existing, effective_reserve)` only when `hold_depth=="partial_hold"` AND `effective_reserve is not None`; otherwise returns `existing` verbatim.

- **Arbitrage CHARGE** (energy_battery.py:1527-1549): `reserve_level=floored` where `floored=_floor_reserve(self._peak_buffer_target, ...)`. With partial floor (e.g. 50) < target (80): `max(80,50)=80` — unchanged. `charge_from_grid=True` (line 1544) is set **unconditionally**, independent of the floor. A floor ABOVE target (>80) would raise reserve but `charge_from_grid=True` still fires — charge proceeds. **Not suppressed.** ✅
- **Attain CHARGE** (energy_battery.py:2036-2050): identical pattern, `charge_from_grid=True` unconditional. ✅

**SOC→phase transition (CHARGE→HOLD) reads `peak_buffer_target`, NOT the clamped reserve — traced:**
- `_get_arbitrage_phase` line **1374**: `if soc is not None and soc >= self._peak_buffer_target: return ARBITRAGE_PHASE_HOLD`. Phase resolution is purely SOC-vs-target. The clamped `reserve_level` is a downstream actuation value emitted AFTER phase is resolved (line 1496-1497) and never feeds back into `_get_arbitrage_phase`. A raised floor **cannot advance, skip, or strand CHARGE.** ✅
- Attain CHARGE→HOLDING transition line **2454-2457**: `soc >= self._peak_buffer_target` → `_attain_state="holding"`. Same — SOC-driven, floor-independent. ✅

**Conclusion:** legitimate charge toward a higher target is structurally un-suppressable by this fix. The floor is an *actuation* clamp; the *control* state machine never reads it.

## 2. No C2-CRIT-1 (buffer-release-pre-boundary) regression ✅

Traced `_run_attain_branch` HOLDING route end-to-end (energy_battery.py:2393-2449):
- HOLDING exit conditions are ALL period/time-driven: mid_peak rate-gate (2398), boundary `mins<=0` (2408), handoff-lead `mins<=ATTAIN_PEAK_HANDOFF_LEAD_MIN` (2422-2427). **None reads `reserve_level`.** The clamp cannot trip an early release or drop the holding latch.
- The C2-CRIT-1 fix (P3-HIGH-1, comment 2413-2421) keeps `state="holding"` through the lead window and emits `_get_attainability_hold_decision` every tick. Both the handoff-lead emission (2433-2439) and the persistent-HOLD emission (2443-2449) thread `effective_reserve`+`hold_depth`.
- `_get_attainability_hold_decision` (2086-2099): `reserve_level=_floor_reserve(self._peak_buffer_target, ...)`, `charge_from_grid=False`. Under partial_hold the floor can only RAISE reserve ABOVE target → **retains MORE buffer**, strictly strengthening C2-CRIT-1's "pin at target until boundary" guarantee. Boundary handoff still `mins`-driven. ✅

## 3. Byte-identical for allow_discharge / no-alert ✅

For `hold_depth != "partial_hold"` (incl. allow_discharge & full_hold-handled-earlier):
- `_allow_discharge_decision` sets `reserve_floor=reserve_soc` (inclement.py:526). Thus `effective_reserve = max(self.reserve_soc, self.reserve_soc) = self.reserve_soc` (energy_battery.py:2841) — the exact v5.5.0 Reviewer-B-certified value.
- `_floor_reserve` guard `hold_depth=="partial_hold"` is FALSE → returns `existing` verbatim (line 1470-1472). Every one of the 6 clamped emissions returns its pre-fix `reserve_level` (peak_buffer_target / reserve_soc). The `suffix`/reason-append branches all gate on `floored != existing`, which is False → reason strings byte-identical too.
- `mode`, `charge_from_grid`, `arbitrage_active`, `arbitrage_phase` are all set by literals unaffected by the clamp. **Decisions byte-identical.** ✅

## 4. All 3 off_peak/mid_peak call paths ✅ (one ⚠️ note, not a bug)

Threaded at the 3 determine_mode sites: off_peak arbitrage (2982-2983), off_peak attain (3000-3001), mid_peak D1b attain (2895-2896) — each passes `effective_reserve=effective_reserve, hold_depth=decision.hold_depth`.

partial_hold reachability (inclement.py): emitted at off_peak (618-629, 696-707) AND **mid_peak/peak corroborated-recoverable** (659-680, `watch_corroborated_recoverable_partial_hold`). So partial_hold is NOT off_peak-only.

- **off_peak arbitrage:** floor reaches WAIT (1561), CHARGE (1542), HOLD (1517) — all 3 phases. ✅
- **off_peak attain:** floor reaches reboot-release (2334), HOLDING (2090), CHARGE (2036) via the threaded `_run_attain_branch`. ✅
- **mid_peak D1b attain:** `_run_attain_branch(tou_period="mid_peak", ...)` threads floor through HOLDING/CHARGE. ✅
- **⚠️ (informational, NOT a finding):** a mid_peak/peak partial_hold's *discharge* emissions (peak 2845-2860; mid_peak 2916/2941/2956) use `effective_reserve` **directly** (already `=max(reserve_soc, reserve_floor)` at line 2841). The floor IS applied there via the v5.5.0 mechanism — they correctly do NOT go through `_floor_reserve` (which only clamps attain/arbitrage target-pinned emissions). The summer-hold `hold_reserve=int(soc)` (2916) holds at SOC ≥ floor (holding), pre-existing v5.5.0-certified. **No partial_hold-reachable state misses the floor.** ✅

## 5. Restart resilience / reboot-recovery ✅

`_maybe_run_reboot_recovery` (2267-2348):
- The floored emission (2320-2340) fires ONLY when `adopted=="release"` — boot landed OUTSIDE any valid attain window (`_adopt_attain_state_from_hardware` line 2263-2265). Old code released to `reserve_soc`; new floors to `max(reserve_soc, effective_reserve)` under partial_hold → **raises** the release floor, cannot release below it. ✅
- **Reboot-mid-charge in a VALID window** returns `adopted=="charging"` (2253-2262) → line 2342 sets `_attain_state="charging"`, returns `None`; recovery does NOT emit. Caller routes to the normal CHARGE path (targets peak_buffer_target ≥ floor). A raised floor cannot release a mid-charge boot below the floor. ✅
- **Non-partial_hold reboot:** `hold_depth=="allow_discharge"` → `_floor_reserve` returns `reserve_soc` unchanged → release path byte-identical to pre-fix. ✅
- Reboot-recovery latch (`_attain_reboot_recovered`, 2285/2303) and defer-without-consume (2293-2302) are untouched by the diff. ✅

## 6. No shared mutable state / double-emit / per-tick cache ✅

- `_floor_reserve` is `@staticmethod` (1456) — no `self`, no mutation, pure.
- `_inclement_decision` is per-tick cached keyed on `now` (792-796); `determine_mode` calls it once (2815) and threads ONE `decision` object's `hold_depth`/derived `effective_reserve`.
- The 3 call sites are mutually exclusive `return`-guarded branches — exactly one executes per tick. No double-emit. ✅
- No new instance attributes; no interaction with `_arbitrage_chunk_completed`/`_attain_state` latches (the clamp touches only emitted `reserve_level`). ✅
