## Charge-by-charge findings

### 1. full_hold short-circuits identically to today's storm branch — ✅ (with INFO-1)

`energy_battery.py:2716–2737`. `full_hold` returns `BATTERY_MODE_SELF_CONSUMPTION + charge_from_grid=True` when `grid_precharge and soc<DEFAULT_STORM_CHARGE_THRESHOLD`, else `BATTERY_MODE_BACKUP`. Both return BEFORE `effective_reserve` is computed (line 2741) and before any TOU branch — TOU branches provably don't run. The short-circuit lives in the exact slot (`:2447–2464` region, post-grid-disconnect / pre-TOU) the old binary storm branch occupied. ✅

**INFO-1 (behavior delta vs old storm path, intentional per D5 ladder):** The old storm BACKUP-hold path passed **no** `reserve_level` (so `_result` emitted no reserve action → reserve untouched); the new full_hold passes `reserve_level=decision.reserve_floor = _full_hold_floor(soc) = int(soc)`. The old precharge path used `reserve_level=self.reserve_soc`; the new uses `int(soc)`. This is the **intended** ladder semantics (full_hold pins reserve at current SOC to hold charge — a strengthening, and harmless in the precharge case since charge_from_grid drives charging regardless of reserve floor). It is NOT byte-identical to the legacy storm path, but the charge-1 invariant ("returns BACKUP/SELF_CONSUMPTION+grid, TOU branches don't run") holds. `test_full_hold_equivalent_to_pre_v_storm_branch_for_warn_tier` correctly asserts on **mode** (BACKUP), not on exact reserve-action equality. No action needed; flagged for the record.

### 2. allow_discharge byte-identical to a no-storm tick — ✅ (key regression guard PASSES)

`_allow_discharge_decision` (`inclement.py:472–491`) sets `reserve_floor=reserve_soc` (= the `self.reserve_soc` fed into `InclementFusion`). In determine_mode, `effective_reserve = max(self.reserve_soc, decision.reserve_floor) = max(reserve_soc, reserve_soc) = reserve_soc` (`energy_battery.py:2741`). Every TOU site then reads `effective_reserve` which equals the pre-edit `self.reserve_soc`. Confirmed by `test_allow_discharge_byte_identical_to_no_storm_path` (asserts mode + reason + reserve value parity vs a clean strategy). ✅ **This is the load-bearing regression guard and it holds.**

### 3. The 4 TOU sites threading effective_reserve — ✅ (most-likely-regression: NO drift)

The two `max(int(soc)-5, …)` sites are mathematically correct: when `effective_reserve > soc-5` the floor wins (partial_hold correctly raises the minimal-discharge floor); when `effective_reserve == reserve_soc` (allow_discharge) the expression is identical to develop (the only added change is `soc or 0` null-guarding, behavior-equivalent for non-None soc). The summer mid_peak HOLD path (`:2814–2821`) intentionally retains `reserve_level=int(soc)` (holds for upcoming peak) and is NOT a discharge site, so it correctly does not thread effective_reserve. ✅

### 4. Precedence preserved + comment block accurate — ✅

`energy_battery.py:2673–2700` precedence block now documents: (1) envoy_unavailable, (2) grid_disconnected → BACKUP "wins over ANY inclement hold", (3) inclement ladder full/partial/allow, (4) peak/mid_peak "now reading effective_reserve", (5) off_peak. ### 5. Per-tick caching — no stale-decision window — ✅

`_inclement_decision` (`:768–835`) caches keyed on `now` (`_last_inclement_decision_at == now`). ### 6. THE ORCHESTRATOR'S EVSE FIX (ee749b5, energy.py:2483–2491) — ✅ max() is CORRECT semantics

`max(int(existing_val), int(hold_reserve))` with `try/except (TypeError, ValueError)` fallback to `hold_reserve`.

- **(a) Can never LOWER a full_hold/partial_hold floor** — ✅. `existing_val` is the reserve action's `value`, written by `_result` as `max(0,min(100,reserve_level))` = an int floor the battery strategy decided (inclement floor or normal reserve_soc). `max(floor, evse_soc) ≥ floor` always. The pre-fix code unconditionally overwrote with `hold_reserve`, which **could lower** an inclement floor when `evse_soc < floor` — the real bug the orchestrator caught. `test_evse_battery_hold_raises_but_never_lowers_reserve_floor` (existing=50, evse=40 → 50) and `test_evse_battery_hold_cannot_lower_partial_hold_reserve_floor` confirm.
- **(b) Still raises when captured EVSE SOC exceeds the floor** — ✅. `max(50,70)=70`. Original "pin reserve to EV-charge SOC to protect the EV's source" intent preserved. `test_evse_battery_hold_still_raises_reserve_when_capture_exceeds_floor` confirms (=70).
- **(c) try/except handles non-int safely** — ✅. `int(existing_val)` raises `TypeError` (None) or `ValueError` (str) → falls back to `hold_reserve`. Note: `existing_val` defaults to `hold_reserve` when `data.value` key is absent, so `max(hold_reserve, hold_reserve)=hold_reserve` — no crash. The fallback-to-`hold_reserve` on parse failure is the only branch that *could* lower a floor, but it only triggers if a reserve action carried a malformed (non-int) `value`, which `_result` cannot produce — INFO-2 below.
- **(d) Correct at BOTH sites (:2576 main, :2900 evaluate) + mode untouched** — ✅. The function only rewrites the reserve action's `value`; it never touches `decision["mode"]`. A full_hold BACKUP stays BACKUP. Both call sites invoke the same function with the same capture semantics. `test_evse_battery_hold_cannot_downgrade_full_hold_backup_mode` confirms BACKUP preserved.
- **Ratchet-down protection intact** — ✅. The anti-ratchet mechanism is the **one-time `_evse_hold_soc` capture** (`energy.py:2573–2575` / `:2897–2899`), untouched by this fix. `max()` only changes the floor-vs-EVSE-SOC arbitration, not the capture. The docstring's "built for ratchet-down" concern is orthogonal to the max() edit and remains satisfied.

**Conclusion: max() is the right operator.** The alternative (overwrite) was the actual defect. No edge case found where max() breaks an intended behavior.

### 7. Breaker safety (default precharge OFF) — ✅

### 10. Restart resilience + signal hygiene — ✅

- All inclement state inits to None/empty in `__init__` (`:310–315`). Post-restart, first attr read returns the safe default pack (`_inclement_attrs:877–890`); first tick re-derives cleanly.
- `SIGNAL_INCLEMENT_STATE_CHANGED` (signals.py:95) dispatched synchronously via `async_dispatcher_send` inside `_cache_inclement` (`:850–867`). **No untracked task** (Bug Class #19) — it's a synchronous call, not `async_create_task`. **No unsub leak** (Bug Class #38) — grep confirms ZERO `async_dispatcher_connect` subscribers exist (signal ships for future consumers per D6). **No Bug Class #34** — `async_dispatcher_send` is imported and used in the same try-block, never referenced before its function-scope import.
- **No double-fire on transition:** signal fires only when `(tier, hold_depth) != _last_inclement_signal_state` (`:842`). After restart `prev is None`, so a clean `allow_discharge` first tick does NOT emit a spurious change (`:845` guard: `hold_depth != "allow_discharge" or prev is not None`). The two determine_mode paths each fire at most once per genuine state transition; idempotent on the state tuple. ✅
