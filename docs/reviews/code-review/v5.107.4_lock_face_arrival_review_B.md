That matches the pre-existing geofence+ble double-P2 behaviour. `_release` skips a lock that is not locked or is in flight (:~1180/H3b), so the only extra effects are a `release_gen` bump and a trail record. INFO.
- **House state changed / lockout re-engaged in the window.** The re-check releases a lockout engaged after the face, as long as a same-person Bermuda entry move lands within 120 s of the face and the person is still really away by GPS. - **Bypass of `_really_away` / boot floor.** None. Both checks are applied in `_apply_arrival` and `_face_arrival_corroborated` on every path (:845, :~1042).
- **Kill switch / SC disabled between hold and re-check.** `_release` re-checks `kill_switch_on()` and `_sc_alive()` at release time (:1161-1164). PASS.

## Findings
**LOW-B1: an unguarded exception in the re-check propagates into PersonCoordinator's listener loop.** Class: cross-coordinator blast radius.
- `_on_pc_update` wraps only `record_bermuda_moves` in try (:~1024-1027). `_face_arrival_corroborated` and `_apply_arrival -> _release / _away_release` run unguarded inside `DataUpdateCoordinator.async_update_listeners`, which is a bare `for cb in ...: cb()` with no try (HA update_coordinator.py:197-200).
- Any raise there would skip every later PC listener (person sensors) for that tick.
- Before this change, `_release` was reached only via SC's dispatcher path, which isolates exceptions.
- No concrete raise was found; `_release` is defensive. Fix: wrap the per-face re-check body in `try/except Exception: _LOGGER.debug(..., exc_info=True)`. Cheap.

**LOW-B2: listener orphan if `async_setup` raises after :566.**
- `security.py:711-713` assigns `self._lock_regime` only after setup returns, so a failed setup is never torn down. The PC listener keeps the orphan alive, and it keeps stamping. The person and lockout subs already leak the same way.
- It can't release anything: `_pending_faces` is filled only via `on_person_arriving`, which SC never routes to the orphan.
- Fix is optional: move `_ensure_pc_listener()` to the end of setup, or tear down in the security.py except.

**LOW-B3: a stale PC listener lasts until the next ensure call.**
- If PersonCoordinator is replaced while the lock regime survives, the swap happens lazily, on the next person event, P2 or boot recheck.
- In the meantime new-PC moves aren't stamped and held faces aren't re-checked. That fails safe (fewer releases). It also doesn't keep the old PC refreshing, because shutdown cancels its refresh.
- Accept and document.

**INFO-B4 (pre-existing, not a regression, A/D lane): `_really_away` M-2(ii) (:982) returns True for a restored-home resident until their first real transition.**
- After a restart, past the 600 s floor, a home resident who walks into an entry area (Bermuda stamp) and is seen by a face camera within 120 s will release the lockout.
- Before this cycle the face alone did that, so v5.107.4 strictly narrows it.
- Worth a card if the operator wants the M-2(ii) exception tightened for P2.
