## Findings

### B-H1: HIGH. Multi-room zones misclassify premature releases as `released`, so the verdict leans SAFE

**Class:** #63, coincidental equality masking a concept split: one room's release is treated as the zone's release.

**Code:** `hvac_zones.py`, `_ev_shadow_verdict`, the `less` branch (`earlier = [t for t in releases if t < now]` → `released`). `_ev_shadow_note_releases` collects a release for ANY room in `legacy_rooms`.

The rule asks whether the legacy side released the ZONE between passes. The code answers a different question: did any one legacy room release? In a zone with two legacy-occupied rooms, one room's tail can expire while the other room keeps `L` True for the whole episode. The episode then closes `released`, even though the legacy zone never released and the evidence rule did release the zone early. That release is exactly the premature event the §7 query is meant to count.

**Repro.** It was run against the branch with the test harness `_World` and then removed; the tree is clean.
- Setup: guest state, zone z1 with `b` (bedroom) and `k` (common_area). Both rooms are occupied with evidence at T0.
- T0+250: `b` is still lighting-occupied but its evidence is inactive, and the bedroom evidence hold of 240 s has expired. `k` is off, with its tail to T0+310. Result: `L=True`, `E=False`, and an episode opens `less`.
- T0+400: `b`'s evidence returns. `L` is still True through `b`.
- Observed row: `outcome='released'`, `ended_at`=T0+310, `duration_s=60`.
- Truth: zone `L` was True on every pass, so the outcome should be `resumed`, with about 150 s of premature release.

**Why it matters although the change is display only.** The rows are the dataset that phase 2 will be decided on, and they are kept for 180 days. `details_json` does not store per-room release instants, so rows booked this way cannot be reclassified later. Guest suites (bedroom plus bath) are multi-room, so this is the common case, not an edge case.

The plan's §3.2 rule 1 says "any room in R", so this defect came from the plan. The code follows the plan faithfully.

**Fix (about 10 LoC).**
- Book `released` only when EVERY room that held `L` at the previous pass has a recorded release before `now`.
- `ended_at` = the LATEST of those release instants, which is when the zone released.
- Add a two-room test using the repro above.

### B-M1: MEDIUM. `released` uses `ended_at = min(releases)` where the zone released at the max

**Class:** same root cause as B-H1.

**Code:** `_ev_shadow_verdict` uses `return "released", (min(releases) ...)` in both the `not L` branch and the `earlier` branch.

**What goes wrong.** The zone's legacy side releases when its LAST room releases. Using the minimum understates `duration_s`. An episode can then fall under the 60 s floor and be dropped, or its duration is under-reported. Fix this together with B-H1.

### B-L1: LOW. Zone rediscovery keeps the episode open

**Class:** lifecycle.

**Code:**
- `discover_zones` clears `_zones` (`hvac_zones.py:487`) and rebuilds it.
- E5 closes only zone ids that are absent on a full pass (`_ev_shadow_run_tracker`).
- The plan's E5 says "removal / rediscovery".

**What goes wrong.** Take a zone that is rediscovered with the same id but different rooms. Its open episode continues with stale `legacy_rooms` and `tails`. Under B-H1's rule this feeds the wrong classification. The effect is diagnostic only.

**Suggested fix.** Close the episode `interrupted` when the zone's room set changes. Otherwise, record this as an accepted residual.

### B-L2: LOW. Per-room shadow dicts are never pruned

**Code:** `_hvac_ev_shadow_out` and `_hvac_legacy_shadow_out`.

They are never pruned for deleted rooms. Their size is bounded by the number of rooms ever seen. Because of the `_ev_shadow_pass_rooms` gate, a stale entry is never read. Accept.

### B-L3: LOW. Exposure across midnight goes to the new day

**Code:** `hvac.py:2298` runs `reset_daily_counters` before the pass at `:2335`.

**What goes wrong.** The interval between the last pass before midnight and the first pass after it, up to 2 ticks, is charged to the new day. The slop is at most 10 min per zone per day, which is noise for a rate. Accept.
