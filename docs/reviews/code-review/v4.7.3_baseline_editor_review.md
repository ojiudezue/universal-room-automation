## Findings

### MEDIUM-1: Unused import in hvac_preset.py

**File:** `custom_components/universal_room_automation/domain_coordinators/hvac_preset.py` line 19
**Bug Class:** None (code hygiene)

`BASELINE_MIN_DEADBAND` is imported but never used in hvac_preset.py. It is only used in config_flow.py (deadband validation). Not a functional issue but may trigger linter warnings.

**Action:** Fix in a follow-up cleanup cycle. Not a deploy blocker.

### MEDIUM-2: D1 deadband validation early-exit on first failure

**File:** `custom_components/universal_room_automation/config_flow.py` line ~4168
**Bug Class:** None (UX)

The deadband validation loop `break`s on the first invalid row. If a user has multiple rows violating the deadband, only one error is shown. The user must fix-and-resubmit iteratively.

This is acceptable UX for a 24-field form (showing a single error with a clear message is less overwhelming than 12 simultaneous errors), but worth noting for future iteration.

**Action:** Acceptable as-is. Could be improved to per-field errors in a future UX pass.

### LOW-1: Process violation -- builder bypassed worktree isolation

The builder committed directly to the `develop` branch instead of using a feature worktree. This means the `develop` branch was in a "dirty" state during build iteration. No functional impact since this is a single-user project, but deviates from the worktree isolation directive.

**Action:** Note for future builders. Not a deploy blocker.

### LOW-2: D2 return type change (int -> float)

`get_seasonal_setpoints()` previously returned `tuple[int, int]` from `SEASONAL_DEFAULTS`. With D2, it returns `tuple[float, float]` due to `float()` cast. All 3 callers verified safe (all use float arithmetic). No type annotation change in the function signature (return type is `tuple[float, float] | None` which is already correct).

**Action:** No action needed. Verified safe.
