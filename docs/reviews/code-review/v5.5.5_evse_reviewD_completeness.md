  battery fill, still within off_peak** — not blocked all night.

## Hunt Results

1. **Every `_paused_by_*` owner re-enumerated** (`energy_pool.py:196-272`). None re-holds the EV
   indefinitely in off_peak. arbitrage + load_shed are LEGITIMATE non-TOU holds with explicit
   overnight release paths (above). No second fill-priority-class deadlock exists.

2. **Ensure-on handoff:** off_peak ensure-on (`energy_pool.py:613-625`) fires `switch.turn_on`
   once all carry-over guards (`energy_pool.py:558-566`: drain/fill_priority/grid_cap/arbitrage/
   load_shed) are clear. After D1, fill_priority is no longer in that set in off_peak, so the only
   remaining off_peak vetoes are arbitrage-breaker (while battery grid-charges) and battery_drain
   (until reserve) — both transient + correct. No remaining veto blocks the turn-on indefinitely.

3. **No instantaneous-PV-as-night-proxy.** D1 phase is TIME-only: `peak_ahead_before_offpeak`
   (`energy_tou.py:247`) walks `get_current_period` by hour — zero PV/battery reads. off_peak
   release is unconditional, not solar-inferred. D2's solar gate is a **share-check only**
   (consumed solely in `soc_recovered`, `energy_pool.py:1043`), never a phase flip.
   `_expected_solar_surplus_pct` (`energy_battery.py:1695`) pro-rates `solcast_remaining` by
   daylight overlap → returns 0.0 at deep night (no overlap) and real-but-low on cloudy daytime —
   exactly defeating the cloudy-daytime trap. The `battery_power_w > 100W` fallback (`energy.py:2696`)
   is a true live "battery charging now" read, not a forecast proxy. **No phase-invariant violation.**

4. **mid_peak→off_peak boundary:** no oscillation. fill_priority goes inert at off_peak and CANNOT
   re-hold (inert = release-and-don't-rehold), so no flap between sets. EV transitions paused→charging
   once (subject only to the legitimate serialize-after-battery-fill under arbitrage). Distinct sets,
   distinct release conditions; no shared toggle.

5. **`peak_ahead is None` legacy path:** acceptable, NOT a regression. `peak_ahead` only influences
   the **mid_peak** branch (`energy_pool.py:1164`). In off_peak/peak, `fill_priority_inert` is True
   regardless of `peak_ahead`, so off_peak release is unconditional even when `_tou is None` or
   `peak_ahead_before_offpeak` raises (`energy.py:2720-2727`). The legacy None path only preserves
   the prior always-hold in **mid_peak** for no-TOU harnesses — it does NOT re-introduce an all-night
   off_peak hold. Reachable in production only if the TOU engine is unwired (off_peak ensure-on also
   depends on TOU period, so a no-TOU prod setup has no off_peak signal at all — consistent).

## Findings

- **No CRITICAL / HIGH.** The invariant ("EVs actually charge overnight in off_peak at reserve with
  no URA gate holding them") HOLDS.
- **INFO (not a defect):** overnight EV charging is *serialized* behind arbitrage battery grid-charge
  (breaker-safety). If the operator expects EV + battery to grid-charge concurrently overnight, that
  is intentionally blocked by the 20 kW + 7.4 kW panel-breaker invariant — documented, correct, and
  unchanged by this cycle. Worth a one-line note in the README's "Live" criteria so it isn't
  mistaken for the old fill-priority deadlock during validation.
- **LOW (observability):** there is no single sensor attribute that says "EV is held by arbitrage-breaker
  vs fill-priority" at a glance for the overnight window; `_classify_evse` precedence resolves it, but a
  validator watching for "did the EV charge by morning" should check `_arbitrage_pause_reason` /
  arbitrage phase, not just fill-priority membership, to avoid a false "still deadlocked" read.

No gate re-introduces the fill-priority all-night hold. The two non-TOU off_peak holds (arbitrage-breaker,
