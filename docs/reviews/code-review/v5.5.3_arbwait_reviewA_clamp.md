## 1. `_floor_reserve` logic — ✅ CORRECT

`energy_battery.py:1456-1472`:
```python
@staticmethod
def _floor_reserve(existing: int, effective_reserve: int | None, hold_depth: str) -> int:
    if hold_depth == "partial_hold" and effective_reserve is not None:
        return max(existing, effective_reserve)
    return existing
```

- **Gating:** raises ONLY when `hold_depth == "partial_hold"` AND `effective_reserve is not None`; otherwise returns the bare `existing`. Matches the spec exactly. ✅
- **Can only RAISE:** `max(existing, effective_reserve)` — the return is `>= existing` by definition, so a higher CHARGE target is never suppressed and a reserve is never lowered. ✅
- **None handling:** the `is not None` short-circuit precedes the `max()`, so a `None` `effective_reserve` can never reach `max(int, None)` (which would `TypeError`). ✅
- **Type coercion:** no coercion performed. `existing` and `effective_reserve` are both `int` on every reachable path (verified §3). `max(int, int) -> int`, matching the `-> int` annotation. No float/str leakage. ✅
- **`existing` is never None on a reachable path** (verified §6) — the two `peak_buffer_target` arbitrage phases are gated behind `soc >= self._peak_buffer_target` comparisons (`energy_battery.py:1374`) that would themselves raise on a None target *before* the helper is reached; the attain entry predicate returns early when `_peak_buffer_target is None` (`energy_battery.py:1944`). `reserve_soc` is always int (`energy_battery.py:153,189`). So `max(None, …)` is structurally unreachable. ✅

**No findings.** The helper is minimal, correct, and pure (staticmethod, no side effects).

The clamp helper therefore never receives a None `existing` on any path this fix touches. No new crash surface. ✅
