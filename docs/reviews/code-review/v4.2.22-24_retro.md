## Findings

### HIGH (parked)

**H1.** Reviewer self-corrected — not a bug. Sleep-mode early-return correctly avoids setting dedup. Skipped.

**H2. `_cover_op_in_flight` flag set before scheduling.** `automation.py` four cover entry points set `_cover_op_in_flight = True` *before* calling `_schedule_cover_runner()`. If a cancellation arrives in the window between flag set and the scheduler's try/except, flag stays True forever. **Parked:** there is no `await` between flag set and the scheduler call (single synchronous statement), so the window is effectively zero in cooperative async. Added to monitoring; will revisit if it actually surfaces.

**H3. Dedup-on-entry has no manual retry path.** Single RF failure at sunset means blinds stay open all night with no service to retry. **Parked as feature, not bug.** Diagnostic surfaces via `last_cover_failure_entities`. Future enhancement: per-room `Retry covers` button or `ura.retry_covers` service that clears `_last_timed_*_date`.

**H4. `_cover_at_target` thresholds (5%/95%) hard-coded for 0-100 scale.** Tilt-only covers (`current_tilt_position`) and non-default-open-position user preferences would misclassify. **Parked as academic** — URA today only does binary open/close commands, not partial position. Revisit if tilt support is added.

### MEDIUM (3 fixed)

**M1 (FIXED).** Duplicate cover IDs in config double-send. `_send_covers_with_verify` now dedupes via `list(dict.fromkeys(cover_ids))` at entry. Test added: `test_duplicate_cover_ids_are_deduped`.

**M2.** TZ-aware `dt_util.now()` is correct throughout. No issue. Skipped.

**M3 (FIXED).** Dropped `timeout=5.0` from cover service calls — meaningless when `blocking=False` (HA's `async_call` returns immediately).

**M4 (PARKED).** `blocking=False` + 8s settle could trigger straggler retries on slow non-group covers still physically traveling from the first command. Mitigation deferred: expose `settle_seconds` per-room as config. Currently a constant.

**M5 (FIXED).** AST guard `test_no_sync_update_listeners` strengthened to also resolve attribute-access handlers (`add_update_listener(self.foo)`), via `_handler_name()` helper that walks both `ast.Name` and `ast.Attribute`. Unresolvable handlers (lambdas, partials, cross-module references) now reported in the assertion message for human audit instead of silently skipped.

**M6 (INVALIDATED).** Reviewer suggested auditing `async_track_state_change_event` and `async_dispatcher_connect` for inverse mismatch (sync required, async would silently never run). **HA actually awaits coroutine callbacks for both**, so sync OR async is fine. No action needed.

### LOW (parked)

**L1.** `_cover_op_in_flight` is plain bool (no lock). All access is from event loop; no race possible in cooperative async. Documented.

**L2.** Activity log scheduling via `hass.async_create_task` (fire-and-forget) is pre-existing pattern. Not changing.

**L3.** `cover_attempts_today` semantics: counts each retry's pending list, so a 10-blind room with 1 straggler counts 12. Correct ("commands sent") but the name could be clearer. Not renaming for v4.2.26.

**L4.** No end-to-end test for the v4.2.23 storm scenario (3 coordinator cycles + persistent failure → exactly 1 runner). Test debt — would have caught the v4.2.22 storm pre-prod. Filed for future test cycle.

**L5.** No runtime test for v4.2.24 beyond AST guard. Could add `import_module + inspect.iscoroutinefunction(_on_entry_update)` assertion. Test debt.

## Lessons for next time

1. **Tier 2 features deserve their second review** — v4.2.22 introduced 200 LOC of new logic + diagnostics. The retro review surfaced 4 fixable items. CLAUDE.md "When in doubt, use 2 reviews" is the right default.
2. **AST guards are worth the 30 min** — `test_no_sync_update_listeners` now permanently prevents Bug Class #28 recurrence.
3. **Cover bug fixes need a regression test for the reentry pattern** — not just unit tests of the helper.
