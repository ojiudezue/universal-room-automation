## Review 2 (Core B — Race conditions, restart, lifecycle)

### Restart behavior

- **Number entity values lost on restart:** RestoreEntity covers it; `async_added_to_hass` reads `last_state` and pushes to controller. If controller isn't ready yet (cross-coord init race), `_on_hvac_tick` deferred-push via `SIGNAL_HVAC_ENTITIES_UPDATE` lands the value once HVAC fires its first cycle.
- **Master switch state across restart:** stored in RestoreEntity. On restart: switch's `async_added_to_hass` reads `last_state` and writes to `cc._solar_gain_enabled` if cc is available. If cc isn't available, the constructor seed (from form) wins — correct fallback.
- **Form value vs Number entity divergence:** form value is read by `__init__.py` at integration setup; Number entity then overrides on `async_added_to_hass` via RestoreEntity. URA mirror pattern compliance: form is install-time seed, Number is runtime truth. Already-shipped pattern from v4.5.0 D2 + v4.5.9.2.

### Race conditions

- **User adjusts slider during HVAC's 5-min decision tick:** slider's `async_set_native_value` writes to `_HVACTunableNumber._value` then pushes via setattr. Decision cycle reads instance attr at decision time. Worst case: slider adjusted mid-cycle → next cycle uses new value (within 5 min). No corruption.
- **Master switch toggled OFF during a solar window with closed covers:** `update()` early-returns. The `_hvac_closed` set retains the entity IDs HVAC closed. When user re-toggles ON later (or window expires), the open-after-solar branch fires for those covers. Acceptable behavior — user's choice to disable mid-window means HVAC stops acting; user can manually reopen if desired, OR trust HVAC to reopen at window end.
- **Form save + Number entity divergence after reload:** if user changes form value (e.g. Close Temp 85 → 82), entry reload re-runs `__init__.py` which re-seeds CoverController with 82. Number entity's RestoreEntity then overrides on `async_added_to_hass` with whatever the slider was last set to. So user's slider value persists across form changes. This is the URA mirror pattern's documented intent.

### Cross-coordinator interaction

- **HVAC reload mid-Number-entity-init:** the `_on_hvac_tick` listener handles this — once HVAC fires `SIGNAL_HVAC_ENTITIES_UPDATE`, the deferred push lands. Listener auto-unsubscribes after first successful push (`unsub_holder[0]()`).
- **`_get_sub_controller()` returns None mid-cycle:** factory's `available` property returns False → entity shows unavailable in UI. No crash. Recovers when sub-controller registers.

### Lifecycle

- **CoverController instantiated without v4.5.10 kwargs (test fixtures):** all 7 new kwargs default to module constants → identical pre-v4.5.10 behavior.
- **HVACPredictor instantiated without v4.5.10 kwargs:** same — defaults to module constants.
- **Module constants kept in place:** `COVER_CLOSE_TEMP`, `COVER_OPEN_TEMP`, `COVER_MANUAL_OVERRIDE_HOURS`, `COVER_SOLAR_HOUR_START`, `COVER_SOLAR_HOUR_END`, `OCCUPIED_CLOSE_TEMP_DELTA`, `SOLAR_BANK_FLOOR`, `SOLAR_BANK_SOC_MIN`, `PRECOOL_FORECAST_HIGH`, `PREHEAT_FORECAST_LOW`. Each serves as the constructor-default for backward compat with code that doesn't pass kwargs.
