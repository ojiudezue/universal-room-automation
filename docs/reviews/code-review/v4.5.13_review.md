## What changed

### Fix 1: HVACACRampKwhRateSensor reads source AC load sensor directly
- **File:** `custom_components/universal_room_automation/sensor.py` (class `HVACACRampKwhRateSensor`, ~line 7449)
- **Before:** `native_value` returned `zone.last_kwh_rate`, populated only when the AC ramp master switch was ON
- **After:** `_read_source_kw` reads `hass.states.get(zone.ac_load_sensor)`, parses float, converts W→kW based on `unit_of_measurement`. Sanity-bounded to [0, 50] kW. Rejects missing/unknown units. Centralized read used by both `native_value` and `extra_state_attributes`.

### Fix 2: AnomalyDetector.get_learning_status relaxes gate
- **File:** `custom_components/universal_room_automation/domain_coordinators/coordinator_diagnostics.py` (~line 734)
- **Before:** `if active_metrics == len(self.metric_names): return ACTIVE` — left coordinators stuck in LEARNING for weeks because some metrics never received observations
- **After:** `threshold = max(1, len(self.metric_names) // 2)`. ACTIVE when at least floor-half of metrics complete. Per-metric anomaly raising in `record_observation` is unchanged — dead metrics still surface as `active=False` in details.

## Recommendations for QUALITY_CONTEXT.md

Two candidate bug classes from this cycle, not yet promoted:

1. **Diagnostic sensor reading gated by feature switch.** The v4.5.12 kwh_rate bug was that a diagnostic-category sensor read from internal state that a feature-switch path was responsible for populating. With the switch off, the sensor was stuck `unknown` even though the source had data. **Pattern to avoid:** any sensor with `EntityCategory.DIAGNOSTIC` should read from the canonical source, not from intermediate computed state, unless the diagnostic IS that intermediate state.

2. **All-metrics gate masks per-metric reality.** Aggregate "learning_status: ACTIVE" required all metrics complete, but the per-metric anomaly logic was independent. The aggregate label became a lagging indicator that confused users into thinking the detector wasn't working when it was. **Pattern to avoid:** aggregate flags should match the pessimism level of the downstream gating — if downstream is per-metric, the aggregate shouldn't be all-or-nothing.

Both deferred to a future QUALITY_CONTEXT update pending one more occurrence to confirm they're recurring shapes.
