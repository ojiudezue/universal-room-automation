### Recommended new bug class

**Bug Class candidate: "Cross-Entry Init Race"**

When a feature spans two config entries (e.g., entity registered under one, coordinator under another), the order of `async_setup_entry` calls is non-deterministic. Direct push from the entity to the coordinator at `async_added_to_hass` time can silently fail.

Detection rule: when an entity in entry A interacts with a coordinator in entry B at startup, never assume B is registered. Either pull from B during B's setup, or use a dispatcher signal that fires when B becomes ready.

Worth adding to `docs/QUALITY_CONTEXT.md`.
