## Findings

### CRITICAL — fixed (minimum-viable)

**C.C1 — Tests use inline replicas, not production classes**
All 27 behavioral tests instantiate `_make_*_sensor()` helper classes that re-implement the sensor logic inline rather than importing and exercising the real classes from `aggregation.py`. If production code is later modified, these tests will not catch the regression.

**Fix this cycle (minimum-viable):** Added `TestProductionClassImports` class with 6 smoke tests that AST-introspect `aggregation.py` to verify:
- Each of the three classes exists by name with the expected base classes (`AggregationEntity` + `SensorEntity`).
- Each class implements both `native_value` and `extra_state_attributes` methods.
- The C2 shared-helper extraction (`_compute_zones_with_motion`) is present.
- The M3 fix (no `self.native_value` self-call in attrs) is present.

**Deferred:** Full refactor to mock-patch `_get_room_coordinators` / `_get_hvac_coordinator` / `_get_energy_coordinator` and drive the real classes through behavioral tests. Same test-infra-debt class as v4.6.11 C.H2. Tracked in dashboard backlog. Scope is non-trivial; deferring keeps this cycle from sprawling.

### HIGH — fixed

**B.H1 — manifest.json version not bumped**
*Auto-resolved by deploy.sh.* The build commit shipped at `v4.6.10.1`; `./scripts/deploy.sh 4.6.12` stamps the version across all source files including `manifest.json`. Same auto-bump mechanism that worked for v4.6.11. No manual fix needed pre-deploy.

**C.C2 — Motion sensor duplicated full iteration in `native_value` + `extra_state_attributes`**
Both properties independently iterated all room coordinators, applied naive-datetime guard, and built the zone set. TOCTOU risk between the two property reads (extremely unlikely at 30s polling but pattern is a maintenance hazard).

**Fix:** Extracted `_compute_zones_with_motion()` private method called from both properties. Single snapshot, no divergence possible.

### MEDIUM — fixed

**C.M3 — `HouseSystemDemandSensor.extra_state_attributes` invoked the value property**
Caused a second coordinator lookup + second zones iteration per state write. Same iteration counted twice and `or 0` masked any computational difference.

**Fix:** Compute pct locally from the already-fetched `zones` snapshot using `len(active_names) / total`. No more self-property-call.

### MEDIUM — deferred

**A.M1 — `utcnow()` vs `now()` consistency**
Builder used `dt_util.utcnow()` (tz-aware UTC); other aggregation.py sensors use `dt_util.now()` (tz-aware local). Functionally identical due to Python tz-aware subtraction normalizing to UTC. Style-only inconsistency. Defer — touching it would expand the diff for zero behavior change.

**A.M2 — `HouseSystemDemandSensor.extra_state_attributes` second-fetch pattern**
Resolved by C.M3 fix above (computes locally now). Marking as fixed-via-C.M3.

**A.M3 — `EnergyGridDemandSensor` reads cap from coord-init snapshot**
Reviewer A confirmed `async_reload` reconstructs the coordinator on options-flow changes, so cap is always live. False-positive on bug class #14. No fix needed.

**B.M1 / B.M2 — Motion sensor duplicate iteration + HouseSystemDemand double-fetch**
Both resolved by C.C2 and C.M3 fixes.

**C.M4 — Task brief attribute name divergence from plan**
Builder followed the plan, not the brief. Plan is authoritative. No code change needed. Noted to keep future brief-writers honest.

### LOW — deferred

**A.L1 — `_get_hvac_coordinator` vs `_get_energy_coordinator` placement**
Helpers 2,280 lines apart in `aggregation.py`. Minor duplication. Future refactor candidate. No cycle-critical impact.

**B.L1 — `AGGREGATION_UPDATE_INTERVAL` constant unused**
Predates v4.6.12. Dead code cleanup candidate. Not in cycle scope.

**C.L5 — No test for `EnergyGridDemandSensor` battery `AttributeError` path**
Production code has a defensive try/except. Test misses the AttributeError branch but covers `net_power_w=None`. Low priority — the try/except is purely defensive.

**C.L6 — `ZoneMotionEventCountSensor` never unavailable**
By design — "0 zones with motion" is a valid measurement. Documented behavior.
