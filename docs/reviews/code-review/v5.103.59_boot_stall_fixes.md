## 1. fix/entity-area-inherit-lookup (1fb37b2b9), verdict SHIP

- Flag semantics hold. `_ura_area_inherit_done` is set only after `device is not None` (entity.py, after the None return), so a device missing on the first add leaves the flag unset and the next sibling retries.
- Operator area is never clobbered. The flag is set before the `device.area_id is not None` return, so a room whose area the operator set is also latched off and is never written.
- Reload and options changes: `__init__.py:5531` builds a new `UniversalRoomCoordinator` per entry setup, so the flag resets on reload. An options change reloads the entry.
- Behaviour change (accepted): within one coordinator lifetime, inheritance runs once. Before the fix, a later entity add, such as a platform added mid-life, would re-inherit if the operator had cleared the area. Negligible.
- Tests: 6/6 pass and are behavioural (stub registry plus a call counter). Drills: neutering the flag check made `test_device_lookup_runs_once_per_room_not_per_entity` fail. Neutering the flag set made the same test fail. The tree was restored and is clean.
- LOW (untested, Bug Class #62-adjacent): no test covers device None on the first entity followed by a retry on the second. A mutation that sets the flag before the None check would leave the suite green. A 10-line test is advisable.

- Equivalent to the old loop. The old match condition was `isinstance(key,str)` with the tuple in the input set. Input tuples already require a truthy `integ`, so the index's extra `integ` filter drops nothing that could match. Old and new both skip devices already in `expanded`. Insertion order is registry order through `_device_order`, the same as the old dict iteration over `devices.values()`. Each device is inserted only once, which matches the old `break`.
- Staleness: the index is a snapshot built at construction. Before the fix, rung 3 read `self._dr.devices` live. The same resolver already snapshotted connections and the platform hint in `_build_indices`, so this adds no new staleness class. The one long-lived holder, camera_census (`camera_census.py:525`), rebuilds on `_resolver_dirty`, which is flipped by EVENT_DEVICE_REGISTRY_UPDATED as well as the entity-registry event (`:476-495`). `binary_sensor.py:1588`, `__init__.py:631` and `transit_validator.py:154` build a fresh resolver per use. No resolver goes stale.
- Test authority: the orchestrator drill reddens `test_rung_identifiers_overlap_pulls_in_sibling_device`.
