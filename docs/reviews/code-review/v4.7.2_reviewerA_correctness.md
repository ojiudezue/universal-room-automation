## Findings

### CRITICAL-1: Surface 2 does NOT call `_validate_dynamic_preset_input` -- sync invariant broken

**Severity:** CRITICAL
**Bug Class:** N/A (new invariant violation)
**File:** `config_flow.py` lines 5510-5536

The plan section 5 item 2 explicitly requires: "Both `async_step_zone_dynamic_preset` and `async_step_hvac_dynamic_preset` call `_validate_dynamic_preset_input`." The builder extracted the shared helper (line 3874) and wired it into Surface 1 (line 3757), but Surface 2 (`async_step_zone_dynamic_preset`, lines 5510-5536) still has its own inline validation. The two paths are semantically equivalent today, but any future change to the helper will silently diverge from Surface 2, which is the exact drift the plan was designed to prevent.

**Action required:** Replace Surface 2's inline validation (lines 5506-5536) with a call to `self._validate_dynamic_preset_input(user_input, zone_name, SLEEP_FLOOR, ...)` with `zone_prefix=""` (bare keys). Both surfaces must invoke the identical helper.

---

### HIGH-1: D1 docstring references non-existent `CONF_DYNAMIC_PRESET_MASTER_ENABLED` -- misleading documentation

**Severity:** HIGH
**Bug Class:** #32 (Form Field With No Runtime Reader -- inverse: documented form field that does not exist)
**File:** `config_flow.py` lines 3681-3682

The docstring for `async_step_hvac_dynamic_preset` says: "Master enable toggle (writes `EnergyCoordinator._dynamic_preset_enabled` via CM `entry.options[CONF_DYNAMIC_PRESET_MASTER_ENABLED]`)." But `CONF_DYNAMIC_PRESET_MASTER_ENABLED` is not defined anywhere in the codebase, and the form does not include a master toggle field. The actual master toggle is the D2 `HVACDynamicPresetSwitch` entity. The docstring is fabricating an API surface that does not exist.

**Action required:** Remove or rewrite the docstring to accurately describe the form layout (5 house-wide boundary fields + per-zone repeats). Reference D2's `HVACDynamicPresetSwitch` as the master toggle surface instead.

**Action required:** Bump to `"v4.7.2"` when ready to commit. If deploy.sh handles it, this is informational only.

### MEDIUM-2: D1 form layout item 1 (master enable toggle) omitted from form without plan amendment

**Severity:** MEDIUM
**Bug Class:** N/A
**File:** `config_flow.py` -- `async_step_hvac_dynamic_preset`

The plan section 4 D1 "Form layout" item 1 says: "Master enable toggle -- mirrors `EnergyCoordinator._dynamic_preset_enabled`." The builder chose to omit this from the form (the toggle is the D2 switch entity instead), which is a defensible design choice (switch entity is more automatable than a buried form field). However, the plan was not amended to reflect this deviation.

**Action required:** Either add a note in the plan acknowledging this deviation, or accept as-is since the D2 switch provides the same functionality through a better UX surface. No code change needed -- this is a documentation gap.
