## Summary

Phase 2 adds `domain_coordinators/optimization_llm.py` (`OptimizationLLMTier` + `OptimizerContextCorpus`, ~570 LoC): provider-agnostic LLM reasoning over the raw substrate via `ai_task.generate_data`, with cheap-triage→premium routing, delta-trigger gate, daily premium cap, structured-output parse/validate, and findings tagged `created_by="tier2_llm"` that flow through the **same Phase-1 chokepoint** — no bypass. 4 new CM-options CONF keys (provider entity, triage entity, editable system prompt, daily cap), all in the reload-suppress sets (Phase-1 C-CRIT-1 lesson applied at build time).

Three disjoint framings:
- **Review A** — LLM I/O correctness + cost-cap enforcement + structured-output safety
- **Review B** — chokepoint non-bypass + autonomy-ladder integrity for LLM actions + safety-goal compliance
- **Review C** — config-flow surfaces + prompt persistence + reload-suppression + test fixture authority

**Central safety claim verified by all three:** there is exactly one `services.async_call` in the LLM tier (`ai_task.generate_data`); every LLM finding is routed through `_consider_apply` → `_apply_action`; at L1 (default) LLM actions are shadow-inert in production code (asserted on the recorded service-call list, not just an outcome string); the kill switch is re-checked after the veto window so a multi-second LLM call cannot ship a stale-level action. **No CRITICAL bypass found.**

The protocol converged on real LLM-trust issues — two flagged by **two** reviewers independently. **All fixed in fix-up `b65f19e`.** Suite: 5349 passed / 44 failed / 14 errors (parity; failures pre-date the cycle). Optimizer test file: 50 → 64.

**Recommendation: FIX-THEN-SHIP — fixes applied; ready for deploy + Review D.** Note the deploy ships at L1; the safety deny-list + entity-validation make L2 escalation defensible, but L2+ should still be dialed per-dimension with care.

- **B-B5 / B-B7** — reject bare service without domain; commit delta signature only after successful parse.

## QUALITY_CONTEXT.md recommendation

Candidate **new bug class — "LLM-supplied gate input"**: when an LLM controls a field the safety gate keys on (action_class, confidence, severity, target_entity), the gate must derive/validate that field from trusted state, never trust the model's value. Phase 2 surfaced four instances (B-B1 action_class, B-B4 confidence, A-HIGH-2 target_entity, A-HIGH-3 service_data). Worth formalizing once a second LLM-actuating surface exists.
