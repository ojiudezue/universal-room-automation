## Cleared (holds because)

- **Exit-hold skip leak.** `_guest_left_exit_now` is set around `await self._run_inference(...)` (:6375-6378). There is no `await` in `_run_inference` before the S9 block (:7885-7938); the first awaits are at :8163/:8174, after the transition is applied, so a concurrent inference sees `current_state != GUEST` and never enters S9. Early returns (`not _enabled`, no manager) clear the flag in `finally`. A rejection by the 300 s minimum dwell leaves the latch off, so the next ticks exit through the normal S9 path. No leak.
- **Press during an in-flight walk.** `left_at` is read at :6260, after every DB await and with no await between it and the latch write at :6292. A press during the DB reads is therefore honoured. The walk's DB-error path keeps the previous latch only when a walk has already succeeded, and that latch is the one the press cleared. `_refresh_guest_stay` and `async_guest_left` are the only writers of `_guest_stay_active` (grep: :6201, :6292, :6361).
- **Load race.** Whichever caller loads first sets `_guest_left_loaded`. A newer RAM press wins over a stored press at :6344. If the walk reads `None` before the Store returns, the press that follows clears the latch anyway.
- **No pre-press stay exists, so a button exit opens no grace.** Entry requires `post_press` (:6271), and `ended_on` is set only on the exit of an active stay.
- **Grace day arithmetic.** `nights` are local `date`s; `(date - date).days` does not depend on DST. Grace 0 is off, because a re-entry night is always ≥ 1 day after the night that ended the stay. An end that is unknown (the stay ended before the 35-night walk window) gives `ended_on = None`, so no grace (fail-safe).
- **Exit cap slice.** n ≥ 1 whenever the stay is active, and n ≤ idx + 1, so `best[idx-x+1:idx+1]` never goes negative (:6283-6286).
- **Flap.** Alternating guest/away nights (Q,E,Q) give n = 2 at re-entry, so the stay holds through one empty night; there is no daily toggle on that pattern. Only the phantom chain in #1 cycles.
- **Button.** Unique id `universal_room_automation_guest_left` is unique (grep). It is registered in the CM-entry branch (`button.py:74-78`). DeviceInfo matches the sibling Presence entities (`binary_sensor.py:2302`), and `_devices.PARENT_MAP` nests it under the CM. `available` follows the presence coordinator.
- **Store I/O.** `Store.async_load` / `async_save` use HA's executor. The lazy import of `homeassistant.helpers.storage` is already loaded, so nothing blocks the event loop.
- **Timezones.** Night windows are aware (`guest_night_window`, tz-aware), and a naive stored press is coerced to UTC (:6342), so the comparison at :6271 cannot raise.
