## Cleared (holds because)

- **Normaliser vs the real shapes** (`frigate_ingress.py:110-135`). It passes `before`, `after` and `type` through by presence only (`"k" in p`), so `sub_label` as `null` or `[name, score]` and `end_time` (null, set only on `end`) reach consumers unchanged. A JSON `null` `before` passes through, which mirrors Jinja `default()` firing on undefined only. Non-object, undecodable and bytes payloads are handled, with bad ones counted (`:417-420`). `test_normalise_matches_live_bus_fixture` asserts dict equality on the 16 live pairs.
- **Consumers read only `data.get("after")` and `data.get("type")`** (`perimeter_alert.py:956-960`, `exterior_track_linker.py:254-265`). The normalised dict and the bus `event.data` give identical values for those reads, so consumer output is byte-identical. The linker passes `sub_label` through `after.get("sub_label") or None`, which is unchanged from before.
- **First-source latch** (`:436-454`). It is keyed `str(after.id)`. A copy from the other family is dropped only while the owner was heard within the TTL. The owner's own `update` stream is never deduped (`held[0] != family`). A refresh calls `move_to_end`, so the front-pop expiry loop (`:446-451`) is correct for a dict ordered by last-seen. Ownership changes hands only after the owner has been silent for the TTL, and an early bus-first copy then owns the id, so each message is still delivered once. The TTL has a floor of 10 (`:138-144`) and is 30 against a measured 44 ms lag. A truth table over held=None / same family / other family within TTL / other family expired gives deliver / deliver / drop / deliver+take-over, and all four rows are implemented.
- **Id-less messages** (`:430-435`). These go through MQTT only while an events subscription is live, otherwise through the bus. With the kill switch off, `_wanted_suffixes` omits `events`, so the bus owns them. That matches the manual (§4.5).
- **Exactly once per consumer.** Each consumer is registered once by name (`register_consumer`) and fanned out once per surviving message. The consumers do not keep their own bus listener while the ingress exists. The `register_frigate_consumer` fallback (`:532-551`) uses the bus only and matches the pre-cycle behaviour.
- **Retained messages.** They are skipped on `events` before counting or normalising (`:413-415`) and in the face handler (`camera_census.py:5462-5464`), which counts them in `frigate_face_msg_retained_count` (`sensor.py:4058`). Topic handlers get the raw message with `retain` intact.
- **Prefix discovery** (`:64-104`). It reads only `hass.data["frigate"][entry_id]["config"]["mqtt"]["topic_prefix"]` for every Frigate entry, with no literal fallback. A missing runtime entry, config or mqtt key, or a non-string prefix, is skipped, and any exception returns an empty set. It strips whitespace and trailing `/`. A set of several prefixes subscribes `(prefix, suffix)` once each (`:337-363`). Reconcile is add-only and is retried from mqtt/frigate `async_when_setup`, HA started, and a 300 s timer.
- **Face bridge on the runtime prefix.** The dead `_resolve_frigate_topic_prefix` and its `"frigate"` literal are deleted. The face handler is registered on the ingress, which subscribes `<prefix>/tracked_object_update` for each discovered prefix, so the bridge no longer listens on retired `frigate/`. The handler is `@callback` (`camera_census.py:5451`) and is invoked from the `@callback` `_topic_cb`, so it runs on the event loop as before. Note: this makes the URA face latch live for the first time since Frigate-1 retired. That is the intended effect, and its downstream reads (synthetic latch leg, D10.5) are Review B/D's lane.
- **D2 "bus silent" WARN.** `_frigate_bus_times` is fed in the consumer after dedup (`perimeter_alert.py:978`), so it counts deduped messages from either source and fires only when both are silent, as documented.
