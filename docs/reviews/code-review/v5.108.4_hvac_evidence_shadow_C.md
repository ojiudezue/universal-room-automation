## Findings
**HIGH-1 (MEDIUM-HIGH, Bug Class #62 untested site): the `DBShuttingDown` handling the review brief named does not exist.** `database.py` `log_hvac_evidence_shadow` has one `except Exception` that logs a WARNING and returns 0. Every sibling DAO that rides the write queue has `except DBShuttingDown: return 0` first (for example `log_forecast_batch`, `database.py:5507`), because a drain landing during HA stop raises `DBShuttingDown(RuntimeError)` from the queue (`database.py:616`). Here every shutdown with queued rows produces a spurious WARNING, and any trip-wire counting WARNINGs from this module sees noise. Neither N10 nor N11 (changing or deleting that arm) moves any test. Fix: add the `except DBShuttingDown` arm and a test that a shutting-down queue returns 0 with no WARNING and a plain failure returns 0 with one.

**MEDIUM-1 (untested site, brief item "room-list cap"): the cap on room lists in `details_json` is unprotected.** M13-M16 and N09 all GREEN. No test creates more than `MAX_ROOMS_PER_LIST` (20) rooms in an episode, so the `[:lim]` slices, the knob and the sort determinism are never exercised. Failure scenario: a zone with 25 rooms writes an unbounded `details_json` and the cap is a decorative knob. Add one 21-room zone episode asserting each of the four lists has length 20 and is the sorted prefix.

**MEDIUM-2 (untested site): the "none" house state.** M01 GREEN: the `None` house-state key (`"none"`) is never asserted. The golden contains passes with `house_state=None` but it only pins producer outputs, not rows. A rename leaves `house_state` as the literal `"None"`/`"nil"`, which the verdict query then reports as a separate state next to `none`. Add an episode and exposure test in house state `None` asserting `house_state == "none"` (episode and exposure rows).

**MEDIUM-3 (untested site): `kind='more'` closing as `resumed` (legacy catches up).** M08 GREEN. `test_more_episode_kind_more` covers only `more` -> `released`. The `more` -> `flipped` and `more` -> `resumed` branches of `_ev_shadow_verdict` have no test.

**MEDIUM-4 (verdict query boundaries and outcome sets untested).** M53, M54 (grace is `>=`), M55 (premature = `resumed` only), M56 (saved = `released` only), M58 (SAFE is `<=` bar), M59/M60 (floors are `<`), M61 (`:since` on exposure) all GREEN. The test data has no `flipped`/`interrupted` episode rows, no `dur == grace` row, no `rate == bar` state, no `occ_zone_h == floor` state and no pre-`since` exposure. These are the numbers that decide SAFE/NOT SAFE, so a one-character slip in the settling query ships silently. Add fixture rows at each exact boundary (dur=300 with grace=300, rate exactly equal to the bar, 30.0 h exactly, a `flipped` and an `interrupted` row, an old exposure row) and assert the verdict.

**LOW-1: prune loop never tested past one batch.** M45 GREEN. `test_prune_window` deletes fewer rows than `batch_size`, so "keep deleting until a short batch" is unproven. Parametrise with `batch_size=2` and 5 old rows.

**LOW-2: DAO malformed-row skip untested.** M42 GREEN. One row with an empty `zone_id` among valid ones should be skipped and not counted.

**LOW-3: M06 (`<` vs `<=` at release == now) and M12 (observed `_hvac_shadow_release_at` candidate)** are GREEN. M12 is largely covered by the tail fallback and is a weak mutant; M06 is a one-instant boundary. Optional.

**LOW-4: knob defaults for MAX_ROWS (96) and MAX_ROOMS (20) are unasserted** (N06, N09 GREEN). `test_boot_window_excluded` already asserts the BOOT default (600) the same way; do the same for the other two.
