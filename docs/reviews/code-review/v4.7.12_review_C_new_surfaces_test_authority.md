## HIGH

### C-H1 — `test_save_anomaly_event_resolution_prefers_anomaly_type_over_event_class` does NOT test the production DAO contract it claims to test

**Location:** `quality/tests/test_v4712_anomaly_type_discriminator.py:339-369`
**Bug class:** #44 (test-infra schema/contract authority — test asserts something the production code path does not in fact guarantee against the same input)

**Description:** The test docstring claims it verifies the DAO's resolution order ("when both attrs present, anomaly_type wins"). The test constructs `_FakeAnomalyEvent(anomaly_type="regime_shift")`, then explicitly overrides `event.event_class = "point_in_time"` post-construction to make the two attrs disagree.

But the test uses `_insert_anomaly`, NOT `save_anomaly_event`. `_insert_anomaly` in `test_v463_behavioral_dao.py` (the helper this test imports) does:

```python
_discriminator = getattr(event, "anomaly_type", None) or getattr(event, "event_class", "point_in_time")
```

The `or` operator falls through on falsy values, not None. That's the *test helper's* resolution. The production DAO in `database.py:4765-4769` does:

```python
_discriminator = getattr(event, "anomaly_type", None)
if _discriminator is None:
    _discriminator = getattr(event, "event_class", None)
```

These are subtly different (the production version only falls back on `None`, never on falsy-but-not-None values). The test only proves the test helper's behavior, not the production DAO's behavior.

**Fix:** Either rename the test to be honest about what it verifies (`test_insert_anomaly_helper_resolution_order`) and add a separate test that constructs an `AnomalyEvent` and calls `save_anomaly_event` via the real async DAO. OR drop this test entirely; the resolution-order contract is enforced by C-M2 via documented invariant + a one-liner unit test against the production resolution code path extracted as a module-level helper.

### C-H2 — `_FakeAnomalyEvent` does NOT invoke `__post_init__` validation; tests that route through the helper can pass values the production dataclass would reject

**Location:** `quality/tests/test_v463_behavioral_dao.py:104-160`
**Bug class:** Test-infra authority (Bug Class #44 cousin — fake/duck-typed stand-in diverges from production contract on a v4.7.12 NEW SURFACE)

**Description:** The whole point of v4.7.12 D1 is the new `__post_init__` validator that raises `ValueError` on unknown anomaly_type strings (production `anomaly_event.py:246-260`). The `_FakeAnomalyEvent.__init__` just sets `self.anomaly_type = _resolved_type` without coercion or validation. Behavioral tests that go through `_FakeAnomalyEvent` and then through `_insert_anomaly` can freely pass garbage discriminators (e.g., `"banana"`) and the test will succeed.

**Impact:** v4.7.13+ regime-shift consumers will trust that any row in `anomaly_log` has a discriminator from the closed set of 4 enum values. The test suite no longer enforces that invariant *behaviorally* — only the AST scans do.

**Fix:** Add a `_resolved_type` validation step to `_FakeAnomalyEvent.__init__` that mirrors the production `__post_init__`:

```python
_VALID_ANOMALY_TYPES = {"point_in_time", "regime_shift", "hazard", "transition_invalid"}
if str(_resolved_type) not in _VALID_ANOMALY_TYPES:
    raise ValueError(
        f"_FakeAnomalyEvent.anomaly_type must be one of {_VALID_ANOMALY_TYPES}; "
        f"got {_resolved_type!r}"
    )
```

Then add a regression test asserting `_FakeAnomalyEvent(anomaly_type="banana")` raises.

## MEDIUM

### C-M1 — `__post_init__` does not handle `None`; raises `TypeError` from `isinstance` check instead of the intended `ValueError`

**Location:** `custom_components/universal_room_automation/domain_coordinators/anomaly_event.py:246-260`
**Bug class:** #22 (enum mismatch — incomplete coercion)

If `anomaly_type=None` is passed, `isinstance(None, str)` is False, the `if` branch is skipped, `self.anomaly_type` stays `None`. The production DAO at `database.py:4765-4770` will then resolve `_discriminator = None`, then fall through to `_discriminator_str = "point_in_time"`. **A None at the emit boundary silently lands as `point_in_time`** — defeating the design intent ("never rely on the default").

**Fix:** Tighten `__post_init__`:

```python
def __post_init__(self) -> None:
    if isinstance(self.anomaly_type, AnomalyType):
        return
    if isinstance(self.anomaly_type, str):
        try:
            self.anomaly_type = AnomalyType(self.anomaly_type)
            return
        except ValueError as e:
            raise ValueError(
                "AnomalyEvent.anomaly_type must be a member of AnomalyType "
                f"or one of {[t.value for t in AnomalyType]!r}; "
                f"got {self.anomaly_type!r}"
            ) from e
    raise TypeError(
        f"AnomalyEvent.anomaly_type must be AnomalyType or str; "
        f"got {type(self.anomaly_type).__name__}"
    )
```

Add a test: `test_anomaly_event_post_init_rejects_none`.
