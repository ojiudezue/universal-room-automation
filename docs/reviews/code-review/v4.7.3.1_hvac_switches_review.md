### MEDIUM-1: Inconsistent `last_state.state` guard across the 3 switches

**Bug Class:** None (style inconsistency, safe-direction default)

`HVACGuestModeActuationSwitch` guards with:
```python
if last_state is None or last_state.state not in ("on", "off"):
```

`HVACOverrideArresterSwitch` and `HVACACRampMasterSwitch` guard with:
```python
if last_state is None:
```

If `last_state.state` is `"unavailable"` or `"unknown"` (HA transient states), the two switches without the explicit guard will parse it as `target = False` (since `"unavailable" == "on"` is `False`). This results in the backing attribute being set to OFF/disabled, which is the safe-direction default for both switches. The old code had the same behavior (no explicit state filter), so this is NOT a regression.

**Severity:** MEDIUM (inconsistency, not a bug)
**Action:** Defer to next hotfix. Recommend aligning all 3 switches to the GuestMode pattern.

---

### LOW-1: Two other HVAC bespoke switches still have old vulnerable patterns

**Bug Class:** #5 (Startup Race)

`HVACACResetSwitch` (switch.py ~line 1372) has NO deferred-restore at all -- if HVAC coord is not ready at `async_added_to_hass`, the restore is silently dropped.

`HVACObservationModeSwitch` (switch.py ~line 1447) uses the old 5-second `async_call_later` timer retry pattern (same pattern that was vulnerable in the old `OccupancyWeightedPredictionSwitch`).

Both are exposed to the same Bug Class #5 root cause. They were not in scope for this hotfix (user reported only the 3 named switches), but should be tracked for a follow-up.

**Severity:** LOW (out of scope for this PR; separate hotfix candidate)
**Action:** File for v4.7.3.2 or next hotfix pass.
