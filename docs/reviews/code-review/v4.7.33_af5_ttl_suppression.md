# Code Review — v4.7.33 A-F5 TTL Suppression (Override Arrester)

**Cycle:** A-F5 suppression-pop fix (carried over from the 2026-06-08 marathon pickup).
**Tier:** 2-DB (elevated — shared suppression primitive consumed by 9 call sites across
`hvac.py`, `hvac_predict.py`, `hvac_override.py`; regression-prone HVAC actuation).
**Baseline tag:** `pre-review-v4.7.33`
**Reviews:** 3 framing-disjoint (A=correctness/edge-cases, B=cross-coordinator/contract,
C=test-authority/lifecycle), run after build, fix-up applied in-cycle, re-verified.

## The defect
v4.7.32 made `_revert_override` (`hvac_override.py:851`) fire TWO climate service calls
under a single `suppress()` — `set_hvac_mode heat_cool` then `set_preset_mode`. The old
suppression mechanism was a `set[str]` that the listener `_handle_climate_change` popped on
the FIRST resulting state event (`discard` + return). So the SECOND URA-generated event ran
unprotected through override detection and could re-arm the arrester. The same latent class
bites any thermostat that emits multiple settle events per single service call.

## The fix
Replaced `_suppressed_entities: set[str]` + single-discard with `_suppressed_until:
dict[str, datetime]` — a 5s TTL window (`SUPPRESS_TTL_SECONDS = 5`). `suppress()` opens the
window, `unsuppress()` pops it (error-path), the listener checks `now < until` WITHOUT
popping a still-valid entry (survives N settle events) and cleans expired entries. All 5
internal `add()` sites routed through `self.suppress()`. New behavioral test drives the real
`suppress`/`unsuppress`/`_handle_climate_change` via a fake clock + `_find_zone_by_entity`
spy (no re-implementation).

## External-contract verdict (Review B)
All 9 external `suppress`/`unsuppress` call sites (`hvac.py` ×7, `hvac_predict.py` ×2) are
SAFE: the dict is entity-keyed so a lingering window on zone A never masks zone B; every
error-path `unsuppress()` still closes the window under the new pop semantics; one site
(`hvac.py:1568`) uses `finally: unsuppress` which restores OLD-style clear-ASAP. The TTL
change is a strict net improvement — it closes a latent multi-settle-event leak that the old
single-pop model had at every single-write site, reducing spurious NM override alerts.

## QUALITY_CONTEXT.md recommendation
No new bug class required — A-F5 is an instance of the existing "shared-primitive contract
drift" pattern (a v4.7.32 feature addition silently violated an implicit one-suppress-
one-event contract). Consider a one-line note under the test-authority / lifecycle classes
that suppression is now a TTL window, not a set.
