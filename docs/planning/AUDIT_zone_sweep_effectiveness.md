## Method (producer / consumer)
- Producer of "fire": `zone.vacancy_sweep_done` False->True (hvac.py:3045 / 3120), published as attribute `vacancy_sweep_done` on `sensor.ura_hvac_coordinator_zone_N_status` (hvac_zones.py:1241). Re-armed False whenever any room is lighting-occupied (hvac_zones.py:1139-1142). Fire = False->True edge in recorder (`state_attributes.shared_attrs`). 173 fires (brief said 172; I count edges with a known prior False).
- Swept set rebuilt from `.storage/core.config_entries` room options: `lights` + `night_lights` - `lights_leave_on_when_empty`, plus `fans` where `room_fan_mode == follow_thermostat`, minus rooms whose `switch.<room>_automation` is off / `manual_mode` on (constant across the 7 d). Zone membership = `live_rooms` attr.
- Per fire: each swept entity's state at T-3 s and transitions in [T-300, T+300] with recorder context. The sweep writes lights/switches with the URA mark (`ura_context.py`: parent_id 01K6RAWR1TE0000000000000A1); the room tier uses the SAME mark, so the discriminator is the room's `ura_activity_log` `light_turn_off` row (room tier logs one; the sweep logs nothing, only an INFO line that is not retrievable here - journal is root-only, no journalctl on `ssh ha`). Sweep-attributed = URA-marked off within -3..+15 s of the flag flip with NO room `light_turn_off`/`reconcile` row. Fans: sweep writes carry no context, so a fan off in the same window is "sweep-coincident", not proven.
- Limits: the sweep INFO log ("swept N entities") unreachable, so the sweep-vs-other attribution is by exclusion. Paused/automation state taken from current switch state (7 d history shows no flips except `unavailable` blips).

Each room is room-automated (Automation switch on, 1 motion sensor; Jaya Bathroom, Laundry Closet, Kitchen Pantry), but the light was switched on by a person (non-URA context) and the room tier never turned it off: no `occupancy_entry` in the preceding 1-2 h in 4 of 5 cases, and in the Jaya overhead case the room vacated 398 s earlier and the light stayed on. - Fans (8): HVAC-owned (Fan Mode follow_thermostat), so there is no room-tier duplicate. 4 of the 8 (3 fires, all `zone_presence_state=pre_arrival`, all at the instant the house went arriving -> home_day, T-0.7..T-0.1 s) are FIGHT-shaped: the pre-arrival activation turned the same fans ON 36-61 s earlier (Living Room -41.4 s / -36.4 s, Study A -36.3 s / -55.6 s) and they went OFF +0.3..+1.3 s after the flag flip. ## Purpose recommendation
Evidence: the sweep does real work in ~6% of fires, essentially one class of catch (manual-ON lights/relays in vacant, room-automated rooms that the room tier did not own because it never saw occupancy, up to 4 h 47 m), plus fan turn-offs that the HVAC tier owns. It is NOT a backstop for unautomated rooms any more (paused rooms are skipped since v5.103.75) and is redundant for every light the room tier turned on itself. Recommend: keep as a narrow BACKSTOP for person-switched lights/relays in automated rooms (the only measured fill), do not widen it to paused rooms, and treat the pre-arrival fan on/off pair (3 fires / 4 fans) as a defect to adjudicate (needs the sweep INFO log or a one-shot trace to prove the writer). Config-first: ~5 relays that look like lighting (Dining Room x4, Media sw0, Upstairs Guest Bath overhead) could be added to a room's `lights` list by the operator with no code, after confirming the load. No code change is justified by this volume (5 light-offs in 7 d).

Falsification attempts: (1) searched for a room `light_turn_off` row at each sweep instant (none for the 5); (2) searched for re-ON within 300 s (none); (3) the one case that looked like a sweep miss (Kitchen Pantry 11-01) was a room-tier off after a device `unavailable` blip. Counter-evidence that would change the conclusion: the unretrievable sweep INFO log showing sweeps that swept entities I attributed to the room tier.
